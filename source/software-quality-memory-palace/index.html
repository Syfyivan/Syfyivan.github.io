Memory Method

轻记法：只压缩顺序，不发明答案

不用硬背字头

生硬字头本身没有意义，背它会多一层负担。现在直接背正式词：客户、成本、社会、可测、可预见。

按逻辑分组

比如质量属性按“谁评价、花多少、对社会、能不能量、能不能预判”来想；这仍然是原知识点，不是额外故事。

用遮答案训练

考试前重点做“看题目、口述、展开对照”。你要记住的是答案本身，不是提示本身。

Exam Blocks

高频考点原文块

大门 · 质量

质量属性完整块

轻记：质量先问“客户是否满意”，再看成本、社会影响、能不能测量、能不能预见。

  • 质量属性：客户属性、成本属性、社会属性、可测性、可预见性。
  • 客户关系：客户是质量接受者，质量服务于客户，由客户判定。
  • 质量管理三部曲：质量策划、质量控制、质量改进。
总控室 · 质量管理体系

质量管理体系完整块

轻记：方针和目标先定，职责和资源支撑，产品实现落地，测量分析改进闭环。

  • 定义：在质量方面指挥和控制组织的管理体系。
  • 组成：质量方针、质量目标、质量策划、管理职责、资源管理、产品实现、测量、分析和改进。
  • 答题抓手：方针目标先定，职责资源支撑，产品实现落地，测量分析改进闭环。
标准楼梯 · CMMI / IDEAL

CMMI 五级 + IDEAL 五步

轻记：CMMI 是成熟度从低到高；IDEAL 是改进项目从启动到复盘。

  • CMMI 五级：初始级、可重复级、已定义级、已管理级、优化级。
  • IDEAL 五步：初始化、诊断、建立、行动、学习。
  • CMMI 流程改进三步：确定总体框架、细化框架要求、确定度量方法与标准。
二楼 · 度量室

度量过程与原则

轻记：先定义清楚，再收集数据，再分析反馈，最后改进过程；原则围绕“清楚、可算、可靠、有反馈”。

  • 过程：识别目标和度量描述、定义度量过程、搜集数据、数据分析与反馈、过程改进。
  • 原则：理论与目标；一致、客观、无二义；经验直觉有说服力；简单可计算；适应产品过程并自动化；统计建立关系；结果可靠；建立反馈。
  • 对象：项目质量度量、产品质量度量、过程质量度量。
二楼 · 费用室

质量费用两大类四小类

轻记：主动花钱保证质量是控制费用；错误已经发生再花钱是失效费用。

  • 控制费用：预防费用、评价费用。
  • 失效费用：内部失效费用、外部失效费用。
  • 劣质成本常见分类：损失成本、返工成本、故障成本。
三楼 · 设计手术室

设计质量：低耦合，高内聚

轻记：耦合越高越不好，所以按“高到低”背；内聚越高越好，所以按“低到高”背。

  • 耦合从高到低：内容耦合、公共环境耦合、外部耦合、控制耦合、特征耦合、数据耦合、非直接耦合。
  • 内聚从低到高：偶然内聚、逻辑内聚、时间内聚、过程内聚、通信内聚、信息内聚、功能内聚。
  • 设计原则：降低耦合，提高内聚，模块接口清晰。
三楼 · 编码床

高质量编程细点

轻记：只输入就 const；无参数写 void；申请后检查，释放后置 NULL。

  • 如果参数是指针且仅作输入用，应在类型前加 const。
  • 函数没有参数时用 void 填充；参数命名要恰当，顺序要合理。
  • 动态内存申请与释放配对，free/delete 后立即置 NULL，避免野指针。
四楼 · 测试中心

测试原则完整块

轻记：测试从需求开始，越早越好；错误会集中；改完要回归；由小到大；尽量独立。

  • 测试追溯到用户需求。
  • 尽早地、不断地测试。
  • 注意缺陷群集现象，发现错误多的模块残留错误也多。
  • 回归测试确认修改没有引入新错误。
  • 增量测试，由小到大；测试通常应由独立测试人员承担。
四楼 · 流水线

测试层级侧重点

轻记：单元看模块，集成看接口，系统看整体，验收看需求。

  • 单元测试：独立单元/模块，开发人员完成，SQA 辅助。
  • 集成测试：模块间接口、参数传递、组合后的父功能、全局数据结构。
  • 系统测试：完整系统运行、功能和非功能、与软硬件环境结合。
  • 验收测试：功能和系统测试之后，发布之前，按规格说明书验收。
五楼 · 白盒实验室

白盒与逻辑覆盖

轻记：覆盖从“只跑语句”逐步加强到“覆盖路径”。不要先背缩写，先理解强弱变化。

  • 语句覆盖：每条语句至少执行一次。
  • 判定覆盖：每个判定真假分支至少执行一次。
  • 条件覆盖：每个条件真假至少出现一次。
  • 判定/条件覆盖：同时满足判定覆盖和条件覆盖。
  • 条件组合覆盖：每个判定中条件组合至少出现一次。
  • 路径覆盖：每条可能路径至少执行一次。
五楼 · 基本路径工位

基本路径测试大题步骤

轻记：大题不是背概念，是按步骤做：画图、算复杂度、列路径、配用例。

  • 控制流图：只画节点、边和编号，不写大段代码。
  • 环路复杂度：常用 V(G)=E-N+2，也可用判定节点数+1。
  • 独立路径条数通常等于环路复杂度。
  • 测试用例必须能覆盖列出的基本路径，不能只写路径不配数据。
五楼 · 黑盒实验室

黑盒：等价类与边界值

轻记：先按输入是否符合规格分类，再重点测边界。

  • 有效等价类：符合规格说明、有意义的输入集合。
  • 无效等价类：不符合规格说明的输入集合。
  • 设计原则：一个新用例尽可能覆盖多个未覆盖有效等价类；一个新用例只覆盖一个未覆盖无效等价类。
  • 边界值：一般边界值常用 4n+1；健壮性边界值常用 6n+1。
五楼 · 因果图/判定表

因果图与判定表

轻记：输入条件是原因，输出动作是结果；组合关系最终整理成判定表。

  • 适合检查输入条件的各种组合。
  • 步骤：找原因和结果，画因果关系，标约束，转判定表，为每列设计测试用例。
  • 因果图最终生成判定表。
测试基础 · 缺陷/用例/回归

容易出判断和简答的定义

轻记：缺陷分内外两种说法；测试用例三件套；回归测试检查修改有没有破坏原功能。

  • 软件缺陷：从内部看是开发或维护过程中存在的错误、毛病等问题；从外部看是功能失效或违背需求。
  • 测试用例：为特定目的设计的一组测试输入、执行条件和预期结果，是执行测试的最小实体。
  • 回归测试：修改代码后，用原有测试用例重新测试，确认修改没有引入新错误或影响原有功能。
集成/性能 · 桩驱动与压力类题

桩、驱动、性能三组概念

轻记：驱动模拟上级，桩模拟下级；性能看指标，负载看工作量，强度看长时间高压，容量看极限。

  • 驱动模块：模拟被测模块的上一级模块，接收数据、传给被测模块、启动被测模块并给出结果。
  • 桩模块：模拟被测模块调用的下级模块，通常只做少量数据处理，用于检查接口。
  • 性能测试：模拟正常、峰值和异常负载条件，测试系统性能指标。
  • 负载测试看一定工作负荷下的负荷和响应时间；强度测试看较长时间高负荷影响；容量测试看某项指标极限。

    质量的属性包括哪些？

    客户属性、成本属性、社会属性、可测性、可预见性。

    最后只背这些正式顺序

    1. 质量属性：客户属性、成本属性、社会属性、可测性、可预见性。
    2. SQA 组织：独立部门、独立工程师、独立小组；工作：计划、过程、评审、审计、记录、报告、跟踪、度量。
