<div class="csf-key-note">你每天都在用电脑、用手机、刷视频，但你大概从没问过一个怪问题：<b>一块沙子做成的芯片，凭什么会"算账"？</b>它又不认识数字，也不懂中文。这门课就干一件事——把"按下电源 → 程序跑起来"中间那座看不见的桥，一格一格修给你看。修完这座桥，你不再是"会用电脑的人"，而是"懂电脑里发生了什么的人"。</div>

欢迎来到《计算机组成原理》。

先说句实在话：这门课名字听着像天书，很多人大学学它学得痛苦，是因为一上来就被一堆术语和电路图砸晕，不知道这些东西到底要干嘛、彼此什么关系。我们换个走法——**先给你一张全景地图**，让你站在高处看清这座桥的每一格，再下去一格一格踩实。地图在手，后面就不慌了。

这是整门课的第 00 讲，是序章。它不堆代码，主要做三件事：**定调子、给地图、立规矩**。读完它你不会"学会"什么硬技能，但你会知道接下来要去哪、用什么姿势去。

## 🎯 这一讲你会学到什么

- 计算机其实是**一层一层"抽象"搭起来的**，理解"抽象层次"这四个字，是看懂这门课的总钥匙。
- 一台计算机大致长什么样——**冯·诺依曼结构**的一句话版本，先有个模糊但正确的印象。
- "**硬件**"和"**软件**"的分界线到底在哪，为什么这条线是模糊的、也是迷人的。
- 这门课接下来每一讲，分别在地图的哪一格，彼此怎么连起来。
- 我们的**玩法约定**：先猜后做、自己动手、AI 只当陪练不当代笔。

## 🛠 跟我做

序章没有写代码的环节，但有两个**必须动手**的小练习。别跳过——它们是你这门课的"起点存档",通关后我们会回来对照,你会清清楚楚看到自己长进了多少。

### 先理解一个词：抽象层次 <span class="csf-b csf-core">必读</span>

"抽象"这个词听起来玄，其实你天天在用。

想想你怎么开车：你踩油门、打方向盘，车就走了。你**不需要**懂发动机里汽油怎么爆炸、火花塞怎么点火、变速箱怎么换挡。"油门 / 方向盘 / 刹车"就是一层**抽象**——它把下面复杂的机械,包装成几个你能轻松操作的"把手"。

计算机也是这么搭的,而且层数多得多。从下往上,大致是这样一摞:

<div class="csf-legend">⚡ <b>最底层</b>：电信号——只有"通电 / 断电"两种状态<br>🔢 <b>往上一层</b>：用通断表示 <b>0 和 1</b>(二进制),进而表示数字、文字、图片<br>🔌 <b>再往上</b>：逻辑门——用 0/1 做出"与、或、非"这类判断,搭出加法器<br>🧠 <b>再往上</b>：CPU——会一条条"取指令、执行指令"的机器<br>📜 <b>再往上</b>：机器指令(CPU 能直接读懂的一串 0/1 命令)、汇编(把这些 0/1 命令写成人勉强能看懂的助记词,比如用 ADD 表示"加"),然后是 Python/C 这些你将来要写的代码<br>🖥️ <b>最上层</b>：你点开的 App、刷的网页</div>

**关键的洞察来了**：上面每一层,都只需要知道"下一层给我提供了什么把手",而**不用关心**那把手底下是怎么实现的。写 Python 的人不用懂电路,正如开车的人不用懂发动机。

<div class="csf-note">那我们为什么还要往下钻?因为<b>把手会漏</b>。程序莫名变慢、内存突然爆掉、数字算出来不对——这些时候,问题往往就藏在你"本来不用关心"的下层。懂组成原理的人,知道该掀开哪一层去看;不懂的人,只能干瞪眼或者瞎试。这门课,就是带你把这摞抽象从下往上走一遍,让每一层对你都不再是黑箱。</div>

把上面那摞层再揉成一句话,就是一台电脑长什么样了——这就是大名鼎鼎的**冯·诺依曼结构**(读作"冯诺依曼",一个人名,他提出了这个经典设计)。用大白话说:**一台电脑 = 存东西的"内存" + 算东西的"CPU" + 跟你打交道的"输入输出"(键盘、屏幕这些)**。最关键的一点是:**程序和数据都一起存在内存里,CPU 一条条把指令取出来执行**。你现在不用记任何细节,脑子里有这么个"内存 + CPU + 输入输出"的模糊轮廓就够了,后面的课会一格一格把它填实。

那"硬件"和"软件"又是怎么分的?也用一句话点一下:**看得见、摸得着的电路和零件——CPU、内存条、主板——是硬件;跑在它们上面的指令和程序——你写的代码、打开的 App——是软件。** 那这条线到底划在哪一层?其实它有点模糊:夹在中间的那层"机器指令"(就是上面图里 CPU 直接读懂的 0/1 命令)最尴尬——它既像软件(是一条条命令),又紧贴硬件(直接驱动电路动起来)。这条说不清的分界线,正是这门课后面会带你慢慢看清的地方。

### 动手练 1：画一张你的"猜想流程图" <span class="csf-b csf-key">重点</span>

现在,**在你学任何东西之前**,我要你先猜。

题目:**从你按下电源键,到一个程序(比如浏览器)出现在屏幕上,机器内部到底发生了什么?** 按你现在的直觉、想象,把这个过程画成一张流程图。

> 先猜后做：别查、别问 AI、别翻书。画错了完全没关系——这张图的价值,恰恰在于它现在有多"天真"。

怎么画都行,手机备忘录、一张草稿纸、或者用文字列步骤都可以。下面给你一个**纯文字版**的示范格式(内容是瞎编的,你要写你自己的猜测):

```text
我的猜想流程图（2026-07-08 存档，学之前）

[按下电源]
   ↓ 我猜：电流通进主板？
[屏幕亮了]
   ↓ 我猜：系统从硬盘里被读出来？读到哪？
[看到桌面]
   ↓ 我猜：我点浏览器图标，CPU 就……开始忙？
[浏览器打开]

我最不确定的地方：
- "程序"平时到底存在哪、运行时又跑到哪去了？
- CPU 一秒钟"算"那么多次，它到底在算什么？
```

写完,**存档保留**(拍照、另存为文件都行,标上今天的日期)。这是你的"出发点照片"。整门课结束时,我们会让你重画一遍,你会被自己的进步吓一跳。

### 动手练 2：钉一个"最想搞懂的问题" <span class="csf-b csf-key">重点</span>

再做一件小事:用**一句话**写下,关于"计算机到底怎么工作的",你**最最想搞懂的那个问题**。

可以是上面流程图里你打问号的地方,也可以是任何困扰你很久的疑问。比如:

```text
我的核心问题（贴在显眼处）：
"为什么芯片用 0 和 1 就能算出 3.14159 这种小数？它哪来的小数点？"
```

把这句话写大一点,贴在你看得见的地方——电脑边、书桌前、或者设成手机壁纸。**这是你这门课的北极星。** 每讲完一讲,瞄它一眼,问自己:现在我离答案近了吗?

<div class="csf-why">为什么非要逼你先猜、先提问?因为大脑对"自己挂念过的问题",记忆和理解会深得多。你带着问题去学,和被动地被灌输,效果天差地别。这就是这门课贯穿始终的"先猜后做"——<b>每一讲在揭晓答案前,我都会让你先猜一把。</b>猜错不丢人,猜错正是学习发生的地方。</div>

## 🔧 翻车现场

序章没有代码可翻车,但有两个**心态上的坑**,几乎每个新手都会踩。提前说,免得你掉进去。

**坑一:把"会用电脑"当成"懂计算机"。** <span class="csf-b csf-core">必读</span>

会装软件、会重装系统、会用快捷键——这些都很好,但它们是"开车技术",不是"懂发动机"。组成原理学的是发动机。两者不冲突,但别混为一谈。承认"我会用,但我不懂里面"是个特别好的起点——这门课就是来填这块的。

> 怎么破:每当你觉得"这我早会了",停一下问自己:"那它<b>为什么</b>这样?底下一层发生了什么?"答不上来,就说明还有的学。

**坑二:急着跳过基础,直接拿现成代码拼一拼(行话叫"调包")。** <span class="csf-b csf-key">重点</span>

很多人一上来就想学最热门的框架、最酷的 AI 库(框架、库都是别人写好、可以直接拿来用的现成代码,省得你从零造轮子),觉得底层"没用、太慢、又难"。短期看好像跑得快,但**地基没打,楼越盖越晃**。一遇到底层报错(比如"内存溢出"——程序占用的内存超出了限制,直接崩掉;或者数据算错、性能莫名变慢),就彻底抓瞎,只能把报错复制给 AI,然后**连 AI 答得对不对都没法判断**。

> 怎么破:接受"慢就是快"。这门课的目标不是让你马上能做炫酷的东西,而是让你将来遇到任何底层问题,<b>知道去哪找、能问出对的问题</b>。这才是真本事。

<div class="csf-note">关于 AI,把话挑明:这门课里,<b>AI 只当陪练和家教,绝不当代笔。</b>那些要你"自己写、自己算、自己画"的练习,千万别丢给 AI 代劳——手算补码、搭加法器、用纸笔模拟 CPU(这几个词现在看不懂完全没关系,都是后面的课才会讲的东西),这些"笨功夫"正是把原理刻进你脑子里的过程。AI 替你写出来的,是它的肌肉,不是你的。你可以让 AI 帮你检查、给你讲不懂的地方、陪你对答案,但<b>动手那一下,必须是你自己。</b>这门课每讲都会提醒你哪些地方"别让 AI 代写"。</div>
