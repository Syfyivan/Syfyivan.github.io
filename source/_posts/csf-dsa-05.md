<div class="csf-key-note">递归不是什么高深魔法，它就一句话：<b>把一个大问题，交给"更小的同一个问题"去解决，小到不能再小时直接给答案。</b><br>这一讲我们不背概念。你会亲手写两个最经典的递归（阶乘、斐波那契），然后在纸上把每一层调用画出来——看懂了那张图，你就真的懂递归了。</div>

## 🎯 这一讲你会学到什么

很多人第一次见递归，脑子是懵的："一个函数自己调用自己？那不就死循环了吗？"（死循环就是程序一直在原地打转、永远停不下来。）这种困惑特别正常，说明你在认真想。这一讲就是要把这层窗户纸捅破。

学完这一讲，你应该能做到：

- 写出一个**带正确出口**的简单递归函数，知道为什么"出口"是性命攸关的那一行。
- 在纸上画出一段递归的**调用栈**，讲清楚每一层到底在干什么、在等什么。
- 用递归写出阶乘、斐波那契、列表求和这三个小东西。
- 亲眼看到朴素递归算斐波那契是怎么"慢到爆炸"的——记住这个痛，第 12 讲我们用动态规划来救它。

<div class="csf-note">上一讲（第04讲）我们用哈希表"用空间换时间"。这一讲换个脑回路：递归是一种<b>思考问题的方式</b>，它教你把难题拆成一模一样的小题。这个拆解的直觉，会一路陪你到树、图、分治（把一个大问题切成几小块分别解决，再把结果合起来），还有动态规划（就是上一段说的那个，英文叫 Dynamic Programming，常缩写成 DP，后面你会经常看到这个缩写）。</div>

### 先从一个生活例子找感觉 <span class="csf-b csf-core">必读</span>

想象你在电影院，你想知道自己坐在第几排，但灯黑了看不清。你怎么办？

你拍拍前面那个人的肩膀问："你是第几排？" 你心里想好：**只要他告诉我他的排数，我加 1 就是我的排数。**

可前面那个人也看不清啊，于是他又问他前面的人……一直传到第一排。第一排的人不用问任何人，他直接知道："我是第 1 排。" 然后答案开始往回传：第 1 排 → 第 2 排 → 第 3 排……一直传回到你。

这就是递归的全部精神：

- **递归式**：我的答案 = 前面那个人的答案 + 1（把问题甩给"更小的同一个问题"）。
- **递归出口 / 基线条件**：第一排的人不用再问别人，直接给答案（小到不能再小，直接返回）。

记住这两样东西——**递归式**和**出口**——一个递归函数就是这两块拼起来的。

### 动手练 1：阶乘 <span class="csf-b csf-key">重点</span>

阶乘的定义你可能见过：5! = 5 × 4 × 3 × 2 × 1 = 120。

用递归的眼光看它，关键是发现这个规律：**5! = 5 × 4!**，而 **4! = 4 × 3!**……也就是 **n! = n × (n-1)!**。这就是递归式。那出口呢？乘到 1! 时，直接等于 1，不用再往下拆了。

先别看代码，**先猜一下**：下面这个函数 `factorial(3)` 会返回几？在心里算好再往下看。

```python
def factorial(n):
    if n == 1:            # 递归出口：小到不能再小，直接给答案
        return 1
    return n * factorial(n - 1)   # 递归式：把问题甩给更小的自己

print(factorial(3))
```

揭晓：返回 `6`（也就是 3 × 2 × 1）。如果你猜对了，恭喜；猜错也没关系，我们马上画图看清它到底怎么算的。

它在内部其实是这样一层层展开又收回来的：

```text
factorial(3)
= 3 * factorial(2)
= 3 * (2 * factorial(1))
= 3 * (2 * 1)        ← factorial(1) 碰到出口，返回 1
= 3 * 2
= 6
```

看到没？**去的路上**是不停地拆（往下问），**回来的路上**才真正开始算（往上传）。

这个"去和回"的过程，计算机内部是用一个叫**调用栈**的东西管起来的，这是这一讲必须搞懂的核心词，我们用大白话说清楚：

<div class="csf-key-note"><b>什么是调用栈？</b><br>每次一个函数调用另一个函数，计算机都会在内存里一块叫"栈"的地方，压上一张"便利贴"，记着这层调用算到哪了、它在等谁的结果。<br>算 <code>factorial(3)</code> 时，便利贴一张张往上叠：factorial(3) 在等 factorial(2)，factorial(2) 在等 factorial(1)…… 直到 factorial(1) 碰到出口直接给出 1，便利贴才开始一张张揭下来，每揭一张就把结果算出来往回传（3 等到了 2×1=2，于是 3×2=6）。<br>"去的路上不停往上叠便利贴，回来的路上一张张揭下来做计算"——这一摞便利贴，就是<b>调用栈</b>。往上叠叫<b>压栈</b>，揭下来叫<b>出栈</b>。</div>

<div class="csf-why">为什么一定要先写出口？因为递归是"自己调用自己"，如果没有一行告诉它"到此为止、直接返回"，它就会 n、n-1、n-2…… 一路减到负数还停不下来，永远调用下去。这就是后面要讲的<b>栈溢出</b>。出口不是可选项，是递归的命根子。</div>

### 动手练 2：斐波那契 <span class="csf-b csf-key">重点</span>

斐波那契数列长这样：1, 1, 2, 3, 5, 8, 13, ……（从第三个开始，每个数都是前两个之和）。

它的递归式有**两个**分支：`fib(n) = fib(n-1) + fib(n-2)`。出口也有两个：`fib(1) = 1`，`fib(2) = 1`。

照例**先猜后做**：你觉得 `fib(5)` 是几？（数一数那个数列的第 5 个）

```python
def fib(n):
    if n == 1 or n == 2:      # 两个出口
        return 1
    return fib(n - 1) + fib(n - 2)   # 递归式：拆成两个更小的自己

print(fib(5))
```

揭晓：`fib(5)` = 5。

接下来是这一讲**最重要的动手任务**：拿出纸和笔，把 `fib(5)` 的**调用树**完整画出来。

先别被"调用树"这个新词吓到——它和前面的"调用栈"是亲戚：阶乘每层只调用一个更小的自己，画出来是**一条线**（这就是调用栈那一摞便利贴）；而斐波那契每层会分叉成 `fib(n-1)` 和 `fib(n-2)` **两个**小问题，画出来就从一条线变成了**一棵会分叉的树**，所以我们换个名字叫它**调用树**。本质还是"谁调用了谁"，只是形状不一样。

别嫌麻烦，这张图画一次，胜过看十篇文章。我先给你画好，但你一定要自己再画一遍：

```text
                fib(5)
              /        \
          fib(4)        fib(3)
         /     \        /     \
     fib(3)  fib(2)  fib(2)  fib(1)
     /    \
 fib(2)  fib(1)
```

画的时候你会有两个重要发现：

1. 每个不是出口的节点，都裂成**左右两个孩子**（对应 n-1 和 n-2），叶子（fib(1) 和 fib(2)）就是出口，直接返回 1。
2. **`fib(3)` 被算了两次，`fib(2)` 被算了好几次！** 同样的小问题，被翻来覆去重复计算。n 越大，重复得越离谱。把这个"浪费"的感觉牢牢记住，这一讲翻车现场和第 12 讲都要找它算账。

### 动手练 3：递归求列表所有元素之和 <span class="csf-b csf-core">必读</span>

前两个是数学题，这个更像真实编程：给一个列表 `[1, 2, 3, 4]`，用递归把它加起来。

怎么用递归的眼光拆？**整个列表的和 = 第一个元素 + 剩下那截列表的和**。剩下那截更短，再拆……拆到空列表，和就是 0（这就是出口）。

先自己写，写不出来再看下面。**这段尤其要自己写，别让 AI 代写**——把"大列表 = 头 + 小列表"这个拆法想明白，比抄对答案重要一百倍。

```python
def list_sum(nums):
    if len(nums) == 0:        # 出口：空列表，和为 0
        return 0
    return nums[0] + list_sum(nums[1:])   # 头 + 剩下那截的和

print(list_sum([1, 2, 3, 4]))   # 先猜：等于几？
```

这段代码里有三个写法，前面没正式讲过，这里一次说清楚（都很简单）：

- `len(nums)` 是求这个列表里**有几个元素**，所以 `len(nums) == 0` 就是判断它是不是**空的**（一个元素都没有）。这正是我们的出口。
- `nums[0]` 是取列表的**第一个**元素。要注意：列表里的位置是**从 0 开始数的**，所以 `[0]` 才是第一个，`[1]` 是第二个，以此类推。
- `nums[1:]` 表示从**第 2 个元素**（位置 1）开始、一直取到末尾的那一截，正好就是"去掉头之后剩下的小列表"。这种"取一段"的写法叫**切片**。

揭晓：`10`。它的展开过程和阶乘一个味道：

```text
list_sum([1,2,3,4])
= 1 + list_sum([2,3,4])
= 1 + (2 + list_sum([3,4]))
= 1 + (2 + (3 + list_sum([4])))
= 1 + (2 + (3 + (4 + list_sum([]))))   ← 空列表碰到出口，返回 0
= 1 + (2 + (3 + (4 + 0)))
= 10
```

<div class="csf-key-note">上面这段 list_sum 也是同一回事：便利贴一张张往上叠，[1,2,3,4] 在等 [2,3,4]，[2,3,4] 在等 [3,4]…… 直到 [] 碰到出口给出 0，便利贴才开始一张张揭下来，每揭一张就把结果加上去往回传。<b>压栈、出栈，和阶乘一模一样。</b></div>

<details class="csf-fold"><summary>再深一层：栈是有限的，所以会"溢出"<span class="csf-b csf-skim">细究 · 可跳读</span></summary>
内存里这块放便利贴的"栈"空间是<b>有限</b>的，叠不了无限多张。<br>所以如果一个递归没有出口、或者永远到不了出口，它就会一直压栈、压栈，便利贴越叠越高却从不揭下来，最后把栈撑爆——Python 会报错 <code>RecursionError: maximum recursion depth exceeded</code>，这就是常说的<b>栈溢出</b>。<br>这正是下面"翻车现场"的主角，看完这段你就知道那个报错到底在说什么了。</details>

## 🔧 翻车现场

<div class="csf-note"><b>翻车一：忘了写出口，直接栈溢出。</b><br>这是新手第一杀手。比如把阶乘写成只有递归式、没有 if 出口：<br><code>def f(n): return n * f(n - 1)</code><br>它会 n、n-1…… 一路减到负数还停不下来，调用栈被无限压满，Python 报 <code>RecursionError: maximum recursion depth exceeded</code>。<br><b>解法：</b>写任何递归，第一件事不是写递归式，而是先问自己"什么情况下我不用再递归、能直接返回答案？"——先把出口写好，再写递归式。</div>

<div class="csf-note"><b>翻车二：出口写了，但永远到不了。</b><br>比如想算 factorial(5)，出口写的是 <code>if n == 0</code>，递归式却是 <code>n * factorial(n - 2)</code>（一次减 2）。n 从 5 出发：5、3、1、-1、-3…… 永远跳过 0，照样溢出。<br><b>解法：</b>确保每次递归都在<b>朝出口靠近</b>。减 1 就老老实实减 1，让 n 一定能踩到出口那个值。</div>

<div class="csf-note"><b>翻车三：朴素递归算斐波那契，慢到怀疑人生。</b><br>还记得 fib(5) 调用树里 fib(3)、fib(2) 被重复算了吗？这个重复是<b>指数级</b>爆炸的。你试试把 <code>fib(40)</code> 跑一下，会卡好几秒；<code>fib(50)</code> 可能要等到天荒地老。原因就是它把同一个小问题反反复复重算了天文数字遍。<br><b>解法：</b>这一讲<b>先记住这个痛</b>，知道"朴素递归可能藏着大量重复计算"就够了。怎么救它（用一个小本本把算过的结果记下来，下次直接查）是第 12 讲动态规划的主场。现在你只需要有这个警觉：递归写出来能跑 ≠ 它跑得快。</div>
