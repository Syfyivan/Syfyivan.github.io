> 承上：上一章阿册看懂了管理员“一眼扫过全桌、有重点地看”。这一章他追问：那些摊在桌上的“纸条”到底是怎么来的、怎么存的？

老馆长带阿册到入口处。每来一句话，先过一道“剪牌机”：它不按一个字一个字剪，而是按常见的片段剪——“图书馆”剪成一片，“还给了”可能剪成“还”“给了”两片。剪出来的是一张张“字牌”。

阿册又问：“这些字牌往哪放？”老馆长指向后面巨大的库房：里面是一面望不到边的货架，每张字牌都按“意思”摆——意思相近的摆得近，意思相远的摆得远。“猫”和“狗”离得近，“猫”和“扳手”离得远；“国王”减去“男人”再加“女人”，差不多就走到了“女王”的位置。

“要找跟某张牌相关的，”老馆长说，“不用一张张翻，看货架上谁离它近就行。”

## 概念揭晓

入口那台“剪牌机”，是**分词器（tokenizer）**：它把文本切成模型处理的基本单位 **token**。token 不一定是一个字或一个词，常常是更小的“子词片段”，这样既能覆盖生僻词，又不至于词表爆炸。

那面“按意思摆牌的货架”，是 **embedding（嵌入）**：每个 token 被表示成一个高维向量，向量的位置编码了它的“意思”。

“意思相近摆得近”的那个空间，是**语义空间**：在这个空间里，含义相似的词向量距离近。

“看谁离它近”，是用**相似度**（如余弦相似度）来衡量两个向量有多接近——这正是后面第 04 讲 RAG 检索的数学基础。

## 为什么按 token 而不是按字

直接按字符处理太细（丢词义），按整词处理又会让词表大到离谱、还搞不定没见过的新词。

子词分词是折中：把常见词当一整块，把生僻词拆成更小的、见过的片段。于是模型既能高效处理常用语，又能用“拼片段”的方式应付没见过的词和拼写。你输入的每段文字，模型眼里都是一串 token，而不是一个个汉字或字母。这也顺带解释了一个常被吐槽的现象：问它“strawberry 里有几个 r”，它容易数错——因为它看到的是 `straw`+`berry` 这样的片段，根本不是一个个字母。

## embedding：把意思变成坐标

模型不直接懂“猫”这个字，它懂的是“猫”对应的那个向量——一串很长的数字坐标（几百上千个数排在一起，这就是前面说的“高维”）。

这串坐标不是人定的，是模型在训练中学出来的：为了把语言任务做好，它被迫把“意思相近的词”放到相近的位置。于是“意思”第一次有了可计算的形式。这其实就是 03.1 说的“表征”落到词这一层的样子。

## 语义空间里的距离和方向

在这个空间里有两件有趣的事：

- **距离**代表相似度：“开心”和“高兴”离得近，“开心”和“扳手”离得远。
- **方向**有时也有含义：著名的例子是“国王 − 男人 + 女人 ≈ 女王”，某些语义关系近似对应空间里的平移方向。

这并不神秘，它只是“为了把任务做好，模型把相关的东西安排到了相近的位置”的副产物。但它非常有用——一旦意思能用坐标和距离表示，“找相关内容”就变成了“找邻居”，这就是检索和推荐的底层逻辑。

## token 还牵着成本和长度

token 不只是技术细节，它直接关系到钱和容量：

- 大模型按 token 计费、按 token 限长。你的输入越长，token 越多，越贵、越占上下文。
- 中文、英文、代码的“字数→token 数”换算各不相同，估算时别想当然。粗略地，英文里常被引用的经验值是“约 4 个字符 ≈ 1 个 token”，中文则常是一个常用字 1 个 token 上下、生僻字更多；但这些只是估算，真实切法取决于具体分词器。

这也是为什么 03.5 讲“上下文窗口”时，单位是 token 而不是“字数”。

## 常见误区

第一，把 token 当成“字”或“词”。它常是子词片段，一个英文长词可能拆成好几个 token。

第二，以为 embedding 是人手工设计的。它是训练中学出来的表征，没人去定“猫该放哪”。

第三，以为“语义相近”等于“事实正确”。embedding 只告诉你两段文字意思接近，不保证内容为真——这点到 RAG 那一讲会更重要。

## 小练习

拿一句你常说的话，试着：

1. 猜猜它会被剪成几片 token（中英文混排时尤其容易猜错）。
2. 想两个“意思很近”和两个“意思很远”的词，体会它们在货架上的远近。
3. 如果要让机器“找出和这句话相关的资料”，你会怎么用“找邻居”这个思路？
