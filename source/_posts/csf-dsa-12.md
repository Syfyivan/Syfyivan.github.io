<div class="csf-key-note">动态规划（DP）听起来玄乎，其实就八个字：<b>记住答案，别重复算</b>。把一个大问题拆成小问题，小问题的答案算一次就记在"账本"里，下次直接查——慢吞吞的递归立刻变快。这一讲我们不背模板，而是亲手把第 05 讲那个"会爆炸"的斐波那契救活，再用同一套思路拿下爬楼梯和凑零钱。</div>

这是《数据结构与算法》的**最后一讲**。走到这里，你已经手写过链表、栈、队列、哈希、树和图，推过几种排序、二分、BFS/DFS（广度优先搜索 / 深度优先搜索，就是前面讲过的"遍历一张图或一棵树"的两种顺序）、双指针。动态规划是这门课的"压轴内功"——它不靠一个新数据结构，而是靠一种**看问题的角度**。学会它，你看一道难题时心里会多一个声音："这能不能拆成小问题？小问题会不会被反复算？"

## 🎯 这一讲你会学到什么

- 看懂 DP 的本质：**递归 + 一本记账本**，没有任何魔法。
- 认识两个"为什么能用 DP"的信号词：**重叠子问题** 和 **最优子结构**。
- 学会 DP 最核心的两步动作：**状态定义** 和 **写状态转移方程**。
- 掌握两种写法：**记忆化**（自顶向下）和 **自底向上递推**，知道它俩其实是一回事的两个方向。
- 亲手解三道入门题：救活斐波那契、爬楼梯、凑零钱（最少硬币数）。

<div class="csf-note">提前打个预防针：DP 是这门课里"想明白比写代码难"的部分。你大概率不会读一遍就全懂，这很正常，不是你笨。请务必<b>自己在纸上画、自己敲代码</b>。这一讲的题，恰恰是最不能让 AI 代写的——因为难的不是那几行代码，而是"我为什么这么定义状态"。那一步想通了，你才真的学到了东西。</div>

### 先回到案发现场：会爆炸的斐波那契 <span class="csf-b csf-core">必读</span>

斐波那契数列是这样的：第 0 项是 0，第 1 项是 1，之后每一项都等于前两项之和：0, 1, 1, 2, 3, 5, 8, 13……

第 05 讲我们写过一个"教科书式"的递归版本。它读起来很美，跑起来却是个灾难：

```python
def fib(n):
    if n < 2:          # 边界：第 0 项是 0，第 1 项是 1
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(10))   # 55，很快
print(fib(35))   # 还能出结果，但你会感觉到明显的卡顿
# print(fib(50)) # 别轻易跑，可能要等到天荒地老
```

**先猜后做**：你觉得 `fib(50)` 大概要算多久？几毫秒？几秒？还是几分钟以上？先在心里押一个数，再往下看为什么。

它慢的根源，是**同一个小问题被算了无数遍**。我们把 `fib(5)` 的计算摊开看：

```text
                fib(5)
              /        \
         fib(4)        fib(3)
        /    \         /    \
   fib(3)  fib(2)  fib(2)  fib(1)
        /    \
   fib(2)  fib(1)   ...
```

注意看：`fib(3)` 被算了 2 次，`fib(2)` 被算了 3 次……n 越大，重复得越夸张。`fib(50)` 这棵树有上百亿个节点。这就是 DP 要解决的核心痛点——**重叠子问题**。

<div class="csf-why">这棵树的节点数大约随项数翻倍增长，是 O(2ⁿ) 级别。从 O(2ⁿ) 到下面我们要做到的 O(n)，不是"快一点"，是"宇宙年龄"和"一眨眼"的差别。同样能跑出结果的两段代码，效率可以差到这种地步——这正是接下来要补救的。</div>

### 第一招：记忆化（给递归配一本账本） <span class="csf-b csf-core">必读</span>

既然问题是"同一个答案算了好多遍"，那解法朴素得让人想笑：**算过的就记下来，下次直接查**。这个"记下来"的动作，就叫 **记忆化（memoization）**。

我们用一个字典当"账本"：

```python
def fib(n, memo=None):
    if memo is None:
        memo = {}
    if n < 2:
        return n
    if n in memo:        # 账本里有？直接取，不重算
        return memo[n]
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo)  # 算完立刻记账
    print(f"算了一次 fib({n})")   # 调试用：看看每个 n 到底算了几遍
    return memo[n]

print(fib(35))
```

（顺便说一句那行 `print` 里的写法：`f"算了一次 fib({n})"` 是 Python 的 **格式化字符串**——字符串前面加个 `f`，就可以在里面用大括号包住一个变量，比如 `{n}`，运行时它会被自动替换成 `n` 当前的值。这样就能把变量方便地拼进一句文字里，不用手动做字符串拼接。）

跑一下你会发现：每个 `fib(n)` 的 "算了一次" 只打印**一遍**。重复计算被账本彻底掐断了。`fib(50)`、`fib(100)` 现在都是一瞬间的事。

确认它快了之后，把那行 `print` 删掉。这就是记忆化的全部精髓：**结构上还是原来的递归，只是多了"查账本 / 记账本"两步**。

<div class="csf-note">这种写法叫"自顶向下"：你从你想要的大答案 fib(n) 出发，一路往下问小问题。"账本"保证每个小问题只真正算一次。注意 Python 默认参数有个坑：别写成 <code>def fib(n, memo={})</code>，那个 {} 会在多次调用间被共享，埋下脏数据。我们用 None 再在函数内创建，就稳了。</div>

### 第二招：自底向上递推（不用递归，直接填表） <span class="csf-b csf-key">重点</span>

记忆化是"从大问题往下问"。还有个反方向的思路：**从最小的问题开始，一个一个往上算，把答案填进一张表里**。这叫 **自底向上递推（tabulation）**。

斐波那契的"表"就是一个数组 `dp`，`dp[i]` 表示第 i 项的值：

```python
def fib(n):
    if n < 2:
        return n
    dp = [0] * (n + 1)   # dp[i] = 第 i 项斐波那契数
    dp[0] = 0            # 边界：最小的两个问题，答案直接已知
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # 用已经填好的小答案，拼出大答案
    return dp[n]

print(fib(50))   # 12586269025，瞬间出
```

第一次看到 `dp = [0] * (n + 1)` 可能会愣一下：这不是"0 乘以某个数"，而是 Python 造列表的一个常用写法——`[0] * (n + 1)` 表示"生成一张长度为 n+1、里面初始全是 0 的列表"。换句话说，我们先准备好一张空表（占好 `dp[0]` 到 `dp[n]` 这么多格子），后面再一格一格往里填真正的答案。

读这段代码，请把目光锁定在 `dp[i] = dp[i - 1] + dp[i - 2]` 这一行——这就是传说中的 **状态转移方程**，听着吓人，其实就是"第 i 项怎么由更小的项推出来"。`dp[0]` 和 `dp[1]` 是 **初始值（边界）**，是不需要推、直接已知的最小答案。

<div class="csf-key-note"><b>记忆化 vs 自底向上，是同一件事的两个方向。</b><br>· 记忆化：从大往小问，遇到没算过的才算，算完记账。（自顶向下）<br>· 递推：从小往大填，按顺序把表填满。（自底向上）<br>两者复杂度都是 O(n)。入门阶段，<b>能用递推就优先用递推</b>——它不递归、不会栈溢出、思路也更"看得见摸得着"。</div>

### 看清 DP 的"两个信号"和"两步动作" <span class="csf-b csf-core">必读</span>

斐波那契帮我们把概念都见了一遍。现在归个总，这套话术你会反复用到：

**两个信号——什么样的题能用 DP：**

- **重叠子问题**：解大问题会反复用到同一批小问题的答案（像 `fib(3)` 被算很多遍）。这是 DP 能"提速"的前提。
- **最优子结构**：大问题的最优解，可以由小问题的最优解拼出来。（比如"爬到第 n 阶的方法数"，能由"爬到第 n-1 阶"和"第 n-2 阶"的方法数加起来。）这是 DP 能"拆解"的前提。

**两步动作——会用 DP 的人怎么下手：**

1. **状态定义**：先用一句人话说清楚 `dp[i]` 到底代表什么。这是**整个 DP 最难也最关键的一步**。状态定义含糊，后面的方程根本没法写。
2. **状态转移方程**：想清楚"`dp[i]` 怎么由更小的 `dp` 推出来"，再把边界（初始值）定对。

<div class="csf-note">把这两步念出声："dp[i] 表示……（一句话）；dp[i] 等于……（由更小的状态算出来）；边界是 dp[?] = ?。"能顺畅说完这三句，题基本就解开了。说不顺，说明状态没想清楚——别急着写代码，回去抠状态定义。</div>

### 实战一：爬楼梯 <span class="csf-b csf-key">重点</span>

> 一段楼梯有 n 阶。你每次可以跨 1 阶或 2 阶。问：爬到第 n 阶，一共有多少种不同的走法？

**先猜后做**：n = 3 时有几种走法？拿张纸把所有走法列出来（提示：1+1+1、1+2、2+1……）。先数出来，再往下对答案。

别急着写代码，先走"两步动作"：

- **状态定义**：`dp[i]` = 爬到第 i 阶的走法总数。
- **想转移**：我要到第 i 阶，最后一步只有两种可能——要么从第 i-1 阶跨 1 阶上来，要么从第 i-2 阶跨 2 阶上来。所以到第 i 阶的走法数，就是这两种来源的走法数**相加**。
- **转移方程**：`dp[i] = dp[i - 1] + dp[i - 2]`。
- **边界**：`dp[1] = 1`（一阶只有 "1" 一种走法），`dp[2] = 2`（"1+1" 和 "2" 两种）。

> 等一下——这方程跟斐波那契长得一模一样？没错。很多 DP 题"换层皮"就是斐波那契。这正是 DP 的迷人之处：表面千变万化，骨架就那么几种。

```python
def climb_stairs(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1            # 爬到第 1 阶：1 种
    dp[2] = 2            # 爬到第 2 阶：2 种
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(climb_stairs(3))   # 你刚才数出来的，应该是 3
print(climb_stairs(10))  # 89
```

跑之前先猜 `climb_stairs(10)`。和你押的数对上了吗？如果 n=3 你数出来就是 3，说明你的"状态定义"和真实问题严丝合缝——先用脑子想清楚、再让代码验证，这个顺序对了，后面的题都会顺很多。

### 实战二：凑零钱（最少硬币数） <span class="csf-b csf-key">重点</span>

> 给你几种面额的硬币（每种数量不限），比如 `[1, 3, 5]`，再给一个目标金额 `amount`，比如 11。问：**最少**用几枚硬币能凑出这个金额？凑不出就返回 -1。

这道题比爬楼梯难一截，因为它要求"**最少**"——这就用上了"最优子结构"。还是走两步动作：

- **状态定义**：`dp[x]` = 凑出金额 x **最少需要的硬币数**。
- **想转移**：要凑出金额 x，我最后放下的那一枚硬币，面额可能是 coins 里的任意一种。假如最后一枚是面额 c，那剩下的 `x - c` 这部分，最少硬币数就是 `dp[x - c]`，再加上最后这一枚，就是 `dp[x - c] + 1`。我**试遍所有面额**，取里面最小的那个：
- **转移方程**：`dp[x] = min(dp[x - c] + 1)`，其中 c 取遍所有硬币面额（且 x - c >= 0）。
- **边界**：`dp[0] = 0`（凑 0 元，需要 0 枚硬币，天然成立）。

<div class="csf-note">这条方程里的 <code>min(...)</code> 要解释一下，不然容易看着别扭。你学过的 min 是"在好几个数里取最小"——这里也是这个意思：c 每取一种面额，就得到一个候选答案 <code>dp[x - c] + 1</code>，**把所有面额对应的候选都算出来、取里面最小的那个**，才是 dp[x]。写成 <code>min(dp[x - c] + 1)</code> 只是一种简写记法，并不是真的只往 min 里放了一个数，而是省略了"对所有 c"这层意思。<br>下面代码里没有直接调用 <code>min</code>，而是写成 <code>if x - c >= 0 and dp[x - c] + 1 < dp[x]: dp[x] = ...</code>——这其实是**用循环逐个比较来实现"取最小"**：每试一种面额 c，只要算出来的候选比当前记的 <code>dp[x]</code> 更小，就更新它；一圈循环下来，<code>dp[x]</code> 自然就停在了最小值上。所以方程里的 min 和代码里的"比当前小就更新"是完全等价的两种写法。</div>

**先猜后做**：用 `[1, 3, 5]` 凑 11，你手算一下最少几枚？（提示：贪心地先拿大的 5+5=10，再拿 1，是 3 枚——但贪心不一定对，DP 会告诉你真正的最优。）

```python
def coin_change(coins, amount):
    INF = float('inf')              # 用"无穷大"表示"暂时凑不出"
    dp = [INF] * (amount + 1)
    dp[0] = 0                       # 边界：凑 0 元需要 0 枚
    for x in range(1, amount + 1):  # 从小金额往大金额，逐个填表
        for c in coins:             # 试遍每一种面额作为"最后一枚"
            if x - c >= 0 and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    return dp[amount] if dp[amount] != INF else -1

print(coin_change([1, 3, 5], 11))  # 3  （5 + 5 + 1）
print(coin_change([2], 3))         # -1 （全是偶数，永远凑不出奇数 3）
```

`dp = [INF] * (amount + 1)` 还是上面那个造列表的写法——"生成一张长度为 amount+1、里面初始全是 INF 的表"，只不过这次初始值不是 0，而是 INF。这里的 `INF`（无穷大）是个常用小技巧：用它表示"这个金额目前还凑不出来"。如果填完整张表，`dp[amount]` 还是 INF，说明压根凑不出，返回 -1。

<details class="csf-fold"><summary>为什么贪心（每次拿最大面额）会出错？<span class="csf-b csf-skim">细究 · 可跳读</span></summary>
经典反例：硬币面额 <code>[1, 3, 4]</code>，凑金额 6。贪心会先抓最大的 4，剩 2，再用 1+1，一共 3 枚。但最优解是 3 + 3 = 2 枚。贪心只顾眼前最大，看不到全局；DP 把每个金额的最优解都老老实实算一遍存下来，所以不会被"眼前的大面额"骗。<br>记住这个区别很有用：直觉解（贪心）有时对、有时翻车，而 DP 给的是真正的最优。
</details>

<details class="csf-fold"><summary>凑零钱也能写成记忆化版本<span class="csf-b csf-skim">细究 · 可跳读</span></summary>
任何递推都能改写成记忆化，反之亦然。凑零钱的记忆化版长这样，对照着看能加深"两个方向是一回事"的理解：

```python
def coin_change(coins, amount):
    memo = {}
    def dp(x):
        if x == 0:
            return 0
        if x < 0:
            return float('inf')   # 凑过头了，此路不通
        if x in memo:
            return memo[x]
        best = float('inf')
        for c in coins:
            best = min(best, dp(x - c) + 1)
        memo[x] = best
        return best
    ans = dp(amount)
    return ans if ans != float('inf') else -1

print(coin_change([1, 3, 5], 11))  # 3
```
</details>

## 💡 自己复述一遍

合上屏幕，用一句话回答：**动态规划到底是什么？**

如果你能说出类似"**就是带账本的递归——把大问题拆成小问题，每个小问题只算一次、把答案记下来反复用**"，那你已经抓住了它的灵魂。再奢侈一点，试着把"两步动作"也念出来：先用一句话**定义状态** `dp[i] 是什么`，再写出**它怎么由更小的状态推出来**。能顺口说完，这一讲就过关了。

## 🔧 翻车现场

**翻车一：状态定义含糊，方程根本写不出来。** 这是新手 90% 卡壳的真正原因。你盯着题憋了半天写不出转移方程，十有八九不是方程难，是你没说清 `dp[i]` 到底代表什么。**解法**：停下来，强迫自己用一句完整中文写下"dp[i] 表示……"。写不出这句话，就别碰代码。状态清晰了，方程往往自己就浮出来了。

**翻车二：初始值 / 边界设错。** 整张表的逻辑都对，结果偏偏不对，多半是边界。比如爬楼梯把 `dp[2]` 写成 1，凑零钱忘了 `dp[0] = 0`。**解法**：单独想最小的那几个问题（n=0、n=1、x=0），把它们的答案**直接手算**填进去，别让循环去推这些"地基"。

**翻车三：循环顺序搞反，用到了还没填好的格子。** 自底向上必须**保证算 `dp[i]` 时，它依赖的更小的格子都已经填好了**。斐波那契、爬楼梯从小往大循环就对。**解法**：写完循环，挑中间一个 i，问自己"这一步用到的 `dp[i-1]`、`dp[i-2]` 此刻填了没？"

**翻车四：把 DP 想得太玄，直接去背模板 / 让 AI 代写。** DP 没有"模板背了就会"这回事，因为难的是**针对这道题想出状态定义**，而这恰恰是模板和 AI 给不了你的。**解法**：老老实实在纸上画小例子（n=3、n=4），看小问题怎么拼成大问题。想通一道，胜过抄十道。

## ✅ 自检三问

1. "重叠子问题"和"最优子结构"分别是 DP 的什么前提？（一个管"为什么能提速"，一个管"为什么能拆解"，你能对上号吗？）
2. 记忆化和自底向上递推，区别在哪？它俩的时间复杂度都是多少？
3. 凑零钱里，为什么不能简单地"每次都拿最大面额"（贪心）？给一个会翻车的例子。

## 🚀 挑战

给你三个台阶难度，自己动手，**别让 AI 代写**——写不出来时让它给提示、帮你看哪里错了就行：

1. **基础（先猜后做）**：不看上面的代码，凭自己理解，把"爬楼梯"用**记忆化**重写一遍（上面给的是递推版）。写完先猜 `climb_stairs(20)`，再运行验证。
2. **进阶**：改造爬楼梯——如果每次可以跨 1、2、**或 3** 阶呢？先写出新的状态转移方程（提示：`dp[i] = ?`），再改代码。边界也要重想。
3. **挑战**：凑零钱换个问法——不求"最少几枚"，改求"**一共有多少种凑法**"（凑出 amount 的不同组合数）。这题状态定义和循环顺序都更微妙，正是练"想清楚状态"的好机会。卡住了，回头看凑零钱那段，琢磨"组合数"和"最少数"的转移哪里不一样。

<div class="csf-why">第 3 题确实偏难，第一次做不出来太正常了。重点不是做对，而是体会"换一个问法，状态定义就得跟着重想"——这种敏感度，比记住任何一道题的答案都值钱。</div>

## 📦 复制带走

<div class="csf-card">📌 <b>DP 的本质</b>：递归 + 一本记账本。把大问题拆成小问题，每个小问题只算一次、记下来反复用。没有魔法。<br>📌 <b>会用 DP 的两步动作</b>：① 用一句人话<b>定义状态</b> dp[i] 是什么；② 写出<b>状态转移方程</b>（dp[i] 怎么由更小的状态推出）+ 定对边界。状态想不清，方程必然写不出。<br>📌 <b>两种写法是一回事</b>：记忆化（从大往小问，自顶向下）和递推（从小往大填，自底向上），都是 O(n)。入门优先用递推。<br>📌 <b>最常见的三个坑</b>：状态定义含糊（方程就写不出）、边界 / 初始值设错（最小的几格要手算填）、循环顺序搞反（算到某格时它依赖的更小的格子还没填）。</div>

### 写在整门课的最后

走到这里，《数据结构与算法》十二讲就全部结束了。回头看看你这一路：从用大 O 估算快慢，到亲手写链表、栈、队列、哈希、树、图；从几种排序、二分，到 BFS/DFS、双指针，再到今天的动态规划。这些不是"背下来的知识点"，是你**一行行敲、一道道推**练出来的内功。

请相信一件事：你现在已经具备了那个最珍贵的东西——**判断力的地基**。看到一段代码，你会下意识想"它是 O(n) 还是 O(n²)"；遇到一个新问题，你会问"该用哈希还是栈，能不能拆成子问题"。AI 能秒写出排序和二分，但**能看出它写错了、写慢了、答非所问了的人**，才是不可替代的。这门课从头到尾就在帮你成为这样的人，而不是只会照单全收的人。
