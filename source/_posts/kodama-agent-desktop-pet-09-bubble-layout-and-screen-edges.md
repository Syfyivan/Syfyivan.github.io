桌宠 UI 最容易被低估的部分，不是画一只宠物，而是让它在真实桌面上“不烦人”。

真实使用时，用户不会把桌面清空给桌宠表演。它旁边可能是飞书输入框、浏览器正文、终端、日历、全屏应用、二维码、悬浮按钮、Dock 和菜单栏。只要气泡挡住一个关键按钮，或者桌宠的点击区域比图案大很多，用户就会马上觉得这个工具在打扰工作。

这一篇记录 Kodama 气泡布局踩过的坑：气泡离宠物太远、气泡盖住宠物、宠物半出屏后面板也出屏、点击范围过大、缩小时 tab 溢出、边界处无法关闭设置面板。

## 第一版问题：气泡离宠物太远

最早的气泡只是固定放在桌宠上方：

```text
panel



pet
```

看起来合理，但实际使用时会很奇怪。气泡像另一个独立窗口，不像宠物“说出来”的东西。尤其当桌宠缩小以后，气泡和宠物之间空出一大段，视觉关系断掉了。

后来把气泡改成“贴近宠物”，优先从宠物附近找位置：

```text
above
below
left
right
```

但这又带来第二个问题：贴太近时，气泡会盖住宠物。

## 第二版问题：气泡盖住宠物

桌宠不是装饰背景，它是用户识别这个系统的主体。如果气泡叠在宠物脸上，用户看到的是几张通知卡片，而不是桌宠。

所以布局算法不能只问“气泡有没有在屏幕内”，还要问“气泡有没有避开宠物可见区域”。

一个简化后的判断是：

```js
const visibleArea = getVisibleViewport();
const visiblePet = intersect(petRect, visibleArea);

for (const placement of ['top', 'bottom', 'left', 'right']) {
  const bubbleRect = layoutBubble(petRect, placement);
  if (!inside(bubbleRect, visibleArea)) continue;
  if (overlap(bubbleRect, visiblePet)) continue;
  return bubbleRect;
}
```

这里的关键是 `visiblePet`，不是完整 `petRect`。当宠物有一半在屏幕外时，屏幕外那部分不需要避让；但屏幕内可见的那半只宠物不能被盖住。

## 第三版问题：宠物到边缘后，气泡也跟着出去

用户希望把桌宠拖到屏幕角落，甚至只露出半个。这很合理，很多桌宠都会允许“贴边停靠”。

但如果气泡仍然以宠物中心点为锚点，就会变成这样：

```text
| screen edge
|      bubble half outside
|    [ pet half visible ]
```

这不对。宠物可以半出屏，因为这是用户主动放置；气泡不应该半出屏，因为气泡是信息。

所以这里需要把“宠物位置限制”和“气泡位置限制”分开：

- 宠物允许进入边缘停靠状态，只保留一部分可见和可拖拽区域。
- 气泡必须始终在可见区域内。
- 气泡根据宠物当前可见区域重新选择左上、左下、右上、右下或侧边。

换句话说，宠物可以像抽屉把手一样停在边上，气泡不能跟着被抽出屏幕。

## 第四版问题：设置面板在边缘关不掉

设置面板比气泡更大，问题更明显。用户把桌宠拖到屏幕边缘时，如果面板固定跟着宠物右侧打开，关闭按钮可能直接跑出屏幕。

一个比较稳的策略是：

1. 面板打开时先计算可见区域。
2. 如果默认位置会出屏，就反向打开。
3. 如果仍然放不下，就贴住屏幕内边距。
4. 支持点击面板外关闭。
5. 关闭按钮固定在面板可见区域内，而不是跟随原始坐标。

“点击其它地方关闭”很重要。因为在桌面悬浮窗里，不应该假设用户一定能点到右上角按钮。

## 第五版问题：点击范围太大

透明 Electron 窗口有一个常见坑：看起来只有宠物图案，实际上整个窗口矩形都可能接收点击。

用户感受到的是：

> 我的鼠标离它还有一点距离，怎么也点到它了？

这会严重影响桌面操作。解决时要拆成两层：

第一层是窗口级穿透。空白区域尽量 `setIgnoreMouseEvents(true, { forward: true })`，让鼠标事件穿过去。

第二层是图形级命中。真正可点区域不应该是整个图片矩形，而应该是一个较小的交互范围，例如：

```text
hitbox = pet visual rect * 0.3
```

后来设置里加了“点击范围”滑杆，就是让用户自己把这个范围调小。默认值应该保守，宁愿少一点交互，也不要影响用户点别的东西。

## 第六版问题：左键和右键要分开

用户提出一个很真实的需求：如果桌宠透明度调低，左键应该尽量穿透，不要挡住屏幕；只有右键才触发设置。

这意味着“点击触发”不应该写死。需要至少支持：

- 左键触发：适合把桌宠当作可交互小工具。
- 右键触发：适合把桌宠放在角落当状态提示，不影响主操作。
- 拖拽触发：鼠标按住可拖动，但空白区域仍然穿透。

这类设置看起来小，但它决定桌宠是“可爱”还是“烦人”。

## 第七版问题：缩小时 tab 文案溢出

桌宠设置面板缩小时，最早的 tab 是这样排的：

```text
[设置] [待交互] [已完成] [会话] [最近]
```

窗口变窄后，中文会竖排、挤压，甚至溢出按钮。这个问题不能简单靠 `font-size: 12px` 解决，因为再窄还是会炸。

更合理的方式是按宽度切换布局：

- 宽面板：一行 tab。
- 中等宽度：短标签，例如“设置 / 交互 / 完成 / 会话 / 最近”。
- 窄面板：两行 grid 或图标 + tooltip。

这里的原则是：不要让文字自己决定布局。固定格式的控件必须有稳定尺寸和响应式规则。

## 第八版问题：气泡常驻和忽略

通知系统常见做法是几秒后自动消失。但 Agent 交互不一样。

如果桌宠提示“需要你确认权限”，几秒后消失，用户可能完全错过。这个提示应该常驻，直到用户：

- 点击进入对应会话。
- 点击忽略。
- 任务状态改变为完成或取消。

因此气泡需要有明确的生命周期：

```text
new event -> show bubble
user dismiss -> hidden
state resolved -> moved to completed
all dismissed -> clear stack
```

同时，“全部忽略”只应该作用于当前可见气泡，不应该删除历史任务。历史仍然能在面板和任务详情里找到。

## 第九版问题：多个会话不能只叠一堆卡片

当多个 Agent 同时跑，气泡堆叠会很快失控。用户需要知道：

- 哪个是飞书消息。
- 哪个是本地 Agent。
- 哪个需要交互。
- 哪个已经完成。
- 哪个能跳转。

所以我把提示分成不同视觉类型：

- 待交互：暖色，强调需要处理。
- 完成：冷色或蓝紫色，强调结果。
- 飞书/会话消息：中性色，强调来源。
- 错误：红色，强调失败原因。

但颜色只是辅助。更重要的是文案和动作按钮：

```text
本地 · 待交互
Agent 需要你确认
打开 Claude Code 终端 ↗   分享   忽略
```

用户一眼能看到状态，也能直接回到现场。

## 一个可用的布局策略

最终我更倾向于这种策略：

1. 先算宠物在屏幕内的可见矩形。
2. 计算气泡栈的理想尺寸。
3. 按 `top-right / top-left / bottom-right / bottom-left / side` 顺序找位置。
4. 每个候选位置必须满足：
   - 在可见屏幕内。
   - 不覆盖宠物可见主体。
   - 不挡住设置面板的关闭按钮。
5. 如果都不满足：
   - 限制气泡高度，内部滚动。
   - 缩短摘要。
   - 显示“还有 N 条”入口。

伪代码像这样：

```js
function placeBubbleStack(petRect, bubbleSize, viewport) {
  const visiblePet = intersect(petRect, viewport);
  const candidates = buildCandidates(visiblePet, bubbleSize, viewport);

  for (const rect of candidates) {
    if (!inside(rect, viewport)) continue;
    if (overlap(rect, visiblePet)) continue;
    return rect;
  }

  return clampToViewport(shrink(bubbleSize), viewport);
}
```

注意最后一步只是兜底。正常情况下，气泡不应该靠遮挡宠物来“勉强显示”。

## 这一轮的经验

桌宠布局的难点不是 CSS，而是它没有固定页面容器。它漂浮在用户所有应用之上，用户可以把它拖到任何地方，屏幕大小和全屏状态也随时变化。

因此它的 UI 规则要比普通网页更像窗口管理器：

- 宠物位置和气泡位置要分开。
- 可见区域比窗口尺寸重要。
- 用户主动放到边缘时，宠物可以半隐藏，信息不能半隐藏。
- 面板必须有逃生通道。
- 命中区域要尽量小。
- 所有气泡都不能盖住宠物主体。

桌宠的可爱感不是来自图案本身，而是来自它知道什么时候不要挡路。
