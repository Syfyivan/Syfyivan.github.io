> 承上：上一章阿铺把账立起来了。这一章，老店主带他到后厨——账记得再清，店还得真转得起来。

午市一来，后厨乱套:十几桌同时点单，伙计们撞作一团。老店主一声哨，后厨立刻有了章法。

“客人多，**先排号**——来的单子排进队里，按顺序、按缓急来，别一拥而上挤垮灶台。一道菜从洗到切到炒到摆盘，**得有固定的工序串着走**，谁接谁清清楚楚。新琢磨的菜，**先在小桌上试**，别拿正餐冒险。每一桌的单子、忌口、上到第几道，**各记各的，别串桌**。料和成品**放哪取哪有定处**，不能用时满世界找。”

## 概念揭晓

老店主整顿后厨这一套，是把 AI（尤其是 Agent）系统跑起来所需的**部署与运行时（runtime）**——这正是第六讲 Harness 在生产环境里的样子。

“先排号”，是**队列（queue）**:请求多了要排队、削峰、按优先级处理，避免瞬时洪峰压垮系统。

“固定工序串着走”，是**工作流（workflow）**:把多步任务编排成可靠、可重试的流程（呼应第六、十一讲的编排），每步失败能重试、能续跑。

“新菜先小桌试”，是**沙箱（sandbox）**:让 Agent 执行代码、操作环境时，在隔离环境里跑，不碰生产（第五、九、十讲反复强调）。

“每桌各记各的”，是**会话（session）/ 状态管理**:多用户、多任务并发时，各自的上下文、记忆、进度要隔离、要持久（第四、十一讲）。

“料和成品放哪取哪”，是**存储（storage）**:模型的工作空间、文件、向量库、长期记忆都要有可靠的存放和读取。

## 从一次调用到一个系统

前面很多讲，焦点是“一次调用/一个任务”。但产品要支撑的是**成千上万并发、长期运行、随时可能出故障**的真实负载。这需要一整套基础设施:

- 请求怎么进来、排队、分发（队列）。
- 多步任务怎么可靠地跑完、断了怎么续（工作流）。
- 各用户/各任务的状态怎么隔离和保存（会话、存储）。
- Agent 的危险动作怎么隔离（沙箱）。

这就是“AI 基础设施”——把模型能力，托在一个能稳定承载真实流量的运行时上。

## 队列与工作流:扛流量、跑稳长任务

- **队列**应对“瞬时来得太多”:削峰填谷、按优先级、防止过载。它也是限流（12.4）的基础。
- **工作流**应对“一件事要好多步、还可能失败”:把长任务拆成可编排、可重试、可断点续跑的步骤。Agent 的多步循环（第六讲）一旦上生产，就需要这样的工作流引擎来保证“跑到一半挂了能接着跑”。

二者让系统既扛得住量，又跑得稳长流程。

## 会话与存储:并发下各管各的

一个真实服务同时面对很多用户、很多任务。运行时必须:

- **会话隔离**:每个用户/任务的上下文、记忆、进度互不串（呼应第四讲 04.5、第九讲隐私、第十一讲隔离）。
- **状态持久**:长任务、跨会话记忆要可靠存储，重启不丢。
- **可扩展**:用户翻倍，存储和状态管理要跟得上。

“别串桌”在 AI 里是硬要求:串了就是把用户 A 的数据泄给用户 B（第九讲）。

## 沙箱:让 Agent 动手而不闯祸

能执行代码、操作系统、读写文件的 Agent（第五、十讲），必须在沙箱里跑:

- 隔离的环境，限定它能碰什么。
- 出问题能丢弃、能回滚，不伤生产。
- 配合最小权限和审批（第九讲），把破坏面压住。

沙箱是“放手让 Agent 干活”和“不让它闯祸”之间的那道墙。

## 常见误区

第一，用“一次调用就返回”的思路做需要长流程、高并发的产品，一上量就垮。

第二，不做会话隔离，并发下用户状态互相串（数据泄露）。

第三，让 Agent 直接在生产环境执行危险动作，不进沙箱。

## 小练习

你要上线一个“帮用户批量处理文件”的 Agent 服务，预计高峰很多人同时用:

1. 哪里需要队列？哪里需要工作流（可重试、可续跑）？
2. 怎么保证每个用户的文件和进度不串、不丢？
3. Agent 执行处理脚本时，怎么用沙箱兜住风险？
