<div class="csf-key-note"><b>一句话点题：</b>硬盘上那个图标，是一份"菜谱"；你双击它，操作系统才照着菜谱真正"做出一道菜"。菜谱叫<b>程序</b>，做出来、正在被吃的那道菜叫<b>进程</b>。这一讲，我们就盯着一份菜谱怎么变成一道活着的菜，又怎么吃完被收走。</div>

上一讲我们认识了操作系统这位"大管家"，知道它在硬件世界里管 CPU、管内存、管文件。这一讲我们把镜头拉近，只看一件最日常的小事：**你双击了一个图标，然后呢？**

这件事你每天做几十遍，但十有八九从没想过中间发生了什么。今天我们就把它拆开。学完你会发现，"程序"和"进程"这两个词，以后你再也不会混着用了——而这恰恰是看懂后面所有内容（线程、内存、并发）的第一块地基。这里的"线程""内存""并发"现在都是陌生词，你不用懂，它们后面每一讲都会单独拆开慢慢讲；这里只是先提一句，告诉你今天打的地基往后能撑起什么。

## 🎯 这一讲你会学到什么

- 说清楚 **程序** 和 **进程** 到底差在哪——一个躺着不动，一个活着在跑。
- 知道从"双击"到"程序在跑"，中间操作系统偷偷做了哪几步（加载、分配内存、开始执行）。
- 认识 **PID**：每个进程的"身份证号"，以及它为什么有用。
- 知道进程不是一直在"跑"，它还会**就绪**、会**阻塞**，像人一样有不同状态。
- 亲手在任务管理器里抓到一个进程，把同一个程序开两次，亲眼看见"两个独立的活体"。

<div class="csf-note">这一讲<b>不需要你写代码</b>，但需要你亲手操作、亲眼观察。请一定打开你的电脑跟着做——光看不练，这些概念明天就忘了。</div>

## 🛠 跟我做

### 第一步：先认清两个词 <span class="csf-b csf-core">必读</span>

我们先用生活里的东西打个比方，把两个最容易混的词钉死。

<div class="csf-legend"><b>程序（Program）</b>：硬盘上的一个文件，是一堆写死的指令，<b>静态的、不动的</b>。比如 <code>微信.exe</code>、<code>计算器</code> 这个应用本身。<br>（这里的 <code>.exe</code> 是 Windows 上一种文件名后缀，专指"双击就能直接运行的程序文件"，你可以把它理解成程序文件的"姓氏"；之所以写成 <code>微信.exe</code> 而 <code>计算器</code> 没带后缀，只是为了举两种常见写法，本质都是硬盘上的一个程序文件，不用纠结后缀有没有。）<br>程序就像一张菜谱、一份乐谱、一本剧本——放在那儿不会自己动。<br><b>进程（Process）</b>：程序<b>被运行起来</b>之后的样子，<b>动态的、活着的</b>。它占着内存、用着 CPU、有自己的状态。就像照着菜谱做出来、正在被吃的那道菜；照着乐谱正在演奏的那段音乐。</div>

记住这组对照，今天就成功了一半：

| | 程序 | 进程 |
|---|---|---|
| 在哪 | 躺在硬盘里 | 跑在内存里 |
| 动不动 | 静态、不动 | 动态、在执行 |
| 有几份 | 通常一份文件 | 可以同时有好几个 |
| 比喻 | 菜谱 / 剧本 | 正在做的菜 / 正在演的戏 |

<div class="csf-note"><b>关键一句：</b>同一份菜谱，可以同时做出好几道菜。所以——<b>同一个程序，可以同时变成好几个进程。</b>这句话先记住，等会儿你会亲眼看到。</div>

### 第二步：双击之后，操作系统偷偷做了什么 <span class="csf-b csf-key">重点</span>

你双击图标，到屏幕上窗口弹出来，感觉是"一下子"的事。但这中间操作系统忙了好几步。我们慢镜头看一遍（先不用记术语，看懂流程就行）：

1. **找到文件**：操作系统先去硬盘上，按你点的图标找到那个程序文件。
2. **搬进内存**（加载）：硬盘太慢，CPU 没法直接在硬盘上干活。所以操作系统把程序的指令从硬盘**搬一份到内存**里——这一步叫"加载"。
3. **分配家当**（分配内存）：操作系统给这个即将诞生的进程划一块**专属的内存地盘**，用来放它运行时要用的数据。这块地盘是它独享的，别的进程进不来。
4. **登记身份**：操作系统给它发一个**身份证号，叫 PID**（Process ID，进程编号），并在自己的小本本上记一笔："现在多了一个进程，编号 XXXX。"
5. **开始执行**：CPU 从程序的第一条指令开始，一条一条往下跑。窗口弹出来了，进程"活"了。

<div class="csf-why"><b>为什么非得先搬进内存？</b>因为 CPU 只能跟内存打交道，速度才跟得上；硬盘相对慢得像蜗牛。这就像厨师做菜，得先把食材从冰箱（硬盘）拿到操作台（内存）上，才能下手——总不能趴在冰箱里炒菜。这个"硬盘慢、内存快"的差别，是后面好多讲的关键，先有个印象。</div>

<div class="csf-note"><b>先给你一把尺子：</b>内存大小常用 KB、MB 这两个单位来量，它们的关系是 1 MB ≈ 1000 KB，也就是 MB 比 KB 大得多。你可以把 MB 想成一个大房间、KB 想成一个小抽屉——几百 KB 是几百个小抽屉，几百 MB 是几百个大房间，差出很多倍。<br><b>先猜后做：</b>下面你要去任务管理器里找一个进程。有了上面这把尺子，动手之前先猜一下——<b>一个刚打开的计算器，大概会占多少内存？是几百 KB（几百个小抽屉）？几 MB（几个大房间）？还是几百 MB（几百个大房间）？</b>心里写个数，等会儿对一下，看看你对"程序有多吃内存"的直觉准不准。</div>

### 第三步：亲手抓一个进程 <span class="csf-b csf-core">必读</span>

现在动手。下面分 Windows 和 Mac 两种，挑你自己的系统做。

<b>如果你是 Windows：</b>

1. 打开**计算器**（开始菜单搜"计算器"，或按 <code>Win</code> 然后输入 calc）。
2. 按 <code>Ctrl</code> + <code>Shift</code> + <code>Esc</code>，打开**任务管理器**。
3. 如果窗口很小，点左下角"详细信息 / 更多详细信息"。切到"**进程**"标签页。
4. 在列表里找到"**计算器**"。看它后面那一列**内存**占用，记下来。
5. 想看 PID：切到"**详细信息**"标签页，找到 <code>Calculator.exe</code> 或 <code>CalculatorApp.exe</code>，看 **PID** 那一列，把数字记下来。

<b>如果你是 Mac：</b>

1. 打开**计算器**（按 <code>Command</code> + 空格，输入"计算器"或 Calculator，回车）。
2. 打开**活动监视器**（同样用 <code>Command</code> + 空格，搜"活动监视器"或 Activity Monitor）。
3. 在搜索框里输 <code>Calculator</code>，找到它那一行。
4. 看"**内存**"那一列，记下来。**PID** 那一列就是它的进程编号，也记下来。

无论哪种系统，你现在手里应该有两个数字：**这个计算器的 PID，和它占用的内存。**

<div class="csf-note"><b>对一下你刚才的猜测：</b>是不是比你想的多？一个"就是几个按钮"的计算器，往往也要占好几十甚至上百 MB 内存。因为它不只是几个按钮——它背后还拖着窗口界面、字体、系统组件这一大家子。这就是"程序一旦活过来，就得占真金白银的家当"。</div>

### 第四步：见证"同一个程序，两个进程" <span class="csf-b csf-key">重点</span>

这是今天最关键的一步，也是专门为了破除最常见的误会设计的。

1. **再打开一次计算器**（Windows 直接再从开始菜单点一次；Mac 上由于系统通常只保留一个计算器窗口，建议改用"**文本编辑 / 记事本**"来做这个实验，连开两个新建文档窗口）。
2. 回到任务管理器 / 活动监视器，刷新一下列表。
3. 你会看到**同一个程序名字，出现了两行**，而且——**两行的 PID 不一样！**

停下来体会一下这件事：

<div class="csf-key-note">你只是把同一个程序开了两次，但系统里现在是<b>两个独立的进程</b>。它们：<br>· 有<b>各自不同的 PID</b>（各自的身份证号）；<br>· 占着<b>各自独立的内存</b>（各过各的日子，互不相通）；<br>· 一个崩了、被你关了，<b>另一个通常毫发无伤</b>。<br>它们就像一对双胞胎：来自同一份"图纸"（同一个程序），但出生后就是两个独立的人。</div>

4. **关掉其中一个**（点窗口的关闭按钮，或在任务管理器里选中它"结束任务"）。回到列表看——**它从列表里消失了，PID 也随之作废。**另一个还在好好待着。

你刚刚完整地看了一个进程的**一生**：从程序文件被加载、分配内存、拿到 PID 开始执行，到被关掉、从系统里消失。它"活"过，也"走"了。

<details class="csf-fold"><summary>进程不是一直在"跑"：它的几种状态<span class="csf-b csf-skim">细究 · 可跳读</span></summary>
你可能以为"进程在运行"就是 CPU 一直在跑它。其实不是。你的电脑可能同时开着几十个进程，但 CPU 里真正干活的单元叫"核心"，一颗 CPU 通常只有几个核心（就是说同一时刻只能有几个人在干活），根本不可能同时伺候几十个进程——好比一家店只有几个厨师，却要同时招呼几十桌客人，忙不过来，只能一桌一桌轮着来。所以操作系统让这些进程轮流上，每个进程在不同时刻处于不同状态，最常见的三种：<br><br>· <b>运行（Running）</b>：此刻 CPU 正在执行它。<br>· <b>就绪（Ready）</b>：万事俱备，就差 CPU 轮到它——像在排队等叫号。<br>· <b>阻塞（Blocked）</b>：在等某件事完成，比如等你敲键盘、等硬盘读完文件、等网络回数据。这期间它干脆让出 CPU，不白占着，等东西来了再回到就绪队列排队。<br><br>举个例子：一个记事本进程，绝大多数时间其实是<b>阻塞</b>的——它在静静等你按键。你不打字，它就不占 CPU。这也是为什么你开着几十个程序，电脑也不一定卡：大部分进程其实都在"等"，没真在抢 CPU。CPU 怎么在它们之间快速切换、谁先谁后，是后面"调度"那几讲的事，这里先有个画面感就够了。</details>

## 💡 自己复述一遍

合上屏幕，用一句话说给自己听（说出声更好）：

<div class="csf-note">"<b>程序</b>是躺在硬盘上的文件，静态的；双击后操作系统把它<b>加载</b>进内存、<b>分配</b>一块地盘、发一个 <b>PID</b>，它就变成了正在运行的<b>进程</b>。同一个程序可以同时跑成好几个进程，每个进程<b>PID 不同、内存独立、互不连累</b>。"</div>

说不顺也没关系，回头再看一眼上面的表格和那几步流程，再说一遍。能用自己的话讲出来，才算真懂了。

## 🔧 翻车现场

<b>翻车一：以为"打开两次同一个软件，还是同一个东西"。</b>
这是今天最该破除的误会。你看到的是同一个名字、同一个图标，但系统里是**两个互相独立的进程**，各有各的 PID、各占各的内存。这有什么用？比如浏览器把每个标签页做成独立进程，一个网页卡死崩掉，其他标签页还能用，就是这个道理。**记住：名字相同 ≠ 同一个进程。看 PID。**

<b>翻车二：把"程序"和"进程"当成一个词随便混用。</b>
"我电脑上装了 50 个程序"和"我电脑上正跑着 50 个进程"是两码事——前者是硬盘上有 50 份文件，后者是内存里有 50 个活体在跑。以后跟人交流、跟 AI 描述问题时，用对词，对方（和 AI）才不会误解你。**这正是为什么要学这门课：你说不清，AI 就帮你修不好。**

<b>翻车三：以为关掉窗口进程就一定彻底没了。</b>
大多数时候是的。但有些程序点"关闭窗口"只是缩到后台——在 Windows 上就是屏幕右下角时间旁边那排小图标区（这块地方叫"托盘"），在 Mac 上是屏幕右上角那排小图标（叫"菜单栏"）；程序图标缩到那里，窗口虽然没了，进程其实还活着、还占着内存。判断的唯一靠谱办法，还是回任务管理器看那个 PID 还在不在——**眼见进程列表里没了，才算真没了。**

## 🚀 挑战

给自己留个小任务，今天就做：

打开任务管理器 / 活动监视器，**按内存占用从高到低排个序**，看看你电脑上此刻"最吃内存"的三个进程是谁。然后挑出其中一个你认识的（比如浏览器），**数一数它占了几个进程**（很多浏览器会开一堆，每个标签、每个插件都可能是独立进程，PID 各不相同）。

## 📦 复制带走

<div class="csf-card"><b>本讲精华，记住这几条就够：</b><br>1. <b>程序 = 硬盘上静态的文件（菜谱）；进程 = 跑起来的活体（做出来的菜）。</b>静态 vs 动态，是这两个词的根本区别。<br>2. <b>双击 → 加载进内存 → 分配内存 → 发 PID → 开始执行</b>，进程就此诞生。CPU 只跟内存打交道，所以必须先把程序搬进内存。<br>3. <b>PID 是进程的身份证号。</b>同一个程序可以同时跑成多个进程，它们 PID 不同、内存独立、一个崩了不连累另一个——判断"是不是同一个"，认 PID 不认名字。<br>4. 进程不是一直在跑，它会在<b>运行 / 就绪 / 阻塞</b>之间切换；很多进程大部分时间其实在"等"。</div>

下一讲（第03讲《进程里的"多个分身"：线程是什么》），我们要钻进一个进程的内部，看看它怎么"分身"出多个线程，同时干好几件事——比如一边下载、一边还能让你点按钮。今天先把"程序 vs 进程"这块地基踩实，我们下一讲见。
