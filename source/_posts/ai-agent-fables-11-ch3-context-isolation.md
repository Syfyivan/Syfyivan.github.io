> 承上：上一章阿筹学会了选调度章法，干起来却发现各组的料单图纸混着传，传到后来谁都不知道该看哪份。这一章，老把头教他给每个人划清“该揣什么”。

工地上乱成一团：施工组手里攥着账房的流水、采料组揣着验收的清单，谁的桌上都堆着一堆和自己没关系的纸，越堆越找不到正经那张。

老把头一声令下重新分:“每个组，**只揣自己这摊用得着的那几份**——施工组要图纸和料，不要账本；账房要流水，不要施工细节。别的组的事，你不必知道，也别去掺和。”他又立了交回的规矩:“你们各干各的，干完只把**该上交的那份成果**交给我，中间一堆草稿别全倒给我。”最后他特意叮嘱:“谁要是把外头一张来路不明、夹了私货的纸混进自己这摊，整摊都得遭殃——只收该收的。”

## 概念揭晓

老把头这套“各揣各的”，是多 Agent 里的**上下文隔离（context isolation）**——它既是性能问题，也是安全问题。

“每组只揣自己这摊”，是**子任务边界与信息所有权**：每个 Agent 只拥有完成自己子任务所必需的上下文，不该看的不给。这呼应第三、四讲的窗口预算——每个 Agent 的上下文都小而聚焦，整体才省、才稳。

“干完只交该上交的那份”，是**汇总协议**：Agent 之间传递的是精炼的结果，而不是各自的全部草稿和中间过程。协调者收到的是“结论”，不是“一地鸡毛”。

“别把来路不明、夹私货的纸混进来”，是**防污染与防注入**：一个 Agent 的输出会成为另一个 Agent 的输入，如果中间混入了污染内容或恶意指令（第九讲的间接注入），会在 Agent 之间传播、放大。隔离是阻断这种传播的关键。

## 为什么不能共享一切

新手容易想:“把所有信息给所有 Agent，大家信息对齐，不就好了？”但这会同时引爆三个问题:

- **上下文爆炸**：每个 Agent 都背着全量信息，窗口撑爆、又慢又贵（第三讲）。
- **互相干扰**：无关信息稀释注意力，Agent 更容易跑偏（第四讲“塞满更差”）。
- **污染传播**：一处被污染或注入，会顺着“共享”扩散到全队（第九讲）。

所以多 Agent 的一条核心纪律是:**默认隔离，按需共享**——只把每个 Agent 真正需要的那部分给它。

## 信息所有权

给每个 Agent 划清楚:

- 它的**输入**：完成这件子任务必需的上下文（任务说明、相关资料、它的工具）。
- 它的**产出**：要交回的结果格式（呼应第四、七讲“把输出形状定死”）。
- 它**不该碰**的：其它 Agent 的内部过程、与本任务无关的全局信息、不该有的权限（第九讲最小权限）。

边界清楚，每个 Agent 才能聚焦，整队才不会互相绊倒。

## 汇总协议：传结论，不传一地草稿

Agent 之间该传什么，很有讲究:

- 传**精炼的结论 / 结构化结果**，不传完整的思考过程和所有草稿。
- 协调者（leader）拿到的应是“可直接用的产出”，而不是要它再去消化一堆原始材料。
- 这既省上下文，也让交接点清晰、可评测（第八讲：每个 Agent 的产出可单独验收）。

把它想成公司里的汇报:你给上级交的是结论和建议，不是把你电脑里所有文件都拷给他。

## 隔离也是安全边界

这点尤其重要,把第九讲接了进来:

- 一个处理“不可信外部内容”的 Agent（比如读网页、读用户上传），应被隔离、低权限，它的输出在进入其它 Agent 前要被当成数据而非指令对待。
- 这样即使它被间接注入，污染也被挡在它那一摊，不会借“共享上下文”扩散到有权限的 Agent。

隔离让“被攻破一个”不等于“全队沦陷”——这正是第九讲“纵深防御”在多 Agent 里的落地。

## 常见误区

第一，图省事让所有 Agent 共享全部上下文。爆窗口、互干扰、污染扩散三连。

第二，Agent 之间互传一大堆原始草稿，而不是精炼结论。

第三，不把“读不可信内容的 Agent”隔离低权，一处被注入就全队遭殃。

## 小练习

一个“调研并写报告”的多 Agent 流程：检索 Agent 读外部网页、写作 Agent 整合、审查 Agent 把关。

1. 每个 Agent 该拥有哪些上下文？哪些不该给？
2. 它们之间该传“结论”还是“全部草稿”？
3. 哪个 Agent 最该被隔离、低权限？为什么？
