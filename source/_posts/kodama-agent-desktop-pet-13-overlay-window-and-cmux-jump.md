第 12 篇解决了「桌宠在别人全屏时消失」。紧接着冒出三个新问题，都很具体：

1. 桌宠**拖不到屏幕边缘**，拖到一半就卡住，没法贴边角。
2. 气泡卡片在屏幕边上**被裁掉一截**（右边的「忽略」按钮看不全）。
3. 点气泡里的「打开 Claude Code 终端」，有时**新开一个 cmux**，而不是跳回我正在用的那个会话。

这一篇讲这三个怎么修的。其中有一个 bug 把我骗得以为「代码写坏了」，其实是另一回事——也一起写出来，因为那个教训比 bug 本身值钱。

## 一、桌宠为什么拖不到边、气泡为什么被裁

### 先理解原来的窗口模型

桌宠是用 Electron 做的。最直觉的做法是：开一个**刚好包住桌宠的小窗口**（比如 280×400），桌宠画在窗口里，拖桌宠 = 拖这个小窗口。

这个模型有两个隐藏问题：

- **拖不到边**：小窗口被「保持在屏幕内」的逻辑钳住了（不然窗口跑出屏幕就找不到了）。所以桌宠（在窗口中心）永远差一截到不了屏幕真正的边缘。
- **气泡被裁**：气泡是画在这个小窗口里的 DOM。窗口只有 280 宽，气泡卡片本身就有 300 多宽，**超出窗口的部分会被操作系统按窗口边界裁掉**。气泡想往桌宠旁边摆，但桌宠贴边时窗口没有多余空间，气泡就被挤出去、被切。

一句话：**小窗口同时限制了「桌宠能去哪」和「气泡能摆多大」。**

### 改成「全屏覆盖层」

正确的做法（几乎所有带气泡的桌宠都这么干）是反过来：

> 开一个**铺满整个屏幕工作区**的、**透明的、点击穿透的**大窗口。桌宠不是「窗口」，而是画在这个大窗口**内部某个坐标**的一个图像。

这样：

- 桌宠想去哪就去哪——它在一张「和屏幕一样大的透明画布」上移动，自然能贴任何边角。
- 气泡有**整屏**的空间可摆，永远不会被窗口边界裁掉；它还能根据桌宠的位置自动翻到左上/右下等可见的一侧。

几个关键词解释一下：

- **透明（transparent）**：窗口背景完全透明，你只看得到画在上面的桌宠和气泡，看不到窗口本身。所以一个「铺满屏幕」的窗口不会挡住你的桌面。
- **点击穿透（click-through）**：这是重点。一个铺满屏幕的窗口，如果会拦截鼠标，那你整个桌面就点不动了——灾难。所以默认让窗口「鼠标穿透」（`setIgnoreMouseEvents(true, { forward: true })`），鼠标事件直接穿过去点到桌面上真正的东西。只有当鼠标**移到桌宠或气泡上方**时，才临时关掉穿透、让它们可点。`forward: true` 的意思是「即使在穿透状态，也把鼠标移动事件转发给我」，这样我才能知道鼠标什么时候移到了桌宠上。

### 实现要点

把这套落地，改了三处：

1. **窗口创建**：尺寸从「小窗口」改成「主屏工作区大小」，`movable: false`（窗口本身不动了）。
2. **桌宠定位**：新增 `petX / petY` 两个坐标（存在本地设置里），桌宠按这个坐标画在覆盖层内；拖拽时改的是 `petX/petY`，并 clamp 到 `[0, 屏宽-桌宠宽]`，所以能一路贴到边。
3. **「大小」改成缩放**：以前「大小」是改窗口尺寸，现在窗口固定铺满屏幕了，所以「大小」改成**缩放桌宠图像**（一个 scale 值），托盘菜单的「很小/小/中/大」推一个 scale 给渲染层。

有意思的是：改完发现，代码里那套「气泡自动选边、按屏幕坐标算可见区域」的逻辑，**本来就是按大窗口/覆盖层写的**——只是之前窗口被建得太小，把这套逻辑废掉了。所以这次重构与其说是「加功能」，不如说是「让窗口和代码的假设对齐」。这也提醒我：**架构假设要前后一致，半套模型最难调。**

### 一个安全底线

铺满屏幕的透明窗口有个可怕的失败模式：**万一点击穿透失效，整个屏幕就点不动了**。所以我保证窗口创建后**第一件事就是开启穿透**，最坏情况也只是桌宠那一小块有问题，而不是整屏锁死。这种「失败也要失败得安全」的兜底，做系统级悬浮窗时一定要有。

## 二、让「打开终端」精准跳回 cmux 会话

### 原来为什么会新开一个 cmux

点「打开 Claude Code 终端」，代码原来的逻辑是：

1. 在进程列表里找到那个 `claude`/`codex` 进程，拿到它的 **tty**（终端设备号）。
2. 用 AppleScript 让**「终端 App」**切到那个 tty 对应的标签页。

问题：那段 AppleScript 是写死给 macOS 自带的 **Terminal.app** 的。而我用的是 **cmux**（另一个终端）。脚本对 cmux 不生效 → 代码退而求其次，直接 `open /Applications/cmux.app`——这只是把 cmux 整个唤到前台，**不会跳到具体那个会话**，看起来就像「又开了一个 cmux」。

更糟的是，很多时候**连 tty 都拿不到**（后面讲），那就更只能盲目打开 App。

### 发现 cmux 自带「遥控 CLI」

翻了下 cmux 的安装包，发现它自带一个命令行工具：`cmux`（在 `cmux.app/Contents/Resources/bin/cmux`），可以通过 Unix socket 遥控 cmux。里面有一堆命令，关键的几个：

- `cmux tree --all`：打印出**完整的窗口/工作区/面板/标签结构**，而且**每个终端都标了 `tty=ttysNNN`**。
- `cmux select-workspace --workspace <ref>`：切到某个工作区。
- `cmux focus-window` / `cmux focus-pane`：聚焦窗口 / 面板。

这就好办了。**tty 就是我手里的会话和 cmux 里的终端之间的「连接键」**：

1. 跑 `cmux tree --all`，解析出「哪个 tty 在哪个工作区/面板」。
2. 用会话的 tty 去匹配，找到对应的工作区。
3. `select-workspace` + `focus-pane` 精确跳过去，再把 cmux 唤到前台。

不再是「打开 App」，而是「跳到这一个会话」。

### 那个把我骗惨的点：tty 经常是空的

修到一半发现：很多本地 Claude Code 会话，**根本拿不到 tty**，所以上面的匹配直接落空。

原因是：原代码靠「进程命令行里包含 sessionId」来找进程。但 **Claude Code 的进程参数里压根没有 sessionId**（它的会话是按文件存的，不在命令行上）。找不到进程 → 拿不到 tty → 跳转失败。

解法是换一个「连接键」：**工作目录（cwd）**。会话信息里带了 cwd。我枚举所有 `claude`/`codex` 进程，用 `lsof` 查每个进程的当前工作目录，和会话的 cwd 比对，匹配上就拿到它的 tty。

```text
找进程的两条路：
1) 进程命令行里有 sessionId   → 直接命中（Codex 等）
2) 否则：按 cwd 用 lsof 匹配  → 兜底（Claude Code 走这条）
拿到 tty 后 → 在 cmux tree 里按 tty 找工作区 → select-workspace 跳过去
```

这下「打开终端」就能稳稳跳回正在用的那个会话了。

## 三、那个让我以为「panel 改坏了」的坑：窗口在，但什么都没画

这是本篇最值钱的教训。

做覆盖层重构、加全屏 panel 的时候，桌宠**连普通桌面都看不见了**。我第一反应是「我刚加的窗口改动把渲染搞坏了」，差点回退。

但根因完全在别处。背景是：我前阵子把桌宠和它的飞书桥接器合并成了一个 **monorepo**，桌宠代码从老目录搬到了新目录。搬家用的是 `git subtree`，而 **git 只搬「被追踪」的文件，不搬被 `.gitignore` 忽略的文件**。

桌宠的 Live2D 渲染素材（引擎 `pixi.min.js`、`cubism core`，以及模型文件）因为有版权、体积大，一直是 gitignore、不入库的。于是新目录里：**代码在、素材不在**。窗口照样创建成功、健康检查接口照样返回「窗口就绪」，但渲染层找不到模型，画了个**全透明的空窗口**——看起来就和「桌宠消失了」一模一样。

把素材目录从老仓拷过去，桌宠立刻回来了。

这个坑留下三条通用教训：

1. **「看不见」不等于「崩了」。** 进程活着、窗口在、接口 OK，但内容是空的——这是一类很隐蔽的故障，排查时别被「进程没死」误导。
2. **git / git subtree 不会带走 gitignore 的文件。** 任何「下载来的、不入库的运行时资源」，换仓库、换目录时都要单独处理。
3. **健康检查要查「对用户有意义的状态」。** 「窗口对象建好了」是开发者视角；「模型真的画出来了」才是用户视角。两者要分开报，否则接口会骗你。

## 小结

这一轮三件事，其实是一类问题的不同侧面：**桌宠这种东西，一直在和操作系统的窗口管理器、和别的 App（终端、全屏应用）打交道**，而不是在自己的浏览器盒子里排版。

- 想贴边、气泡不被裁 → 把窗口从「贴身小窗」换成「全屏透明穿透覆盖层」。
- 想精准跳回会话 → 找到目标 App（cmux）的遥控能力，用 tty/cwd 当连接键。
- 想不被假象误导 → 记住「看不见 ≠ 崩了」，健康检查要查到「真的画出来了」。
