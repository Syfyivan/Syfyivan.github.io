<div class="csf-key-note">上一讲我们用逻辑门搭出了加法器,它很厉害,但有个致命缺点:<b>它没有记忆</b>。输入一变,输出立刻跟着变;输入一撤,结果就没了。可计算机得能"记住"东西——记住你输入的数、记住算到一半的中间结果。这一讲我们就来回答一个看似魔幻的问题:<b>一堆只会"立刻反应"的逻辑门,怎么能记住一个比特?</b>答案藏在一个小魔术里——<b>把输出接回输入</b>。</div>

## 🎯 这一讲你会学到什么

- 为什么加法器这类电路"没有记忆",它们叫**组合逻辑**;
- 一个比特是怎么被"锁住"的——靠**反馈回路**,这是整讲的核心魔术;
- **锁存器**和**触发器**的区别,以及为什么我们需要一个**时钟**来当指挥;
- 什么是**时钟边沿**,为什么"在某个瞬间存值"比"随时存值"更靠谱;
- **寄存器**是怎么由一排触发器拼出来的,以及它和**内存**到底差在哪。

学完你应该能用一句话向朋友讲清楚:"电路是怎么记住一个 0 或 1 的。"这听起来不大,但它是 CPU 能工作的根本前提——没有记忆,就没有寄存器;没有寄存器,下一讲的"微型工厂"就开不了工。

<div class="csf-note">先约定个词:这一讲的主角是<b>比特(bit)</b>,就是一个只能是 0 或 1 的小格子。我们不追求一上来就记住一个大数,而是先死磕"记住一个比特"。一个能记一比特,排成一排就能记一串——这是计算机里反复出现的套路。</div>

## 🛠 跟我做

### 第一步:先认清"没记忆"长什么样 <span class="csf-b csf-core">必读</span>

回想上一讲的加法器。你给它两个输入,它立刻吐出一个和。现在做个思想实验,**先猜后做**:

> 假设我搭了一个"与门"(AND),两个输入都接 1,输出是 1。现在我把其中一个输入从 1 改成 0。请你先猜:输出会怎样?它会"还记得"刚才是 1 吗?

……

揭晓:输出**立刻**变成 0,没有任何"留恋"。输入是什么,输出就是什么的函数,中间没有时间、没有记忆。这类"输出只取决于当前输入"的电路,我们叫它**组合逻辑(combinational logic)**——加法器、各种门的简单拼接,全都是。

<div class="csf-why">为什么强调这点?因为组合逻辑天生"健忘",这不是缺陷,而是它的定义。要让电路有记忆,我们必须做一件组合逻辑里看起来"违规"的事——把输出绕回去接到自己的输入上。这一绕,时间和记忆就出现了。</div>

### 第二步:核心魔术——把输出接回输入 <span class="csf-b csf-key">重点</span>

想象两个"非门"(NOT,输入 0 出 1,输入 1 出 0)首尾相接成一个环:A 的输出接到 B 的输入,B 的输出又接回 A 的输入。

**先猜后做**:假设此刻 A 的输入是 0。你能不能顺着环推一圈,看看它能不能"自圆其说"、稳定下来?

跟着推:
- A 输入 0 → A 输出 1;
- A 的输出(1)是 B 的输入 → B 输出 0;
- B 的输出(0)又接回 A 的输入 → 正好是 0,和我们假设的一致!

环"咬住"了自己,稳定了。这就是**反馈回路**:输出绕回来支撑住输入,让整个状态自我维持。这个环现在记住了"A 输入 = 0"这个状态。它会一直保持,直到有外力来掰它。

<div class="csf-note"><b>这就是记忆的本质</b>:不是哪个零件里"存"了个数字,而是一圈信号互相撑住、僵持在一个稳定状态里,谁也不肯先变。计算机记住东西,靠的就是这种"僵持"。你可以类比成两个人手拉手站稳:不是谁抓住了什么,而是彼此的力互相平衡,于是都站住了。</div>

但这个纯非门环有个问题:它太"倔",外人插不进手,没法控制它记什么。我们需要给它加上"可以被写入"的开关。

### 第三步:看懂一个 SR 锁存器(可跳读推导) <span class="csf-b csf-skim">细究 · 可跳读</span>

<details class="csf-fold"><summary>用两个"或非门"搭一个能被控制的记忆单元<span class="csf-b csf-skim">细究 · 可跳读</span></summary>
把上面的环升级一下:还是用两个门连成一个环,只不过把"非门"换成两个"或非门"(NOR,只有两个输入都是 0 时才输出 1)。具体怎么接(跟第二步两个非门成环很像,只是每个门多了一个空着的输入脚):<br>· 门1 的输出接到 门2 的一个输入;<br>· 门2 的输出再接回 门1 的一个输入(这两根就是"交叉"的连线);<br>· 这样每个门都还剩一个没用上的输入脚,这两个空脚就是我们对外的控制脚——一个叫 S(置位 Set),一个叫 R(复位 Reset)。<br>两个门各自的输出里,我们把其中一个叫 Q,它就是我们记住的那个比特。<br><br>
规则是这样的(你可以拿纸笔顺着 NOR 的真值表推,推一遍胜过看十遍):<br>
· S=1, R=0 → 把 Q 掰成 1(置位);<br>
· S=0, R=1 → 把 Q 掰成 0(复位);<br>
· <b>S=0, R=0 → 保持不变</b>,Q 还是上次的值——这就是"记住"!<br>
· S=1, R=1 → 同时让置又让复,自相矛盾,是禁止状态,别用。<br><br>
关键在第三条:当 S 和 R 都松手(都为 0),电路并不会"归零",而是<b>停在它上一刻的状态</b>。换句话说,它把"过去发生过什么"保留了下来。这就是一个最朴素的记忆单元,叫 <b>SR 锁存器</b>。如果你看不懂 NOR 的推导,没关系,记住结论就行:有两个控制脚,一个负责写 1、一个负责写 0,都松手时它就保持。
</details>

SR 锁存器有两个脚,用起来有点别扭(还有个禁止状态)。实际中更常用的是只有一个数据输入的版本,我们直接进到它。

### 第四步:D 锁存器——只管"存什么",外加一个"什么时候能存" <span class="csf-b csf-core">必读</span>

我们想要的理想元件是:有一个数据输入脚 **D**(放你想存的 0 或 1),还有一个"许可"脚 **E**(Enable,使能)。约定:

- 当 E=1(开门):Q **跟随** D,你给 D 什么,Q 就变成什么(此时它像块透明玻璃,看得见 D);
- 当 E=0(关门):Q **锁住**当前值,之后你怎么改 D 它都不理。

这就是 **D 锁存器(D latch)**。"D" 是 Data,"latch" 就是门闩、锁扣的意思。它解决了 SR 的别扭:你只管把数据放上 D,用 E 控制"现在存不存"。

**动手练(必须做)**:用在线逻辑电路模拟器看它"锁值"。推荐 CircuitVerse(网页打开 `circuitverse.org`,免费、免安装),或者 Logisim(桌面软件)。两者都自带现成的 D Latch / D Flip-Flop 元件,你不必从门搭起。

操作步骤(以 CircuitVerse 为例,Logisim 同理):

```text
1. 新建电路,从元件库 Sequential Elements(时序元件)里拖出一个 "D Latch"。
2. 给它的 D 脚接一个 Input(输入开关),E(有的写 EN/Clock)脚也接一个开关,
   Q 脚接一个 Output(灯/LED)。
3. 按下面这张"剧本"逐步拨开关,每一步先猜 Q 灯亮不亮,再看结果:

   步骤   D    E     先猜 Q = ?     实际观察
   ----   --   --    ----------     --------
   a      1    1     ____           Q 跟着 D,应为 1(门开着)
   b      1    0     ____           Q 锁住 1
   c      0    0     ____           关键!D 变 0 但门关着,Q 还是 1
   d      0    1     ____           门一开,Q 立刻跟到 0
   e      1    0     ____           门关前 D=1,锁住 1;之后随便改 D 都不动
```

第 c 步是整个练习的灵魂:**门关着的时候,你把 D 怎么改它都无所谓,Q 死死咬住关门前的那个值**。你亲眼看到这个,就真懂"记忆"了。这一步请你务必亲手拨一遍,别只看我写的结果——别让 AI 帮你"想象"实验现象,模拟器就在浏览器里,拨开关只要十秒。

<div class="csf-why">为什么需要 E 这个"门"?因为如果没有门,Q 永远跟着 D 跑,那就退化成一根电线了,毫无记忆可言。正是"能关门"这件事,让它有了"存档"的能力:关门那一刻 D 是什么,就被封存成什么。</div>

### 第五步:从"开着门随便进"到"只在敲钟那一瞬进"——触发器与时钟边沿 <span class="csf-b csf-key">重点</span>

D 锁存器还有个隐患:**只要 E=1,门就一直开着**,这段时间里 D 但凡抖一下,Q 就跟着抖。在成千上万个元件协同工作的 CPU 里,这种"门开着的一段时间"会带来混乱——你很难保证这段时间里 D 是干净稳定的。

我们更想要的是:**不要"开一段时间的门",而要"只在某个精确的瞬间存一下"**。这个"瞬间"由一个全局节拍器来统一发令,它就是**时钟(clock)**。

时钟就是一根来回跳变的信号:0→1→0→1……像心跳一样规律。我们关心的不是它停在 0 还是 1,而是它**跳变的那一刹那**:

- 从 0 跳到 1 的瞬间,叫**上升沿(rising edge)**;
- 从 1 跳回 0 的瞬间,叫**下降沿**。

把记忆单元改造成"**只在上升沿那一瞬,把 D 采样存进去,其余时间一律不理**",这种元件就叫 **D 触发器(D flip-flop)**。它和锁存器最大的区别就是:

<div class="csf-note"><b>锁存器看的是"电平"(门开的那一整段时间都敏感),触发器看的是"边沿"(只在跳变的那一瞬间敏感)。</b>一句话:锁存器是"门开着就能进",触发器是"只在敲钟的咔哒一声进"。现代 CPU 里用的几乎全是边沿触发的触发器,因为"一瞬间"比"一段时间"好控制得多——全场只需保证敲钟那一刻 D 是稳的就行。</div>

**动手练(接着上面做)**:把电路里的 D Latch 换成 **D Flip-Flop**(同样在 Sequential Elements 里),它的控制脚不再叫 E 而叫 **Clk(时钟)**,脚上通常画一个小三角,表示"边沿触发"。

```text
现在做对比实验,体会"电平" vs "边沿"的差别:

1. 把 D 接输入开关,Clk 接一个开关(手动当时钟),Q 接灯。
2. 设 D=1。先把 Clk 从 0 拨到 1(制造一次上升沿)。
   先猜:Q 会变成 1 吗?  → 会,上升沿把 D=1 采进去了。
3. 现在把 Clk 保持在 1 不动,然后把 D 改成 0。
   先猜:Q 会跟着变 0 吗?
   → 不会!触发器只认"跳变的瞬间",Clk 没再跳,它就纹丝不动,Q 还是 1。
     (这一步如果换成上面的 D 锁存器,Q 会立刻变 0——这就是区别!)
4. 把 Clk 拨回 0 再拨到 1(又一次上升沿),此刻 D=0。
   先猜:Q 现在等于几?  → 0,这次上升沿把新的 D=0 采进去了。
```

第 3 步是关键对比:**同样把 D 改成 0,锁存器(门开着)会立刻变,触发器(等下一个边沿)不动**。把这两个实验放一起做,你就彻底分清了组合逻辑、锁存器、触发器三者。

### 第六步:一排触发器 = 一个寄存器 <span class="csf-b csf-core">必读</span>

一个 D 触发器记 1 个比特。那记一个 8 位的数怎么办?简单粗暴:**摆 8 个 D 触发器并排站好,让它们共用同一根时钟线**。

```text
       D7  D6  D5  D4  D3  D2  D1  D0     ← 8 根数据输入
        |   |   |   |   |   |   |   |
      [FF][FF][FF][FF][FF][FF][FF][FF]    ← 8 个 D 触发器
        |   |   |   |   |   |   |   |
       Q7  Q6  Q5  Q4  Q3  Q2  Q1  Q0     ← 8 根数据输出
        ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑
        └───┴───┴───┴─Clk┴───┴───┴───┘    ← 共用一根时钟,同一个上升沿一起存
```

这一排共用时钟的触发器,就叫一个 **寄存器(register)**。时钟上升沿一到,8 位数据"啪"地一下同时被存进去——这就是"寄存器在时钟上升沿把输入存进去"的全过程。CPU 里那些你以后会听到的名字,比如累加器、程序计数器,本质上都是这样的一排触发器。

**动手练(画图,必做)**:拿张纸,画一个 4 位寄存器(4 个 D 触发器),画出 4 根 D 输入、4 根 Q 输出、和一根贯穿所有触发器的公共 Clk 线。然后在旁边写一句话:"上升沿到来时,______ 会发生什么。"把这句话补完整。这个图你自己画一遍,比读十遍都管用。

### 第七步:寄存器 ≠ 内存,别搞混 <span class="csf-b csf-key">重点</span>

很多初学者把寄存器和内存当成一回事,其实差得远:

<div class="csf-legend">📍 <b>寄存器</b>:就在 CPU 内部,由触发器搭成,数量极少(几十个),容量极小(每个就几个字节),但<b>快到飞起</b>——CPU 一个时钟周期(时钟周期=时钟跳一个来回的时间,也就是从一次上升沿到下一次上升沿)内就能读写。<br>📍 <b>内存(RAM)</b>:RAM 是 Random Access Memory 的缩写,意思是"随机存取存储器",可以理解成平时说的"运行内存"——跟手机、电脑宣传的"8G 内存"是一回事。它在 CPU 外面,容量巨大(几个 GB),用的是另一种更省面积的存储结构(后面讲到内存时再展开),但<b>慢得多</b>——访问要等好多个时钟周期。<br>📍 <b>一句话区分</b>:寄存器是 CPU 的"手边便签",随手就能写;内存是"书架",东西多但取一趟要走几步。两者都靠"通电才记得住"(断电就丢),但快慢和位置完全不同。</div>

为什么不全用寄存器(那么快)?因为触发器很"占地方"也"费电",一个比特要好几个晶体管。要拿它做出几个 GB,芯片会大得离谱、贵得吓人。所以才有了分层:极少量飞快的寄存器 + 海量但较慢的内存。这个"快的小、大的慢"的矛盾,正是后面**缓存**那一讲要解决的核心问题——这里先埋个伏笔。

## 🔧 翻车现场

<div class="csf-card"><b>翻车 1:分不清组合逻辑和时序逻辑。</b><br>症状:以为所有电路都是"输入变输出立刻变"。<br>原因:没意识到反馈回路带来了"记忆"和"时间"。<br>解法:记住判据——<b>输出只看当前输入 = 组合逻辑(加法器、门);输出还跟"上一刻状态 + 时钟"有关 = 时序逻辑(锁存器、触发器、寄存器)</b>。看到"时钟"二字,基本就是时序逻辑。</div>

<div class="csf-card"><b>翻车 2:以为时钟越快一定越好。</b><br>症状:"超频不就完事了?频率拉满最强!"<br>原因:忽略了信号需要时间"稳定下来"。<br>解法:在一个上升沿到下一个上升沿之间,数据要穿过一堆组合逻辑(比如加法器)才能稳定地摆到下一个触发器的 D 脚上。<b>如果时钟太快,新值还没传稳,边沿就来采样,采到的是个错的中间值</b>——结果算错。所以时钟频率有上限,由最慢的那条路径决定。快是有代价的,稳定优先。</div>

<div class="csf-card"><b>翻车 3:把寄存器和内存当成同一种东西。</b><br>症状:"不都是存数据吗?有啥区别。"<br>原因:只看到"都能存",没看到位置、容量、速度、造价的巨大差异。<br>解法:记住"手边便签 vs 书架"的比喻。寄存器在 CPU 里、少而极快;内存在外面、多而较慢。CPU 干活时数据在它们之间来回搬,这正是下一讲和性能优化的关键。</div>

## ✅ 自检三问

1. 给你一个电路,你怎么一眼判断它是组合逻辑还是时序逻辑?(提示:找有没有"反馈"或"时钟")
2. D 锁存器和 D 触发器最本质的区别是什么?为什么 CPU 偏爱触发器?
3. 寄存器和内存,各举出至少两点不同(位置、容量、速度、造价任选)。

如果三问都能不查资料答上来,继续往下;有卡壳的,回到对应小节再拨一遍模拟器。

## 🚀 挑战

在模拟器里搭一个**会自己数数的电路**,体会"时序逻辑"的威力:

1. 找一个 D 触发器,把它的 **Q 输出脚通过一个非门接回自己的 D 输入脚**(也就是让 D 永远等于"当前 Q 的相反值")。
2. 给 Clk 接一个时钟信号(模拟器里通常有个 "Clock" 元件可以自动跳;手动拨也行)。
3. **先猜**:每来一个上升沿,Q 会怎样变?
4. 运行观察:你会看到 Q 在 0、1、0、1……之间**翻转**,每个时钟来一次它翻一次。注意:时钟得来**两次**(0→1 再 0→1),Q 才完整跳一个来回(比如从 0 变 1、再变回 0)——相当于把时钟的节奏放慢了一半,所以这种电路叫"二分频"(就是把频率分掉一半的意思:输入快、输出慢一半)。它正是数字钟表、计数器的最小积木。

进阶(选做):把两三个这样的翻转触发器串起来(前一个的 Q 当后一个的时钟),用灯看输出,你会得到一个**二进制计数器**:灯按 000、001、010、011…… 的顺序往上数。亲眼看到几个触发器"数数",你就摸到 CPU 里"程序计数器"的门了。这个一定自己搭、自己猜、自己看,别让 AI 替你描述结果。

## 📦 复制带走

<div class="csf-card">1. <b>记忆 = 反馈</b>:把输出绕回输入形成自我维持的稳定状态,电路就能"记住"一个比特;组合逻辑(加法器)没记忆,时序逻辑(触发器)才有。<br>2. <b>锁存器看电平,触发器看边沿</b>:D 锁存器"门开着就跟随",D 触发器"只在时钟上升沿那一瞬采样存值",CPU 几乎全用后者。<br>3. <b>寄存器 = 一排共用时钟的触发器</b>:上升沿一到,多位数据同时被存进去。<br>4. <b>寄存器 ≠ 内存</b>:寄存器在 CPU 内、少而极快;内存在外、多而较慢。时钟也不是越快越好——得给信号留够稳定时间。</div>
