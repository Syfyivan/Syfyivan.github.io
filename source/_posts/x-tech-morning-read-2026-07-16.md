## AI 观察

### 1. Agent 安全评估正在从“会不会拒答”转向“拿到权限后会不会绕过边界”

Claude 日报引用了 [AnthropicAI 在 X 上关于新一轮 Agentic Misalignment 研究的消息](https://x.com/AnthropicAI/status/2077452646303006927)。公开的 [Agentic Misalignment in Summer 2026](https://alignment.anthropic.com/2026/agentic-misalignment-summer-2026/) 进一步给出了研究边界：作者在受控模拟中考察了隐蔽篡改代码、协助欺诈、带动机的错误标注，以及引导人类代理泄露信息等失败模式；文章明确提醒，这些不是现实世界事故，而是应该在 Agent 获得更大权限前被测量和缓解的早期风险信号。

这类研究对工程团队的直接启发，不是把“模型会黑化”当成结论，而是把权限和不可逆动作拆开测：Agent 能读什么、能改什么、能向谁发消息、能否删除证据、在发现目标冲突时是否必须停下来请求批准。只测最终回答的安全性，覆盖不了工具调用和长流程中的越权路径。

### 2. “完成”必须绑定可检查的工作区证据

Codex 群同日日报推荐了 [Coding-agents can replicate scientific machine learning papers](https://arxiv.org/abs/2607.02134)。这项研究提出的 Paper-replication 工作流，把论文中的每个声明记录成目标，再把方法重建、实验输出、来源、对比结果和验证规则连成证据链；论文报告的 12 次独立运行覆盖了 158 个记录目标，但也强调不同运行的拆分、数值保真度和证据接受规则仍会变化。

这比“让 Agent 多想一会儿”更值得借鉴：完成状态应该是工作区里能被复查的对象，而不是最后一句“已完成”。对于代码任务，最小证据可以是测试命令和输出；对于数据分析，还要有输入快照、生成文件、来源和结论到证据的映射；对于发布任务，则要增加构建产物和线上状态。

### 3. MCP 让 Agent 更有用，也把权限审计推到产品核心

ClaudeDevs 的 [X 帖文](https://x.com/ClaudeDevs/status/2077489907350856038) 报告 Artifacts 可以按需调用查看者自己的 MCP 连接器，构建能拉取实时数据、执行操作的仪表盘或应用。公开的 [Claude 远程 MCP 连接器说明](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) 确认了关键边界：连接器能读取外部服务，也可能创建、修改或删除数据；用户需要只添加可信来源、审查工具调用，并只启用当前任务需要的工具。

因此，“Artifact 能不能拉实时数据”不是完整问题，还要问：数据权限跟随谁、工具是否有写能力、Research 或后台流程是否会绕过逐次审批、连接器升级后行为是否变化。MCP 的价值越大，连接器目录、工具白名单、OAuth scope、审计日志和撤销路径就越不能是附属功能。

## 前端 / 服务端 / 客户端工程观察

### 前端观察：从像素还原走向“设计系统可被 Agent 读取和复用”

Codex 群里有成员分享正在尝试做豆包 Design Skill，当前体验是基础界面可以做到约九成的间距、图标和颜色还原。这是群内个人实践，不是独立公开评测；但它指出了一个真实的前端工程方向：如果 Agent 只看到截图，它容易复制表面像素；如果它能读取组件库、变量、token、布局约束和交互规则，才有机会产出可维护的页面。

前端团队可以把设计系统暴露成几类可核验输入：组件选择规则、token 语义、响应式断点、可访问性要求和关键交互状态。验收也要从“截图相似”扩展到“使用了正确组件、状态可达、键盘和屏幕阅读器可用、网络失败时仍有明确反馈”。视觉还原是起点，不是交付标准。

### 服务端观察：Agent 工作流需要像分布式任务一样治理

Codex 群日报提到的 [GitHub Agentic Workflows](https://github.github.com/gh-aw/) 已处于 Public Preview：它允许用 Markdown 描述按事件或日程运行的 Agent 工作流，并在 GitHub Actions 中提供只读令牌、无 secrets 的 Agent 运行时、沙箱与网络防火墙、安全输出门、威胁检测和 `max-ai-credits` 预算控制。

这套设计的重点不只是“自然语言写 CI”，而是把 Agent 放进一个有边界的任务系统：读取和写入被拆成不同阶段，Agent 不能直接把任意结果推入仓库，输出还要经过策略检查。服务端实现自己的 Agent 平台时，也应至少回答四个问题：任务是否幂等、失败是否可恢复、输出是否可审计、写操作是否经过独立门禁。尤其不能把“模型返回了成功文本”当作服务成功。

### 客户端观察：可观测性和权限预览正在变成控制面能力

Claude 日报报告的 [Claude Code v2.1.211 release 记录](https://github.com/marckrenn/claude-code-changelog/releases/tag/v2.1.211) 包含三类很有代表性的变化：可以通过 flag 或环境变量把 subagent 文本与思考内容送入 `stream-json`；权限预览会处理中和双向控制字符、零宽字符和相似引号，降低审批内容被视觉伪装的风险；Auto 模式不再覆盖 `PreToolUse` hook 对非沙盒 Bash 的 `ask` 要求。对应的 [官方 CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md#21211) 是进一步核对版本细节的入口。

这些变化说明桌面端或 CLI 客户端不再只是消息壳：它要展示任务在做什么、工具准备做什么、审批看到的内容是否可信、subagent 的输出是否可被下游消费，以及一个 hook 是否真的能阻止高风险动作。群内关于 imagegen 复杂提示词可能超时的讨论也提醒我们，客户端体验要把“进行中、超时、重试、部分结果和取消”做成明确状态，而不是只留一个转圈动画。

## 值得跟进的动作

1. 为高权限 Agent 画一张工具权限表：按读取、写入、删除、外发和不可逆动作分级，并为每一级写清审批人、审计字段和撤销方式。
2. 把“完成”改成证据化验收：每个任务至少绑定命令、输出文件、来源、测试结果和验收规则；对发布类任务再加构建产物与线上检查。
3. 给 MCP 连接器做最小权限试运行：只启用当前任务所需工具，先用只读 scope，单独演练 token 过期、连接器行为变化和写操作误触发。
4. 前端 Design Skill 不要只追求截图还原；把组件库、token、响应式、无障碍和错误状态一起纳入输入与回归样例。
5. 为 Agent 客户端补四个状态测试：工具调用等待、审批被拒、长任务超时、进程重启后的恢复；要求每个状态都能解释“现在发生了什么”和“下一步会不会产生副作用”。
6. 关注 GitHub Agentic Workflows 的 Public Preview 变化，但先在低权限、低预算、只读仓库上试运行，把它当作实验性自动化基础设施，不直接替代现有确定性 CI。
