## 一、故事正文

入门第三日，青萝学得正起劲。她在卷宗房抄完一份软件缺陷清单，心里盘算：「我只要把手上这份活干到最好，宗门的软件质量自然就高了。」她甚至有些得意，觉得质量这件事，归根结底是看谁手艺硬。

长老听她这么说，没有点头，也没有摇头，只把她带出卷宗房，登上山门后的望气台。台上能俯瞰整座灵枢宗：东边是炼器堂在出软件产品，南边是会审殿里执律师姐正带人做软件评审，西边的库房管着各炉丹药的灵材来源，北边的钟楼按时敲钟、记录每一炉的成败。青萝第一次发现，原来一炉丹药从立项到交付，要穿过这么多殿堂。

「你说你一个人把活干好，宗门质量就高。」长老指着下面，「那我问你——库房灵材若不可追溯，你炼得再好，能算高质量吗？会审殿若不把关，缺陷漏到山下，能算高质量吗？钟楼若不记录、不复盘，下一炉还会犯同样的错，能算高质量吗？」青萝答不上来。

长老说：「这就是**系统工程学**的思想。灵枢宗不是一间炼器房，而是由许多子系统构成的整体。质量不靠一人之力，而靠**软件质量工程体系**。」他在台上的石板写下体系建立的次第：先**确定顾客和其他相关方的需求和期望**，再**建立质量方针和质量目标**，然后**确定过程和职责**、**提供资源**、**规定测量方法**、**用测量确定有效性和效率**、**确定防止不合格的措施**，最后**建立持续改进的过程**。「你看，从需求到改进，是一条闭环。」

青萝顺着长老的手指看下去。她注意到，会审殿门口立着两块牌子：一块写「**质量控制**」，意思是设定标准、测量结果、判定是否达标、对问题补救并防止再发生；一块写「**质量保证**」，意思是为让产品充分满足要求而做的有计划有组织的活动，目的是「提供对满足质量要求的**信任**」。执律师姐在两块牌子之间穿梭，一会儿做面向各阶段的**复审**，一会儿做检查内部是否守规矩的**内审**。

「那这些殿堂归谁管？」青萝问。长老指向最高处的祖师堂：「在**质量控制**、**质量保证**和**质量改进**之上，是**质量方针**——由组织的最高管理者正式发布、形成文件的质量宗旨与方向。方针在上指挥，**质量管理**居中协调，控制、保证、改进各司其职。」他顿了顿，「而改进本身也有章法，叫 **IDEAL 模型**，也有人用**六西格玛**。一座宗门若能让每个环节都不断改进，一百万次出炉里，瑕疵也不过三四个。」

青萝望着脚下层层叠叠的殿堂，忽然觉得自己手上那份缺陷清单，只是这张大网里的一个结。质量原来是立体的。

## 三、概念正解

### 3.1 系统工程学思想与体系建立

**系统工程学**是为了研究多个子系统构成的整体系统所具有的多种不同目标的相互协调，以期系统功能的最优化、最大限度地发挥系统组成部分的能力而发展起来的一门科学。落到软件上，就是要把**软件质量管理作为一个系统来管理**，运用系统科学的方法，通过有关质量的各种信息反馈与调控，对软件质量进行全面、综合的系统性管理，包括软件质量的**计划、组织、协调、控制**，以实现软件质量目标。

**建立和实施质量管理体系的方法**（按课件顺序，常考填空/简答）：

1. 确定顾客和其他相关方的需求和期望；
2. 建立组织的质量方针和质量目标；
3. 确定实现质量目标必需的过程和职责；
4. 确定和提供实现质量目标必需的资源；
5. 规定测量每个过程的有效性和效率的方法；
6. 应用这些测量方法确定每个过程的有效性和效率；
7. 确定防止不合格并消除产生原因的措施；
8. 建立和应用持续改进质量管理体系的过程。

口诀：**需求 → 方针目标 → 过程职责 → 资源 → 测量方法 → 测量执行 → 纠正措施 → 持续改进**，是一条闭环。

### 3.2 软件质量指标 vs 软件质量因素

这是本章最易混的一对，务必分清。

**软件质量指标**：衡量那些**可识别的软件质量特性**的项目，有助于对软件质量进行度量，利用软件工程方法来达到特定的质量目标。软件有**六个品质要素**（六个指标维度）：

| 品质要素 | 课件定义 |
| --- | --- |
| 正确性 | 实现的功能达到设计规范，并满足用户需求的程度 |
| 可靠性 | 规定的时间和条件下，仍能维持其性能水准的程度 |
| 易用性 | 用户掌握软件操作所要付出的时间及努力程度 |
| 效率 | 软件执行某项功能所需电脑资源（含时间）的有效程度 |
| 可维护性 | 当环境改变或软件发生错误时，执行修改或恢复所做努力的程度 |
| 可移植性 | 从一个系统/环境移到另一系统/环境的容易程度 |

每个要素下还细分若干**具体质量指标**，例如功能性下有功能正确性、准确性、完整性；可用性下有可操作性、通用性、一致性；可靠性下有自我恢复能力、健壮性、分布性；可维护性下有简单性、自我描述性、模块化、可测试性、可追溯性等；可移植性下有独立性、可重用性、互操作性等。

**软件质量因素**：**影响软件质量特性或影响软件指标的参数**。注意定义里的关键词是「**影响……的参数**」——因素是「因」，指标是「果」。质量因素分两类：

- **软件产品的质量因素**：与产品本身特性相关的参数。
- **软件过程的质量因素**：贯穿在各过程中的参数，包括项目计划过程（如与客户的沟通能力、评审流程范围方式、文档规范）、项目设计过程（指标定义、设计标准、文档规范）、项目实施过程（变更控制、缺陷处理流程）、软件维护过程（变更控制、用户反馈、回归测试）、软件商业环境过程（改进策略、产品开发模式、市场定位）。

一句话区分：**指标是被衡量的「质量特性」，因素是去影响这些特性的「参数」**。

### 3.3 软件质量模型

建立质量模型，是为了**描述质量因素与质量指标之间的关系**，分析因素究竟如何影响指标，从而寻求最优的质量保证方案。三个经典模型：

| 模型 | 年代 / 别名 | 要点 |
| --- | --- | --- |
| **McCall 模型** | 1977，GE 模型 | 由 **11 个指标**构成，分为**产品操作、产品修订、产品转移**三类 |
| **Boehm 模型** | 1978 | 基于很多特性和标准，层次更细 |
| **ISO 简化模型** | —— | 包括 6 个质量目标，每个目标下有很多属性 |

**ISO 简化模型**（按 ISO/TC97/SC7/WG3/1985-1-30/N382）由 **3 层**组成：

- 高层 = **软件质量需求评价准则（SQRC）**
- 中层 = **软件质量设计评价准则（SQDC）**
- 低层 = **软件质量度量评价准则（SQMC）**

ISO 认为，应对**高层和中层建立国际标准**在国际范围内推广，**低层可由各使用单位视实际情况制定**。ISO 的三层模型来自 McCall 等人的模型：高层、中层、低层分别对应 McCall 模型中的**特性、度量准则、度量**。

**模型评价与分析**：三者**存在差别**（特性、因素或指标的定义不完全一致），但**思想接近**（总体要表达的思想非常接近），**目的相同**（都是质量因素、准则、度量三者综合的结构模型）。区别在于：**ISO 模型第一层（质量特性）和第二层（准则）的关系非常清楚，不像 McCall 模型和 Boehm 模型那样存在交叉关系**。

### 3.4 软件质量工作层次

层次自上而下：**质量方针 > 质量管理（含质量控制、质量保证、质量改进）**。

- **质量方针**：在质量控制、质量保证和质量管理之上。由组织的**最高管理者正式发布**、该组织的质量宗旨、目标和质量方向，并**形成文件**；是企业经营总方针的组成部分，是管理者对质量的指导思想和承诺，为组织提供关注的焦点，在质量管理体系中起关键作用。
- **质量管理**：在质量方针指导下，指挥和控制组织的质量活动，协调各项工作，**包括质量控制、质量保证和质量改进**。
- **质量控制**：一个**设定标准（根据质量要求）、测量结果、判定是否达到预期要求、对质量问题采取措施补救并防止再发生**的过程。已不再仅仅是检验，而更倾向于确保产品满足用户要求的**过程控制**。
- **质量保证**：为保护产品和服务充分满足消费者要求的质量而进行的**有计划有组织的活动**，致力于**提供对满足质量要求的信任**。按对象分**内部质量保证**（向自己的管理者提供信任）和**外部质量保证**（向外部客户或其他方提供信任）；按活动分**复审**（在生命周期每个阶段结束前，用结束标准对该阶段软件配置成分进行严格技术审查）和**内审**（检查组织内部是否遵守已有的模板、规则、流程）。
- **质量改进**：致力于**增强满足质量要求的能力，是一个持续过程**。常用模型有 **IDEAL 模型、六西格玛模型、PDCA 模型、PEIS 模型、CMM 模型、SPICE 模型**等。

**IDEAL 模型**五阶段（首字母对应）：

| 阶段 | 含义 |
| --- | --- |
| Initiating 初始化 | 为成功地改进质量工作奠定基础 |
| Diagnosing 诊断 | 确定现状与质量目标之间的差距 |
| Establishing 建立 | 计划如何达到质量目标 |
| Acting 行动 | 根据计划开展质量工作 |
| Learning 学习 | 从经验中学习，以提高将来采用新技术的能力 |

**六西格玛模型**：六西格玛在统计学中称为标准差，用来表示数据的分散程度。达到 **6 西格玛**的程度，就几近于完美地达成顾客要求——**在一百万个机会里，只找得出 3、4 个瑕疵**。其改进流程为 **DMAIC**：

| 步骤 | 含义 |
| --- | --- |
| 界定（Define） | 确定需要改进的目标及其进度；界定前需辨析并绘制出流程 |
| 测量（Measure） | 以灵活有效的衡量标准测量现存系统与数据，了解现有质量水平 |
| 分析（Analyze） | 用统计学工具分析整个系统，找到影响质量的少数几个关键因素 |
| 改进（Improve） | 运用项目管理等工具，针对关键因素确立最佳改进方案 |
| 控制（Control） | 监控新的系统流程，采取措施维持改进结果，使流程充分发挥功效 |

### 3.5 软件质量成本

**质量成本**是为确保和保证满意的质量而发生的费用，以及没有达到满意质量所造成损失的总和。核心公式：

> **质量成本 = 保证成本 + 损失成本**
> **保证成本 = 预防成本 + 评价成本**

- **预防成本**：预防产生质量问题（软件缺陷）的费用，是企业的计划性支出，专门确保各环节不出现失误。
- **评价成本**：在交付和服务环节，为评定软件产品或服务是否符合质量要求而进行的试验、软件测试和质量评估等支出。
- **损失成本**：分内部与外部——**内部损失成本**指软件发布之前发现质量问题，要求重做、修改、问题分析带来的成本；**外部损失成本**指产品售出后因质量问题产生的一切损失和费用。

**引入质量成本的意义**：把质量与企业经济效益直接联系起来，质量得以**货币语言**表达，从务虚概念转为务实概念，更易树立质量至上的理念。

两个易混的「劣质成本」概念：

- **PONC（Price of Nonconformance）**：「不符合要求的代价」，指由于缺乏质量造成的人力、财力、物力及时间成本的浪费。是「**零缺陷**」质量管理中引入的重要概念。
- **COPQ（Cost of Poor Quality）**：「不良成本」，指所有由过程、产品和服务中的质量缺陷引起的费用。是「**6 西格玛**」质量管理中的重要概念。

**劣质成本的分类**：故障成本（外部/内部故障成本、返工返修纠正等补救成本）、过程成本（非增值成本、低效率过程成本、机会损失成本）、损失成本（顾客损失成本、信誉损失成本）。关键数字：**软件劣质成本竟高达 46%--80%**。

### 3.6 标准体系与三类度量

**软件质量标准体系空间**：纵向分为**产品和过程质量管理标准**；横向分为**通用和各行业质量标准**；范围分为**国际和国内标准**。标准体系层次：**原理标准**（描述各原理级的关键组织标准）、**要素标准**（原理标准中各要素的详细性能要求，必须执行）、**指南和补充**（如何把原理或要素标准应用于特定场合的指导性文件）。

**软件质量度量的地位**分三类：

- **项目质量度量**：度量项目特征和执行质量状态，含资源使用效率、项目性能、项目风险等。
- **产品质量度量**：度量产品特性和质量属性，含功能、复杂性、设计特征、性能和可靠性等。
- **过程质量度量**：度量开发和维护的改进过程，含某时刻的状态（时间切面）、历史数据分析和未来变化预测等。

## 五、考点卡

- **判断题抓手**：
  - 「软件质量靠一个人把活干好就能保证。」错。质量靠**软件质量工程体系**（系统工程思想），不靠一人之力。
  - 「质量指标和质量因素是一回事。」错。指标是被衡量的**质量特性**，因素是**影响质量特性或指标的参数**。
  - 「质量保证就是检验产品合不合格。」错。质量保证是有计划有组织的活动，致力于**提供对满足质量要求的信任**；「检验/补救」更偏向质量控制。
  - 「ISO 简化模型的三层是 SQRC、SQDC、SQMC。」对。
  - 「保证成本 = 预防成本 + 评价成本。」对。

- **选择题抓手**：
  - 看到「11 个指标 / 产品操作、产品修订、产品转移 / 1977 / GE 模型」→ **McCall 模型**。
  - 看到「1978 / 特性和标准很多 / 层次细」→ **Boehm 模型**。
  - 看到「SQRC / SQDC / SQMC / 三层」→ **ISO 简化模型**。
  - 看到「界定、测量、分析、改进、控制 / 百万机会 3~4 个瑕疵」→ **六西格玛 DMAIC**。
  - 看到「初始化、诊断、建立、行动、学习」→ **IDEAL 模型**。
  - 看到「零缺陷」→ **PONC**；看到「6 西格玛 + 劣质成本」→ **COPQ**。

- **填空题抓手**：
  - 质量成本 = **保证成本** + **损失成本**；保证成本 = **预防成本** + **评价成本**。
  - 质量保证致力于提供对满足质量要求的 **信任**。
  - McCall 模型由 **11** 个指标构成，分为产品操作、产品修订、产品转移。
  - 软件劣质成本竟高达 **46%--80%**。
  - 软件质量因素是影响软件质量特性或影响软件指标的 **参数**。

- **简答题答题骨架**（如「简述建立质量管理体系的方法」）：按八步——①确定需求期望 ②建立方针目标 ③确定过程职责 ④提供资源 ⑤规定测量方法 ⑥执行测量评有效性 ⑦确定纠正措施 ⑧建立持续改进。

- **设计题答题骨架**（如「为某团队设计质量改进方案」）：①选模型（IDEAL 或六西格玛 DMAIC）②按阶段展开（如 DMAIC：界定目标并画流程 → 测量现状 → 分析关键因素 → 改进方案 → 控制维持）③结合质量成本说明收益（降低劣质成本/PONC/COPQ）。

## 六、小试炼

**题 1（判断）**：质量控制和质量保证是同一个概念。
参考答案：错。**质量控制**是设标准、测结果、判定、补救并防再发的过程（偏过程控制）；**质量保证**是有计划有组织的活动，致力于**提供满足质量要求的信任**，分内部和外部。为什么：二者目的不同，一个保达标，一个保信任。

**题 2（选择）**：以下哪个模型由 11 个指标构成，分为产品操作、产品修订、产品转移？
A. Boehm 模型　B. McCall 模型　C. ISO 简化模型　D. IDEAL 模型
参考答案：B。为什么：11 指标 + 三分类 + 1977/GE 是 McCall 模型的标志特征。

**题 3（填空）**：质量成本 = ______ + 损失成本，其中保证成本 = 预防成本 + ______。
参考答案：保证成本；评价成本。为什么：课件公式原文，常考。

**题 4（简答）**：简述六西格玛的 DMAIC 五步及其含义。
参考答案：**界定**（确定改进目标与进度，先画流程）、**测量**（衡量现存系统与数据，了解现有质量水平）、**分析**（用统计工具找影响质量的少数关键因素）、**改进**（针对关键因素确立最佳方案）、**控制**（监控新流程、维持改进结果）。补充：达 6 西格玛时百万机会仅 3~4 个瑕疵。

**题 5（设计）**：某软件团队缺陷反复出现、返工严重，请用一种质量改进模型给出改进思路。
参考答案要点：选 **IDEAL 模型**——①**初始化**：为改进奠定基础、争取支持；②**诊断**：测量现状，确定与质量目标的差距（如缺陷密度、返工率）；③**建立**：制定达到目标的计划；④**行动**：按计划开展（建立变更控制、回归测试、复审/内审等）；⑤**学习**：复盘、沉淀经验提升将来能力。最后用**质量成本**衡量：通过加大**预防成本**降低**损失成本/劣质成本（PONC/COPQ）**，整体质量成本下降。

## 七、易错点

- 把**质量指标**和**质量因素**混为一谈。记住：指标=被衡量的质量特性（六品质要素），因素=影响指标的参数（分产品/过程）。
- 把**质量控制**和**质量保证**搞反。控制偏「设标准、测、判、补救」；保证偏「有计划有组织、提供信任」，且分内部/外部、复审/内审。
- 记错模型归属：**IDEAL = 改进模型**（初始化/诊断/建立/行动/学习）；**DMAIC = 六西格玛**（界定/测量/分析/改进/控制）。两套五步别串。
- 混淆 **PONC 与 COPQ**：PONC 属「零缺陷」管理，COPQ 属「6 西格玛」管理；二者中文都译「劣质成本」，但出处不同。
- 漏掉关键数字：McCall **11** 个指标、六西格玛百万机会 **3~4** 个瑕疵、软件劣质成本 **46%--80%**。
- 答「建立质量管理体系方法」时步骤乱序或漏项。务必从**需求**起、到**持续改进**收，闭环八步。
- 只背故事忘了术语。答题必须落到「系统工程学、质量方针、质量控制、质量保证、质量改进、SQRC/SQDC/SQMC」等课件原词。
