## 一、故事正文

青萝把自己炼制的第一件灵器交上去会审时，脸上是藏不住的得意。执律师姐拿起来翻看，问她：“质量如何？”青萝脱口而出：“我觉得不错。”

师姐没接话，把灵器放回案上，反问：“‘不错’是多少？比上一炉好几成？缺陷少几个？你拿什么证明给委托人看？”青萝愣住了。她忽然意识到，在灵枢宗，判断软件质量从来不许凭感觉——必须用**测量**、**度量**、**指标**说话。

执律师姐取来一把刻度卡尺，又在墙上挂了一张箭靶，叫青萝过来上一课。“先说一件最容易被忽略的事，”师姐说，“量得**准**和量得**稳**，是两回事。”她拿卡尺去量一段灵纹的宽度，连量五次，五次读数几乎一模一样——这叫**可靠性**高，同一方法多次测量值很一致。“可是，”师姐话锋一转，“如果这把卡尺本身刻度就偏了一丝，那你量五次都一样地错。稳，不代表准。”

她又指向箭靶。第一组箭，密密地扎在靶心左下角一小块——“这就是**可靠但不有效**：每次都射同一处，稳得很，可全偏了。”第二组箭，散布在靶心四周，平均下来居中，单看哪一支都没中红心——“这是**有效但不可靠**：平均没错，可你信不过任何单独一次。”第三组箭，又密又准，全扎在靶心——“这才是又**可靠**又**有效**。”

青萝盯着箭靶，半晌说：“所以我说‘我觉得不错’，连卡尺都没拿，更别说准不准、稳不稳了。”

师姐点头，把课件摊开：“**测量**，是对产品或过程的某个属性的范围、数量、维度、容量或大小，提供一个定量指示；**度量**，是对软件产品进行范围广泛的测度，给出系统、构件或过程某个给定属性的定量测量；**指标**，是一个或一组度量的组合，用易于理解的形式，对过程、项目或产品质量提供更全面深入的评价。”她顿了顿，“记住顺序：先有测量，攒成度量，再合成指标。一件灵器好不好，要落到**缺陷密度**、**缺陷清除率**、**圈复杂度**这些数上，而不是落到‘我觉得’三个字上。”

青萝把卡尺和箭靶都画进了卷宗里。她现在懂了：这一境修的不是炼器手艺，是**怎么把‘好’这件事量出来**。

## 三、概念正解

### 3.1 三个基本概念：测量、度量、指标

| 概念 | 课件定义 |
| --- | --- |
| **测量** | 对产品或过程的某个属性的**范围、数量、维度、容量或大小**提供一个**定量的指示** |
| **度量** | 对软件产品进行范围广泛的测度，给出一个系统、构件或过程某个**给定属性**的**定量测量** |
| **指标** | 一个**度量或一组度量的组合**，采用易于理解的形式，对软件过程、项目或产品质量提供更全面、深入的评价 |

记忆链：**测量 → 度量 → 指标**，由点到面、由单项到综合。

### 3.2 四种度量尺度

| 尺度 | 含义 | 是否有绝对零 | 例子 |
| --- | --- | --- | --- |
| **分类尺度** | 把指标分成一系列类别 | — | 质量属性分为功能性、可靠性、可维护性等 |
| **序列尺度** | 在分类基础上再排序 | — | 用 1、2、3 表示满意度，1 最低 3 最高 |
| **间隔尺度** | 用数值表示两点之间差异，但**没有绝对“零”值** | 无 | 温度（摄氏） |
| **比值尺度** | 与间隔尺度相似，但**有绝对“零”值** | 有 | 长度、缺陷数 |

口诀：分类只分组、序列能排序、间隔无零点、比值有真零。

### 3.3 测量标准：有效性 vs 可靠性（最重要）

有效性和可靠性是测量标准中**最重要的指标**。

- **有效性**：测量结果**正确反映**被测对象的实际状况和程度，合乎事物发展、变化的规律。（量得**准**）
- **可靠性**：用同样的测量方法对同样的事物**多次测量**，得到值的**一致性**。多次测量值越接近，可靠性越高。（量得**稳**）

打靶比喻（务必记牢三种组合）：

| 打靶表现 | 对应 |
| --- | --- |
| 弹着点密集但整体偏离靶心 | **可靠但不有效**（稳但不准） |
| 弹着点分散但平均居中 | **有效但不可靠**（准但不稳） |
| 弹着点又密又中靶心 | **又可靠又有效**（又稳又准） |

### 3.4 测量过程与基本原则

**测量过程**（按课件顺序）：识别目标和度量描述 → 定义度量过程 → 搜集数据 → 数据分析与反馈 → 过程改进。

**基本测量原则**（要点）：

- 测量基于该领域**正确的理论**，并在定义中确定测度目标；
- 每个测量定义应具有**一致性、客观性、无二义性**；
- 测量在经验和直觉上要有说服力；方法力求**简单、可计算**；
- 测量应被**剪裁**以适应特定产品和过程，尽量使收集和分析**自动化**；
- 用正确的**统计技术**建立内部属性与外部待测特征的关系；
- 测量结果应**可靠**，不因技术问题大幅偏离；
- 测量应建立**反馈机制**。

### 3.5 三类度量：项目 / 产品 / 过程

软件质量度量按研究对象分为三类：

| 类别 | 管什么 | 包含 |
| --- | --- | --- |
| **项目质量度量** | 描述项目特性和执行状态；评估开发过程质量、预测进度工作量，辅助管理者质量控制和项目控制 | 计划有效性、资源使用效率、成本效益、项目风险、进度、生产力 |
| **产品质量度量** | 描述软件产品特征，用于产品评估和决策 | 规模大小、复杂度、设计特征、性能、质量水平 |
| **过程质量度量** | 用于开发、维护过程的优化和改进；形成组织模型、持续改进、提高生产力 | 缺陷移除效率、缺陷到达模式、缺陷修复效率 |

### 3.6 项目度量分类与规模度量方法

**项目度量分类**：进度度量、**风险度量（= 风险发生的概率 × 风险发生后的损失）**、规模度量、复杂度度量、缺陷度量、工作量度量，以及顾客满意度等其他度量。

> 规模度量是工作量度量、进度度量的**基础**，用于估算工作量、编制成本预算、策划进度。

**规模度量方法**：

- **德尔菲法**：专家评估技术，适用于**没有或没有足够历史数据**时；专家水平和对项目的理解是关键。
- **构造性成本模型（COCOMO）**：精确、易用的基于模型的成本估算方法。
- **代码行度量方法**
- **功能点分析法**
- **面向对象软件的对象点方法**

### 3.7 直接度量 vs 间接度量

| 类型 | 例子 |
| --- | --- |
| **直接度量** | 软件缺陷数、缺陷密度、软件性能、所耗资源、投入成本 |
| **间接度量** | 复杂性、客户满意度、功能性、效率、可维护性 |

### 3.8 软件缺陷的度量

- **缺陷密度**——缺陷在**规模**上的分布，如每 **KLOC**（千行代码）或每个功能点的缺陷数。
- **缺陷率**——缺陷在**时间**上的分布，如应用软件 90% 以上缺陷在发布后两年内被发现。
- **整体缺陷清除率** = 软件开发过程中发现的所有缺陷数 / 发现的总缺陷数。
- **阶段性缺陷清除率**——分阶段统计的缺陷清除率。

务必区分：**缺陷密度看规模、缺陷率看时间**。

### 3.9 软件复杂性度量（McCabe 圈复杂度为重点）

复杂性度量可评估系统的可测试性、可靠性、可维护性，提高工作量估计精度，帮助选择更有效的方法。

**McCabe 环形复杂度（圈复杂度）**：对程序拓扑结构复杂性的度量，明确指出任务复杂部分。

计算公式：

- ① **V(G) = D**（D 为**区域数**；计算区域数时应**包括图外部未被围起来的区域**）
- ② **V(G) = E − N + 2**（E 为流图中边的条数，N 为结点数）

**优点**：避免错误倾向；指出极复杂模块（可进一步细化）；度量测试计划、确定测试重点；指导测试过程、指出待测区域；帮助确定测试和维护对象；**与高级语言类型无关**。

**缺点**：局限于二元决策，不能区分不同种类控制流复杂性（如 Loop 与 if-then-else、case 与 if-then-else 无法区分）。

**应用**：圈复杂度指出为确保质量应检测的**最少基本路径数目**。

**建议**：**圈复杂度到 10（建议 ≤10）**，因为高圈复杂度使测试更复杂、增大软件错误概率。圈复杂度度量的是模块中的分支数目，所有开发周期都要使用。

**用途**：作为测试的辅助工具、程序设计和管理指南、网络复杂性度量的一种方法。

**其他复杂性度量方法**：

- **语法构造方法**：根据可执行代码行的操作符和操作数数量计算复杂性；可揭示语法构造与缺陷率关系，如：缺陷率 = 0.15 + 0.23 DO-WHILE + 0.22 SELECT + 0.07 IF-THEN-ELSE。
- **结构度量方法**：Henry 模型 Cp =（扇入 × 扇出）²（扇入=调用外部模块的模块数，扇出=被外部模块调用的次数）；Card/Glass 模型 Ct = St + Dt（St 结构复杂性，Dt 数据复杂性）。

### 3.10 过程度量：共性 / 个性要素

软件过程质量要素分两大类：

- **共性过程质量要素**：与开发过程中**多个**活动阶段都相关，各阶段收集数据、度量方法、评价准则类似。围绕**改善质量、提高生产效率、降低成本**三方面，涉及 **7 个互相关联的要素**：进度、资源和费用、评审、缺陷、开发性能、技术完备性、需求稳定性。
- **个性过程质量要素**：只和当前过程活动相关，与软件开发的 **5 个阶段**（需求、设计、编码、测试、运行和维护）对应：需求规格说明书、设计有效性、代码审查、测试用例和环境、问题和缺陷修复。

典型度量元：阶段缺陷清除率 **DRE = nf1 /（nf2 + nf3）**、缺陷密度 BD = ns / KLOC、评审效率 CE 等。

### 3.11 统计分析与 Pareto 二八规则

**统计分析步骤**：① 收集和分类软件缺陷信息；② 找出每个缺陷的原因；③ 用 **Pareto 规则（二八规则：80% 缺陷主要由 20% 的主要因素造成，20% 缺陷由另外 80% 的次要因素造成）**，分离出这 20% 的主要因素；④ 标出少数主要因素后，较容易纠正引起缺陷的问题。

**错误的根本原因来源**（部分）：说明不完整或错误（IES）、与客户交流不够的误解（MCC）、故意与说明偏离（IDS）、违反编程标准（VPS）、数据表示有错（EDR）、模块接口不一致（IMI）、设计逻辑有错（EDL）、不完整或错误的测试（IET）、文档不准确不完整（IID）、将设计翻译成程序设计语言中的错误（PLT）、人机界面不清晰不一致（HCI）、杂项（MIS）。

## 五、考点卡

- **判断题抓手**：
  - “可靠性高的测量一定有效。”——错。可靠是多次测量一致（稳），有效是正确反映实际（准），可靠不等于有效。
  - “缺陷密度反映缺陷在时间上的分布。”——错。缺陷密度看**规模**（每 KLOC），缺陷率才看**时间**。
  - “比值尺度有绝对零值，间隔尺度没有。”——对。
  - “圈复杂度越高越好。”——错。建议 ≤10，过高使测试更复杂、增大出错概率。
- **选择题抓手**：
  - 看到“范围、数量、维度、容量、定量指示”→ **测量**；看到“一组度量的组合、易于理解”→ **指标**。
  - 看到“有绝对零值”→ **比值尺度**；“无绝对零值”→ **间隔尺度**。
  - 看到“概率 × 损失”→ **风险度量**；“没有足够历史数据、专家评估”→ **德尔菲法**。
  - 看到“V(G)=E−N+2”“区域数”“≤10”“二元决策”→ **McCabe 圈复杂度**。
  - 看到“80% 缺陷由 20% 因素造成”→ **Pareto 二八规则**。
- **填空题抓手**：
  - 测量标准中最重要的两个指标是 ______ 和 ______（有效性、可靠性）。
  - V(G) = ______（E − N + 2）；建议圈复杂度 ≤ ______（10）。
  - 缺陷密度反映缺陷在 ______ 上的分布，缺陷率反映缺陷在 ______ 上的分布（规模、时间）。
  - 软件质量度量按研究对象分为 ______、______、______（项目、产品、过程）。
- **简答题答题骨架**（“简述有效性与可靠性的区别”）：
  1. 有效性 = 结果正确反映被测对象实际（准）；
  2. 可靠性 = 同方法多次测量值的一致性（稳）；
  3. 二者独立：可靠但不有效 / 有效但不可靠 / 又可靠又有效；
  4. 打靶比喻收尾。
- **设计题答题骨架**（给一段流图算圈复杂度）：
  1. 画/确认控制流图，数出结点 N 与边 E；
  2. 用 V(G) = E − N + 2 计算，或数区域数 D（含图外区域）；
  3. 两法结果应一致；
  4. 与建议值 10 比较，判断是否需细化模块、确定测试基本路径数。

## 六、小试炼

**题 1（判断）**：用同一方法多次测量得到值很一致，说明该测量有效性高。
参考答案：错。这说明**可靠性**高（稳），不等于**有效性**高（准）；卡尺本身偏了也能量得一致。

**题 2（选择）**：下列属于“有绝对零值”的度量尺度是？
A. 分类尺度 B. 序列尺度 C. 间隔尺度 D. 比值尺度
参考答案：D。比值尺度与间隔尺度相似，但有绝对“零”值。

**题 3（填空）**：McCabe 圈复杂度公式 V(G) = ______，建议圈复杂度不超过 ______。
参考答案：E − N + 2（或区域数 D）；10。
为什么：高圈复杂度使测试更复杂、增大软件错误产生概率。

**题 4（简答）**：缺陷密度与缺陷率有何区别？
参考答案：缺陷密度是缺陷在**规模**上的分布，如每 KLOC 或每功能点的缺陷数；缺陷率是缺陷在**时间**上的分布，如发布后两年内发现的缺陷比例。一个看规模、一个看时间。

**题 5（设计）**：某控制流图有 9 条边、7 个结点，请计算圈复杂度并判断是否需关注。
参考答案：V(G) = E − N + 2 = 9 − 7 + 2 = 4。4 ≤ 10，复杂度在建议范围内；它同时表示为确保质量应检测的最少基本路径数目为 4。

## 七、易错点

- 把**可靠性**和**有效性**混为一谈：可靠是“稳”（多次一致），有效是“准”（正确反映实际），二者相互独立，别用一个推另一个。
- 把**缺陷密度**和**缺陷率**搞反：密度看规模（每 KLOC），率看时间（发布后多久发现）。
- 把**间隔尺度**和**比值尺度**搞混：区别只在有没有**绝对零值**，比值尺度有、间隔尺度没有。
- 误以为**圈复杂度越高越能体现工作量价值**：恰恰相反，建议 ≤10，高复杂度增大出错与测试难度。
- 只背了打靶故事，答题却不写“有效性、可靠性、测量、度量、指标”等课件原词，得不到分。
- 把**风险度量**只写成“评估风险”，漏掉公式核心：风险 = 概率 × 损失。
