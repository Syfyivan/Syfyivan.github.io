> 承上：第四讲的书记很会查档、答得也可核验，可老书记最后点破：真要它出门办事——开门、动钱、改东西——光会查档不够，得会借工具、还得守规矩。这一讲我们来到一间工具行。新来的学徒阿器要学的第一件事，是别什么都自己硬来。

阿器接了个活儿：量一块地有多大。他蹲下去就想用步子量，老掌柜一把拦住：“你又不是尺子，凭感觉量准吗？”

老掌柜教他一个规矩：自己不会、或不该亲手干的事，就开一张**领用单**——单上写清要哪件工具（卷尺）、怎么用（从这头量到那头）。把单子交到柜台，柜台的人按单去用工具，量完把**结果**（“三丈二尺”）写在回执上递回来。阿器拿着这个准数，再接着算下一步。

“你看，”老掌柜说，“你不必什么都会。你要会的是：判断这一步该借哪件工具、把单子写明白、再用借来的结果往下走。”

## 概念揭晓

这张领用单的来回，就是**工具调用（tool calling，又叫 function calling）**。

模型不亲手执行动作，它做的是“决定要不要用某个工具、用哪个、带什么参数”，产出一张**工具调用单（tool call）**。真正去执行的，是外面的系统（Harness）。执行完，把**工具结果（tool result）**写回消息历史，模型再据此继续。

要让这套跑起来，每件工具得先有一份**工具定义**：它叫什么、干什么、需要哪些参数、参数是什么格式（参数 **schema**）。模型正是照着这份定义，才知道怎么开单、填什么。

一个完整流程：

```text
用户提出任务
模型判断需要工具，产出 tool_call（工具名 + 参数）
Harness 执行该工具
工具结果回到消息历史
模型基于结果继续回答或继续开下一张单
```

## 模型为什么不该亲手干

大模型擅长理解和生成，不擅长精确计算、读实时数据、改真实世界的状态——这些它一“凭印象”就出错（第三讲讲过的幻觉与推理不稳）。

工具调用把分工理清了：**判断和编排交给模型，精确执行交给工具。** 算账用计算器、查实时信息用搜索、读写文件用文件工具。模型负责“什么时候、用哪个、怎么用”，工具负责“把这一步真做对”。这正是从“会说话”走向“会办事”的关键一步。

## 工具定义和参数 schema

模型不会读心，它只能照工具定义来用。一份定义通常包含：

- **名字**：简洁、能体现用途。
- **描述**：这工具干什么、何时该用。
- **参数 schema**：每个参数的名字、类型、是否必填、取值范围（常用 JSON Schema 描述）。

schema 之所以重要，是因为它把“该带什么、什么格式”约束死了，模型照着填，系统也能校验。schema 含糊，模型就容易填错参数、调错工具——这点 05.4 会专门讲“工具契约质量”。

## 单轮、并行、多轮

借工具有三种节奏：

- **单轮**：一个任务、一次调用、一个结果（量一块地）。
- **并行**：同一轮里开多张单，等结果一起回来再比较（同时量三块地）。
- **多轮**：后一步依赖前一步结果（先量地、再据面积算用料、再据用料去采购）。

Deep Research、代码修复、办一桌席（第一讲），骨架都是“多轮”：每拿到一个工具结果，就重新判断下一步开什么单。这条循环正是第六讲 Agent Loop 的核心。

## tool result 怎么回填

工具执行完，结果要写回模型的消息历史，模型才“看得见”。这一步看似琐碎，却很关键：

- 结果要让模型读得懂（结构清楚、必要时带说明）。
- 结果太大要考虑裁剪或引用，别把上下文撑爆（第三、四讲的预算意识）。
- 出错也要回填“为什么错”，模型才好决定重试还是换路。

模型对世界的认知，全靠这些回填的结果。回填得好不好，直接影响它下一步判断得准不准。

## 常见误区

第一，以为“接了工具”模型就什么都能干。工具是它的手脚，但用不用、怎么用，仍取决于模型的判断和工具定义的质量。

第二，让模型亲手做它不擅长的事（算数、查实时）。该交给工具的别让它硬扛。

第三，忽视 tool result 的回填质量。结果含糊或撑爆上下文，后面全乱。

## 小练习

挑一个你想让 AI 帮你办的小事（比如“查一下明天的天气再决定要不要带伞”）：

1. 这件事里，哪一步该交给工具、哪一步该模型自己判断？
2. 这个工具需要哪些参数？格式是什么？
3. 工具返回的结果，怎么写才能让模型据它做下一步？
