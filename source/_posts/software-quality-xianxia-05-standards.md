## 一、故事正文

灵枢宗山门外挂着一块铜牌，上书「过程成熟度·第三阶」。青萝路过时盯着看了许久，忍不住去问长老：「这块牌子是谁给挂的？凭什么有的宗门能挂这种高阶认证，外面各方委托人一看见就敢把大单交过来，而有的宗门干一样的活却没人信？」

长老把她带到藏经阁最深处。那里整面墙都是卷宗，分了几层架子。最高一层贴着「国际」二字，下面依次是「国家」「行业」「企业」「项目」。长老说：「你问的『凭什么』，答案就在这面墙上。行当里有一整套分层的**软件质量标准**——国际标准、国家标准、行业标准、企业规范、项目规范。**ISO** 这样的国际机构定的，全世界参考；**GB** 这样的国家标准，本国通行；**IEEE** 这样的行业组织定的，专管某个业务领域。门外那块『第三阶』的牌子，靠的不是哪位长老的口碑，是按一套公开的模型评出来的。」

青萝又问：「炼器宗、炼丹宗、铸剑宗都能挂这种牌子，软件这行有什么特别？」长老说：「软件特别就特别在——它**不存在明显的生产阶段**。一炉丹药要经过采药、配伍、入炉、出丹，每一步都看得见摸得着；可软件写完了就是写完了，没有像铸剑那样反复捶打的工序，而且软件**不会「耗损」**，不像剑用久了会卷刃。正因如此，**设计阶段的质量活动对最终质量尤其重要**。所以光有通用的 **ISO 9001** 还不够，得有 **ISO 9000-3** 这样专门帮人在软件过程里解释标准的指南。」

「那门外那个『阶』又是怎么评的？」青萝追问。长老在地上画了一道五级的台阶：「这叫 **CMMI**，能力成熟度模型集成。它衡量的不是某个弟子手艺多高，而是整个宗门的**过程能力成熟度**——也就是一个特定过程被明确地**定义、管理、测量、控制并且是有效的程度**。最低的**初始级**，全凭个人，今天这个弟子在就能交活，明天他闭关了活就砸了；往上是**可重复级、已定义级、已管理级**，到最高的**优化级**，过程已经融入正反馈循环，生产率和质量稳步改进。我们宗门现在评在第三阶，就是**已定义级**——过程都编了完整文档，靠评审保证质量。」

青萝看着那五级台阶，忽然明白门外铜牌的分量：它不是说「我们有几个高手」，而是说「就算高手走了，这套过程也照样能交付合格的软件」。这，才是各方委托人敢信任的根据。

## 三、概念正解

### 3.1 标准的层次（五层，按从大到小记）

软件质量标准按制定机构和适用范围分为五个层次：

| 层次 | 制定者 | 适用范围 | 例子 |
| --- | --- | --- | --- |
| **国际标准** | 国际机构 | 供各国参考 | ISO（国际标准化组织） |
| **国家标准** | 政府或国家级机构 | 本国范围 | GB、ANSI、BS、JIS |
| **行业标准** | 行业机构、学术团体、国防机构 | 某个业务领域 | IEEE、GJB、DOD-STD、MIL-S |
| **企业规范** | 大型企业或公司 | 本部门 | IBM 1984 年《程序设计开发指南》 |
| **项目规范** | 组织为具体项目制定 | 该项任务专用 | 某科研生产项目的操作规范 |

记忆口诀：**国际 → 国家 → 行业 → 企业 → 项目**，范围逐层收窄，针对性逐层增强。

### 3.2 ISO 9001 与 ISO 9000-3：软件为什么特殊

- **ISO 9001** 是 **ISO 9000** 簇标准体系之一，即「设计、开发、生产、安装和服务的质量保证模式」，这套标准包含了高效质量保证系统必须体现的 **20 条需求**。**ISO 9001 适用于所有的工程行业**。
- **ISO 9000-3** 是 ISO 指南的子集，在软件过程的使用中**帮助解释 ISO 标准**（即软件组织的实施指南）。

**软件为什么需要专门的 9000-3？** 课件给的原因要背：软件**不存在明显的生产阶段**，故软件的开发、供应和维护过程不同于大多数其它类型的工业产品；比如软件**不会「耗损」**，所以**设计阶段的质量活动对产品最终质量显得尤其重要**。

### 3.3 ISO 9000-3 与 CMM 的区别

二者**都以全面质量管理为理论基础，都针对过程进行描述**，但**设计思路不同，属于两个不同的体系**：

- **ISO 9000-3**：ISO 指南的子集，是**软件组织的实施指南**。
- **CMM**：**专门针对软件设计行业**的、**描述软件过程能力的模型**。

### 3.4 从 CMM 到 CMMI（沿革，记关键年份与机构）

- **1987 年**，卡内基—梅隆大学**软件工程研究所（SEI）**为支持美国国防部对软件承包商能力作客观评价，于 **1991～1993 年**发表了《软件能力成熟度模型》，即 **SW-CMM 1.0 版和 1.1 版**。
- **CMMI** 兼收了 SW-CMM 2.0 版 C 稿草案和 SPA（软件过程评估）中更合理、科学、周密的优点。
- 一句话定性：**CMMI 其实就是 SW-CMM 的修订本**。

### 3.5 CMMI 质量思想与五级成熟度（本讲最核心考点）

**软件过程能力成熟度**：指一个特定过程被明确地**定义、管理、测量、控制并且是有效的程度**。成熟度意味着能力上的增长，并表明一个组织软件过程的丰富性和在项目中运用它时的一致性。

| 级别 | 名称 | 课件定义（要点） |
| --- | --- | --- |
| 1 级 | **初始级** | 基本上**没有健全的软件工程管理制度**，全凭个人。 |
| 2 级 | **可重复级** | 有些基本的项目管理行为，设计和管理技术基于**相似产品中的经验**，故称「可重复」。 |
| 3 级 | **已定义级** | 已为软件生产过程编制了**完整的文档**，管理和技术方面都明确定义，按需不断改进过程，并**采用评审的办法保证软件质量**。 |
| 4 级 | **已管理级** | 对每个项目都设定**质量和生产目标**，这两个量被不断**测量**，偏离目标太多时采取行动修正。 |
| 5 级 | **优化级** | 目标是**连续地改进**软件过程，使用**统计质量和过程控制技术**作指导，知识运用于以后项目，使软件过程融入**正反馈循环**。 |

口诀：**初（始）可（重复）定（义）管（理）优（化）**。

### 3.6 关键过程域 KPA

**除第一级外**，CMMI 的每一级都包含若干**关键过程域（KPA）**，指出企业需要集中力量改进的软件过程，并指明达到该成熟度等级所需解决的具体问题。每个 KPA 明确列出一个或多个**目标**，并指明一组实现该目标所允许做的**关键实践活动**；实施这些关键实践活动就能实现该 KPA 的目标，从而增加过程能力。

### 3.7 CMMI 内容分级（三个级别 + 两个核心构件）

CMMI 内容分为 **「必需的」「期望的」「提供信息的」三个级别**，衡量模型包括的质量重要性和作用：

- **「必需的」级别——构件是「目标」**：是模型和过程改进的**基础**。目标代表过程改进想达到的最终状态。一个目标对应一个 KPA 称**特定目标**，对应整个 KPA 称**公用目标**。整个 CMMI 模型包括 **54 个特定目标**，每个 KPA 对应 **1～4 个**特定目标。
- **「期望的」级别——构件是「方法」**：在过程改进中起主要作用，但某些情况不是必须的。方法代表达到目标的实践手段。一个方法对一个目标唯一就是**特定方法**，适用于所有目标就是**公用方法**。CMMI 包括 **186 个特定方法**，每个目标有 **2～7 个**方法对应。
- **「提供信息的」级别**：构成模型主要部分，为过程改进提供有用指导。包括：目的、介绍性说明、引用、名字、方法与目标关系表、注释、典型工作产品、子实践、学科扩充以及公用方法的详尽描述。

### 3.8 IEEE 软件工程标准（务必区分各编号）

| 标准号 | 主题 | 要点 |
| --- | --- | --- |
| **IEEE 730** | 软件质量保证计划 | 结构与内容，共分**十七个部分** |
| **IEEE/EIA 12207** | 软件生命周期过程 | —— |
| **IEEE 1012** | **验证与确认** | 见下方「验证 vs 确认」 |
| **IEEE 1028** | 评审 | 评审是对软件元素或项目状态的一种**评估手段**，以确定其是否与计划结果保持一致，并使其得到改进 |

**验证（Verification）**：用来评价某一系统或某一组件的过程，**判断给定阶段的产品是否满足该阶段开始时施加的条件**。（口语化记忆：are we building the product right——做得对不对，对照阶段输入条件。）确认则是面向用户真实需求的评价。这是判断/选择高频混淆点。

### 3.9 ISO/IEC 15504 与 TickIT

- **ISO/IEC TR 15504《软件过程评估》**：在 SW-CMM 思路启发下，ISO/IEC JTC1 于 1991 年启动 SPA 国际标准化项目，**1995 年**发布。其中 **15504-2** 确定过程评估要求构成完整结构；**15504-3** 规定执行评估要求的最小集合；**15504-4** 为过程评估提供框架，可用于组织对采办、供应、开发运行等的计划、管理、监督、控制和改进。
- **TickIT**：主要目的是鼓励软件开发商和采购商考虑——软件开发过程中质量的真正含义、如何实施和实现质量、如何制定并持续改进质量管理体系。主要要求：发布指南帮助软件组织解释 **ISO 9001** 的要求；培训、选择和注册具备 IT 经验的审核员；建立并保持软件行业认证机构的认可规定。

### 3.10 CMMI 量化管理（第四级，MEAN / UCL / LCL）

**CMMI 第四级（已管理级）**的软件组织会根据已收集的缺陷数据，建立**软件过程能力基线**。过程能力基线包括：

- **期望（MEAN）**：描述未来项目缺陷密度的**预期值**；
- **能力上限（UCL）** 与 **能力下限（LCL）**：描述未来项目缺陷密度的**合理变化范围**。

这样的过程能力基线可用来：帮助未来项目设立量化的项目质量目标；理解和控制未来项目的实际结果。

## 五、考点卡

- **判断题抓手**：
  - 「CMMI 第一级也有关键过程域 KPA。」——错，**除第一级外**每级才有 KPA。
  - 「ISO 9001 只适用于软件行业。」——错，**ISO 9001 适用于所有工程行业**，ISO 9000-3 才是软件指南。
  - 「CMMI 是全新模型，与 CMM 无关。」——错，**CMMI 其实就是 SW-CMM 的修订本**。
  - 「软件会随使用而耗损。」——错，软件**不会耗损**，故设计阶段质量尤重要。
- **选择题抓手**：
  - 看到「初始/可重复/已定义/已管理/优化」→ CMMI 五级。
  - 看到「定义、管理、测量、控制并且有效的程度」→ 软件过程能力成熟度的定义。
  - 看到「验证 vs 确认」「IEEE 1012」→ 验证判断给定阶段产品是否满足阶段开始时的条件。
  - 看到「MEAN/UCL/LCL」「过程能力基线」→ CMMI 第四级（已管理级）量化管理。
  - 看到「54 个特定目标 / 186 个特定方法」→ CMMI 内容分级（必需的目标 / 期望的方法）。
- **填空题抓手**：
  - 软件过程能力成熟度是指一个特定过程被明确地 **定义、管理、测量、控制** 并且是 **有效** 的程度。
  - CMMI 内容分为 **必需的、期望的、提供信息的** 三个级别。
  - 过程能力基线包括期望 **MEAN**、能力上限 **UCL**、能力下限 **LCL**。
  - IEEE **1012** 是验证与确认，IEEE **1028** 是评审，IEEE **730** 共分十七个部分。
- **简答题答题骨架**（简述 CMMI 五级）：1. 给成熟度定义（过程被定义/管理/测量/控制并有效的程度）；2. 逐级给名称与一句话定义（初始＝无健全管理制度→可重复＝基于相似产品经验→已定义＝完整文档+评审→已管理＝设质量/生产目标并测量修正→优化＝统计技术+正反馈循环连续改进）；3. 点出除一级外每级含 KPA。
- **设计题答题骨架**（给组织评成熟度/规划改进）：1. 判定当前所处级别（看是否有文档化、可重复、量化目标）；2. 指出该级目标对应的 KPA；3. 列改进的关键实践活动；4. 若冲第四级，说明建立过程能力基线（MEAN/UCL/LCL）。

## 六、小试炼

### 题 1（判断）
ISO 9000-3 和 CMM 属于同一个标准体系，只是名字不同。

参考答案：**错**。二者都以全面质量管理为理论基础、都针对过程描述，但**设计思路不同，属于两个不同的体系**：ISO 9000-3 是软件组织的实施指南，CMM 是专门描述软件过程能力的模型。

### 题 2（选择）
软件过程能力成熟度是指一个特定过程被明确地（　）并且是有效的程度。
A. 编码、测试、部署、上线　B. 定义、管理、测量、控制　C. 计划、设计、实现、验收　D. 需求、分析、开发、维护

参考答案：**B**。这是课件原话，需逐字记。

### 题 3（填空）
CMMI 五级成熟度由低到高依次为：初始级、______、______、______、优化级。

参考答案：**可重复级、已定义级、已管理级**。

### 题 4（简答）
为什么软件需要专门的 ISO 9000-3，而不能只用 ISO 9001？

参考答案要点：ISO 9001 适用于所有工程行业，但软件**不存在明显的生产阶段**，其开发、供应和维护过程不同于大多数其它工业产品；软件**不会「耗损」**，因此**设计阶段的质量活动对产品最终质量尤其重要**。ISO 9000-3 作为 ISO 指南的子集，在软件过程的使用中帮助解释 ISO 标准，是软件组织的实施指南。

### 题 5（设计/简答）
某软件公司每个项目都设定了质量和生产目标，并持续测量这两个量、偏离过多就修正，但还没有用统计技术做连续改进。它处于 CMMI 哪一级？再上一级要做什么？

参考答案：处于**第 4 级已管理级**（设质量/生产目标 + 不断测量 + 偏离修正是其特征；并已可建立过程能力基线 MEAN/UCL/LCL）。再上一级为**第 5 级优化级**，目标是**连续地改进**软件过程，使用**统计质量和过程控制技术**作指导，把各方知识运用于以后项目，使过程融入**正反馈循环**。

## 七、易错点

- 把 **ISO 9001** 和 **ISO 9000-3** 混淆：前者适用所有工程行业（含 20 条需求），后者才是软件实施指南。
- 把 **CMM 与 ISO** 当成同一体系：二者理论基础相同但设计思路不同、分属两个体系。
- 误以为 **CMMI 每级都有 KPA**：是「**除第一级外**」每级才有。
- 把内容分级三构件的对应关系记反：**必需的→目标**、**期望的→方法**、提供信息的→详尽说明。
- 把 **验证（IEEE 1012）** 和评审（IEEE 1028）、确认混为一谈：验证是判断给定阶段产品是否满足该阶段开始时施加的条件。
- 把 **MEAN/UCL/LCL** 安到错的级：它属于**第四级已管理级**的过程能力基线，不是第五级。
- 只背故事不背术语：考试要落到「定义、管理、测量、控制并有效」「初/可/定/管/优」「54 个特定目标、186 个特定方法」等课件关键词。
