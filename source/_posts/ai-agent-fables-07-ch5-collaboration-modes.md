> 承上：上一章阿砖有了图纸和验收单。这一章，他真和施工队（也就是 Agent）配合起来，发现“什么时候放手、什么时候盯紧”大有讲究。

阿砖一开始要么全程盯着施工队的每一锹，累得够呛；要么撒手不管，回来一看砌歪了一面墙。老工头教他分场合换三种站法。

“方向还没定时，”老工头说，“**放手让它快搭几个草样**，你挑哪个顺眼——这时候别较真细节。图纸定了、要认真盖时，**让它照图纸一项项施工，你管节奏和把关**，别由着它自由发挥。每完成一段，**你逐项对验收单查**，过了再让它往下。要是发现砌错了——别在错的上面接着补，**拆掉那段，回到上一个好状态重来**，往往比硬改快。”

“同一个施工队，”老工头说，“你站对位置，它是好帮手；站错位置，它能帮你把活儿干砸。”

## 概念揭晓

老工头教的三种站法加一手“拆了重来”，是和 AI/Agent 协作的几种基本模式。

“放手快搭草样”，是**探索模式**：方向未定时，让 AI 快速生成多个方案供选择，对应 07.1 的 vibe coding，重点是快和多，不纠结细节。

“照图纸一项项施工、你管把关”，是**施工模式**：规格定了之后，让 Agent 按任务执行，你掌控节奏、审查产出，不让它脱离规格自由发挥。

“逐项对验收单查”，是**审查模式**：拿 07.4 的验收单一条条核对它的产出，把“做完了”变成“做对了”。

“拆掉那段、回到上一个好状态重来”，是**回滚（rollback）**：当 Agent 跑偏，恢复到已知良好状态再重来，常比在错误结果上继续修补更省事——这也是为什么版本控制（git，程序员给代码“随时存档、随时读回某个存档点”的工具）在 AI 编程里如此重要。

## 全程盯 vs 全撒手，都不对

和 Agent 协作的两种极端都低效：

- **全程盯**：每一步都要你确认，等于自己干，没发挥它的速度。
- **全撒手**：完全不看，等它跑完，结果常常方向早偏、错误已积累一大堆，返工成本更高。

正确的姿势是**按阶段切换控制力度**：探索时松、施工时中、审查时紧。让人把精力花在“定方向、把关键关、做验收”上，把重复劳动交给 Agent。

## 三种模式各在什么时候用

| 模式 | 何时用 | 你的角色 |
| --- | --- | --- |
| 探索 | 方向未定、找感觉 | 出题、挑方案，不抠细节 |
| 施工 | 规格已定、认真做 | 控节奏、盯着别脱离规格 |
| 审查 | 一段产出完成 | 对验收单逐条核 |

这三种模式常常在一个任务里来回切：先探索定方向 → 写规格 → 施工 → 审查 → 发现要调，再小范围探索……和第六讲 Agent Loop 的“想—做—看”循环是同构的，只是这里多了“人在关键节点把关”。

## 回滚为什么常比硬改强

Agent 跑偏后，新手的本能是“在错的结果上继续让它修”。但错误会叠加：它为了圆上一个错，又引入新的错，越改越乱。

举个能感知的场景：你让 Agent 重构（在不改变功能的前提下重新整理）一个函数，它改完测试挂了；你说“修一下”，它为了让这个测试过又动了三处别的，结果又挂俩。与其在这堆改动上继续纠缠，不如用 git 一键退回重构前那个干净的存档点（一个 commit），把“要始终保持这几个测试通过”写进规格，再让它重来一次——往往十分钟搞定，比硬修半小时还干净。

更稳的做法就是回滚：丢弃这段、回到上一个验证过的良好状态，带着“这次哪没说清”的教训重来。这要求你**频繁保存良好状态**（小步提交、用好 git），让“退回去”随时可行。把回滚当成一等公民，你才敢放手让 Agent 大胆试。

## 谁来对结果负责

模式怎么切、控制力度多大，最终都指向一个原则：**人对交付结果负责，Agent 是强力的执行者，不是责任主体。**

所以关键决策（方向、取舍、上不上线）要人来定，高风险动作要人来批（呼应 05.5），最终验收要人来签。你可以把大量执行交给 Agent，但不能把判断和责任也一起交出去。

## 常见误区

第一，从头到尾只用一种力度——要么累死自己，要么放任跑偏。

第二，发现跑偏了还在错的结果上硬修，不肯回滚。

第三，把判断和责任也甩给 Agent。它执行，你负责。

## 小练习

你让 Agent 帮你重构一个模块，给下面三个时刻各选一种模式（第 4 条额外想一想）：

1. 你还没想好重构成什么样。
2. 方案定了，要它按计划一步步改。
3. 它改完了一个文件，提交之前。
4. 额外想一想：哪个时刻你最该确保“能一键回滚”？
