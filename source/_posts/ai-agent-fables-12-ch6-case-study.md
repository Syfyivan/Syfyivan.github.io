> 承上：上一章阿铺把店规立全了。这一章，老店主带他爬上镇口高台——把这一路学的一摊摊事，用一个真项目串成一条线。这也是整门课的收尾。

高台上望下去，是镇里一处奇景:一座小小的城，城里住着许多小人，各有各的营生——有人摆摊、有人串门、有人记着昨天和谁吵过架、今天绕着走。游人趴在城墙外，能实时看见每个小人此刻在干嘛。

“你看这座小城，”老店主说，“它能转起来，靠的全是你这一路学的。每个小人，是一个会绕圈办事的工匠（第六讲）；它们记得住旧事（第四、六讲的记忆）；后台有人给它们排号、分派、存放各自的状态（这一讲的 runtime）；城墙外的人能实时看到城里的动静，是因为‘里头变了、外头立刻跟着变’。一摊摊单看是零件，合起来，才是一座活城。”

## 概念揭晓

这座“能运转的城”，对应一类很好的收尾案例:**AI Town 这样的 Agent runtime（多智能体小镇 / 运行时）**——它把这门课的诸多概念，落进一个看得见、能跑的系统里。

“每个小人会绕圈办事”，是每个 Agent 各自的 **Agent Loop**（第六讲）。

“记得住旧事、绕着吵过架的人走”，是**长期记忆**（第四讲 04.5、第六讲 Company Brain）:Agent 把经历存下来，影响后续行为。

“后台排号、分派、存状态”，是**运行时与调度**（12.3）:队列、工作流、会话、存储，把许多 Agent 同时跑起来还不乱。

“城外能实时看到城里动静”，是**前端状态同步**:后台 Agent 的状态变化，要实时、可靠地反映到用户界面上（这也是把它做成“产品”而非“脚本”的关键体验，呼应第十讲）。

## 一个案例怎么串起整套工程

把这座小城拆开看，几乎能对上这门课的每一讲:

- 每个居民是**会用工具、会循环**的 Agent（五、六讲）。
- 它们的对话和决策来自**大模型**（三讲），靠**提示与上下文**驱动（四讲），底子是**机器学习**（二讲）。
- 多个居民并发、交互，是**多 Agent 协作**（十一讲）。
- 要稳定运营，需要**runtime、监控、成本治理、团队流程**（本讲）。
- 要让人放心看、放心玩，需要**体验设计与安全**（九、十讲）。
- 而判断它好不好，靠的是**评测**（八讲）。

一个真实项目，从来不是单点技术，而是这十二讲拢到一起的合奏。

## AI Town 这类项目长什么样

AI Town 是一类“多智能体生活模拟”项目:一个虚拟小镇，住着许多由大模型驱动的居民，它们有日程、有记忆、会交谈、会形成关系；用户可以实时围观、甚至参与。

它之所以是绝佳的收尾案例，因为它把抽象概念变成了你能看见的东西:记忆怎么影响行为、多个 Agent 怎么并发调度、运行时怎么承载、状态怎么实时同步到前端。本站另有一门 [AI Town：Agent 基础设施](/courses/ai-town/) 专门拆它的源码，从 runtime、调度、回放到前端渲染——想把这一讲落到代码，可以从那里继续往下钻。

## 从案例回看这门课

这门课的承诺，是“从第一张菜谱，讲到会自己找工具、还能开店经营的系统”。走到这里，回看会发现每一讲都不是孤立的:

- 第一讲教你**分类**:别把规则、模型、生成、Agent 混为一谈。
- 二、三讲讲清**模型怎么来、肚子里有什么、边界在哪**。
- 四、五、六讲，是 Agent 的**三件套**:会查资料、会借工具、会自己绕圈。
- 七讲教你**把灵感变蓝图**，八、九讲教你**验收和守护**。
- 十讲让它**看会听、能动手**，十一讲让一群 Agent **分工成队**。
- 这一讲，把一切**变成能长期运营的产品**。

它们串起来，正是“一个想法 → 一个能可靠办事、还养得活的 AI 系统”的完整路。

## 十二讲，一条主线

如果只带走一句话，那就是这门课从第一讲反复说到最后的那句:

> **能力来源是模型，可靠性来自模型之外的安排。**

模型给了惊人的能力，但要让它可靠地办成事、还不闯祸、还能长期运营——靠的是工具、上下文、评测、安全、协作和运营这一整套“模型之外的安排”。这套安排，就是这门课十二讲的全部内容，也是“AI 工程”区别于“调一次模型”的根本。
