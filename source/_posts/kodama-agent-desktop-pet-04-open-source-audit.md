前面三篇已经把 Kodama 的主链路跑通了：飞书 bridge、本地 Agent hook、事件气泡、会话跳转和 session 分享。

但做到这里还不能说“一个桌宠产品完成了”。因为用户真正拿它当桌宠用时，会自然拿它和成熟桌宠比较：

- 别人的桌宠会不会走路、爬墙、换装？
- 别人的桌宠有没有勿扰模式？
- 别人的桌宠是不是能打包安装、开机自启、自动更新？
- Agent 桌宠能不能看 Claude Code、Codex、Cursor、Gemini？
- 如果隐藏了，它能不能找回来？

所以这一篇不是写某一个功能，而是做一次能力审计：看看开源桌宠生态已经提供了什么，然后决定 Kodama 要追平哪些能力，以及在哪些地方必须做得更多。

## 调研对象

这次主要看了几类项目。

第一类是传统桌宠：

- VPet：开源桌宠模拟器，强调大量交互、动画、食物/物品、Steam Workshop 模组。
- Shimeji / Shijima：经典桌面小人体系，重点是行走、爬墙、掉落、可替换图片集。
- Desktop Goose：更偏恶作剧和干扰型桌面玩具，能拖图片、弹文本、叼鼠标。
- BongoCat / DockCat / 各类小动物桌宠：重点是陪伴感、输入反馈、低打扰。

第二类是新一代 Agent 桌宠：

- Clawd on Desk：像一个多 Agent 状态监控器，能看 Claude Code、Codex、Cursor 等 CLI 的状态，支持权限泡泡、勿扰、声音、主题、安装包。
- AgentPet：关注 agent token、成长、等级和排行榜。
- OpenPets：更像一个桌宠平台，强调插件 SDK、提醒、小游戏、启动器、编码 Agent 集成。
- Agentic Desktop Pet：把 LLM、记忆、情感和 RPG 属性系统都放进桌宠。

调研时我没有只看“它是不是可爱”，而是按功能面拆开：

- 窗口层：透明、置顶、全屏、点击穿透、拖动、位置记忆、多屏。
- 行为层：待机、工作、完成、失败、行走、爬墙、互动。
- 养成层：食物、经验、等级、好感、物品、换装。
- 扩展层：主题包、模组、插件 SDK。
- Agent 层：多 Agent 状态、权限确认、跳转、远端 relay。
- 产品层：安装、开机自启、自动更新、恢复入口、勿扰、声音、系统通知。

## 传统桌宠的共性

传统桌宠最成熟的是“它像一个活物”。

VPet 这类项目会提供大量动画状态和交互。它不是只有 idle 和 done，而是会被摸头、被抱起、工作、进食、休息。Shimeji 系列则更强调“在屏幕上生活”：走路、爬墙、从窗口边缘掉下来，甚至可以出现多个角色。Desktop Goose 的重点更极端：它会主动干扰用户，拖出图片和文本，甚至影响鼠标。

从这些项目里可以学到三点。

第一，桌宠不能只有通知功能。通知功能再强，也只是一个 toast。桌宠要有“平时的生命感”，哪怕只是轻微的 idle、状态变化、点击反馈。

第二，资产和引擎必须分开。Shimeji 的图片集、VPet 的 Workshop、Clawd 的 themes，本质都是让用户能换角色，而不是把逻辑和素材绑死。

第三，默认不能太打扰。Desktop Goose 很有传播性，但它的干扰性不是 Kodama 的方向。Kodama 是工作工具，打断用户的成本很高。任何“拖鼠标”“乱弹窗口”都只能作为可选玩具功能，不能是默认行为。

## Agent 桌宠的共性

Agent 桌宠的核心不是“宠物更可爱”，而是“后台任务变得可见”。

Clawd on Desk 的 README 里非常明确：它会在 AI coding agent 思考、读代码、跑工具、开子 Agent、等待权限、完成任务时显示不同状态。它还支持多种 agent、权限泡泡、全局快捷键、勿扰、声音、托盘、i18n、安装器和自动更新。

AgentPet 走的是成长路线：监控 Claude Code、Codex、Cursor、Gemini 这类 agent，跟踪 token、喂养、升级，甚至做排行榜。

OpenPets 更平台化：它不只做一个宠物，而是把 focus timer、reminder、mini game、launcher、coding-agent sidekick 都抽成插件能力。

Agentic Desktop Pet 则走更激进的一端：LLM、长期记忆、情感系统、RPG 属性、工具调用。这个方向很有想象力，但也更容易把桌宠做成另一个复杂 Agent，而不是一个清晰的状态界面。

这些项目给 Kodama 的启发是：

1. 多 Agent 状态是基本盘。
2. 待确认/失败必须比普通消息更显眼。
3. 勿扰和恢复入口是产品能力，不是锦上添花。
4. 主题、插件、安装器和自动更新决定了它能不能给别人用。
5. 记忆/情感/RPG 可以做，但必须谨慎处理隐私和任务边界。

## Kodama 已经有的优势

Kodama 现在不只是追别人的桌宠。它已经有一个差异点：

> 飞书机器人 + 本地 Agent 共享一只桌宠。

这点是普通 Agent 桌宠没有的。

很多 Agent 桌宠只看本机 CLI：Claude Code、Codex、Cursor、Gemini。Kodama 还接了飞书 bridge。也就是说，同一个用户的“群里机器人任务”和“本地终端任务”可以进入同一条桌宠事件流：

```text
飞书 @机器人
  -> bridge
  -> Codex 执行
  -> 飞书回复
  -> Kodama 气泡 / 面板 / 分享

本地 Claude Code / Codex
  -> hook / notify
  -> Kodama 气泡 / 面板 / 跳转
```

这让 Kodama 更像一个“个人 AI 工作台”的前端，而不是单纯的桌面玩具。

## 当前差距

按能力矩阵看，Kodama 当前已经有：

- 透明置顶窗口。
- 点击穿透和小命中框。
- 拖动、位置记忆、大小调整。
- 飞书事件和本地 Agent 事件。
- 常驻气泡、事件面板、待交互/完成/最近事件分区。
- 会话跳转、悬停摘要、session 分享。
- 养成、token 喂食、等级、配饰。
- 番茄钟、久坐提醒。
- 隐藏/显示、快捷键和本地控制接口。

但还缺这些：

- 成熟的主题包和角色导入。
- 可配置的食物/物品/背包系统。
- 宠物行走、爬墙、抱起、摸头等传统互动。
- 更完整的多 Agent 集成，如 Cursor、Gemini、Copilot、opencode。
- 安全的一键权限 approve/deny。
- 远端 devbox/SSH agent relay。
- 打包安装、开机自启、自动更新。
- 跨平台 QA。
- 可选的长期记忆、情感、RPG 属性。

这不是一两天能全部做完的，但它们可以分层。

## 我给 Kodama 定的路线

第一层是可靠性：

- 隐藏后一定能恢复。
- 全屏里尽量可见。
- 事件不能丢。
- 待交互和失败不能被无声吞掉。
- 桥接器离线时桌宠不能坏。

第二层是桌宠基本盘：

- 主题包。
- 宠物互动。
- 配饰和物品。
- 迷你停靠模式。
- 更细的设置面板。

第三层是 Agent 控制面：

- 多 Agent hooks registry。
- 安装/诊断向导。
- 权限泡泡。
- 会话跳转和分享。
- 远端 relay。

第四层是 Kodama 的独有能力：

- 飞书机器人与本地 Agent 的统一时间线。
- 任务上下文关联。
- 可分享的内网页面。
- 个人工作负载的本地可视化。

## 本轮直接落地的功能

这次审计后，我没有先做“爬墙”或“走路”。原因很简单：当前用户刚刚遇到的是隐藏后找不到桌宠，这比动画丰富度更致命。

所以本轮优先做了三件事：

1. 勿扰模式：事件仍记录和喂养，但不弹气泡、不响、不发系统通知。
2. 声音和系统通知开关：用户可以独立控制。
3. 恢复通道：`⌘⌥K`、`⌘⌥P`、`pnpm run show`、`/pet/show`。

这些能力看起来不像“宠物能力”，但它们是成熟桌面工具必须有的地基。

## 后续文章

下一篇会专门写“勿扰、声音和恢复通道”。

它解决的是一个真实问题：隐藏桌宠本来是为了不打扰，但如果隐藏后用户不知道怎么找回来，这个功能就是危险功能。一个好的桌宠不能只会消失，它必须给用户留一条明确、稳定、可记忆的回家路。
