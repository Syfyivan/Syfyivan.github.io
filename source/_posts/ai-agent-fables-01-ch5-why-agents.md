账房里有个很会说话的先生，写得一手好信，对答如流。可东家让他去办一件事——“把城东那批货的欠款收回来”——他却只会坐在桌前，写一封措辞漂亮的信，然后等着。货没收回来，钱也没到账。

东家叹气，找来一个嘴笨些的学徒。学徒不擅长讲漂亮话，但他会跑：先去库房翻账本（查资料），再跑去城东敲门（调用工具），人不在就改天再去（遇到反馈调整），收到一部分钱就回来报账、再问下一步（多步推进）。一趟办不完就跑两趟、三趟，直到事情真的了结。

东家这才明白：会写信的先生很值钱，但他缺的是腿、是账本、是“没办成就再试一次”的那股劲。把这些补上，先生才从“会说”变成“会办”。

## 概念揭晓

会写信的先生，是**语言模型**：能力很强，但只会产出文本，办不了事。

会跑腿的学徒，是 **Agent**：在模型外面加了三样东西——能调用的**工具**、要完成的**长任务**、以及来自环境的**反馈**，于是它能多步推进，直到任务真正完成。

Agent 这个词很早就有，它最近重新变热，不是因为出了新词，而是因为模型终于强到“能在循环里可靠地决定下一步该干什么”，工具和运行环境也成熟到“能让它真的去干”。这一章讲的就是：**从“会生成答案”到“会完成任务”，到底补上了什么。**

## Agent 比一次问答多了什么

一次普通问答是：你问，模型答，结束。Agent 在这之上多了三件事：

1. **工具使用**：模型可以输出“请调用某工具、带这些参数”，由外部系统执行，再把结果交还给它。它从此能查实时资料、读写文件、运行命令。
2. **长任务**：目标往往一步做不完。Agent 在一个循环里持续推进，每拿到新结果就重新判断下一步。
3. **环境反馈**：工具的返回、报错、文件变化都是反馈。Agent 根据反馈调整，而不是一条道走到黑。

这三件事合起来，才把“会说”变成“会办”。少了任何一件，它要么只会空谈，要么走一步就卡死。

## ReAct：想、做、看的循环

支撑 Agent 的经典思路叫 **ReAct**：把“推理”（Reason）和“行动”（Act）交织起来——先想下一步该做什么，再做（调用工具），再看结果（Observe），然后回到想，如此循环，直到满足停止条件。

学徒收欠款就是一圈圈 ReAct：想“先去库房核账”→做“翻账本”→看“欠 800”→想“去城东要”→做“敲门”→看“人不在”→想“改天再去”……每一圈都用上一圈的结果决定下一步。Deep Research、代码修复、故障排查，骨架都是这个循环。

## 为什么是现在

Agent 概念不新，重新变热靠的是几条线同时到位：

- 模型的**推理和指令遵循**变强，能在循环里做出像样的下一步决策。
- **工具调用**有了结构化接口（function calling、MCP 等），让模型可靠地“开单子”。
- **运行环境**（Harness）成熟：有文件系统、沙箱、权限、上下文管理和停止条件，让循环跑得稳、收得住。

所以 Agent 的复兴，与其说是模型变聪明，不如说是“模型 + 外壳”这套组合终于能办事了。模型是能力来源，外壳决定它能不能被放心地放出去跑——这正是第 06 讲整讲要展开的主题。

## Agent 不是更聪明的模型

这是最该记住的一点。Agent 不等于换了个更强的脑子，而是给同一个脑子配上了腿、账本、工具和“没办成就再来一次”的循环。

因此 Agent 出问题，往往不在模型本身，而在外壳：工具说明写得含糊、没有停止条件导致空转、权限太大造成误伤、上下文搬运不当让它忘了目标。看懂这一点，你排查 Agent 故障时就会先看外壳，而不是一味怪模型笨。

## 小练习

拿一个你想交给 AI 的需求，判断要不要上 Agent：

1. 它是一步能答完的问题，还是需要查资料、调工具、分多步推进？
2. 完成它需要哪些工具？这些工具有没有清楚的“何时用、何时别用”说明？
3. 它该在什么条件下停下来？谁来确认它真的办成了？

如果三问里出现“多步”“要调工具”“要有停止和确认”，这就是一个 Agent 任务，而不只是一次问答。
