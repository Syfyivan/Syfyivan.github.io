> 承上：上一章那位会报菜的厨子很会说，可客人让他真办一桌席，他只会报菜名干等。这一章，师傅动手给后厨配上腿和家伙——跑这趟的，正是小满。

后厨那位会报菜的厨子，菜单写得花团锦簇，对答如流。可东家让他办一件实事——“把城东那桌席给办了”——他却只会坐着把菜名报得漂漂亮亮，然后干等。料没采、火没起、席也没上桌。

师傅叹气，把小满叫来：“他会想菜，你会跑腿，搭一块儿。”于是这桌席这样办起来：先回库房看有什么料（查资料），缺的就去集市采买（动手用工具），买回来尝一口咸淡、不对就回锅调（遇到反馈调整），一道做好上一道、再想下一道（多步推进）。一趟办不齐就跑两趟、三趟，直到整桌席真的上齐。

东家这才明白：会报菜的厨子很值钱，但他缺的是腿、是采买、是“没办成就再来一次”的那股劲。把这些配上，他才从“会报菜”变成“会办席”。小满一边跑一边乐：原来自己不是更聪明了，只是给这张会报菜的嘴配上了手和脚。

## 概念揭晓

只会报菜的厨子，是**语言模型**：能力很强，但只会产出文本，办不了事。

“会报菜的厨子 + 采买、尝味、返工、一道道推进”这一整套，是 **Agent**：在模型外面加了三样东西——能调用的**工具**、要完成的**长任务**、以及来自环境的**反馈**，于是它能多步推进，直到任务真正完成。

Agent 这个词很早就有，它最近重新变热，不是因为出了新词，而是因为模型终于强到“能在循环里可靠地决定下一步该干什么”，工具和运行环境也成熟到“能让它真的去干”。这一章讲的就是：**从“会生成答案”到“会完成任务”，到底补上了什么。**

## Agent 比一次问答多了什么

一次普通问答是：你问，模型答，结束。Agent 在这之上多了三件事：

1. **工具使用**：模型可以输出“请去采买这些料、用这把刀”，由外部系统执行，再把结果交还给它。它从此能查实时资料、读写文件、运行命令。
2. **长任务**：一桌席一步做不完。Agent 在一个循环里持续推进，每拿到新结果就重新判断下一步。
3. **环境反馈**：尝出来的咸淡、采买回来的缺货、火候的变化都是反馈。Agent 根据反馈调整，而不是一条道走到黑。

一个最小的例子：问“北京现在几点、天气怎么样”，纯语言模型只能凭训练时定格的旧知识猜，甚至直说不知道——因为它的知识在某个时间点就停了，够不到“现在”；而配上工具的 Agent 会真去查一次再回答。差别不在谁更聪明，而在能不能伸手够到当下的世界。

这三件事合起来，才把“会报菜”变成“会办席”。少了任何一件，它要么只会空谈，要么做一道就卡死。

## ReAct：想、做、尝的循环

支撑 Agent 的经典思路叫 **ReAct**：把“推理”（Reason）和“行动”（Act）交织起来——先想下一步该做什么，再做（采买、下锅），再尝结果（Observe），然后回到想，如此循环，直到满足停止条件。

办这桌席就是一圈圈 ReAct：想“先看库房有什么”→做“翻库房”→尝“缺一味高汤”→想“去集市买”→做“采买”→尝“还差点火候”→想“回锅调”……每一圈都用上一圈的结果决定下一步。Deep Research、代码修复、故障排查，骨架都是这个循环。

## 为什么是现在

Agent 概念不新，重新变热靠的是几条线同时到位：

- 模型的**推理和指令遵循**变强，能在循环里做出像样的下一步决策。
- **工具调用**有了结构化接口（function calling、MCP 等），让模型可靠地“开采买单”。
- **运行环境**（Harness）成熟：有库房、集市、灶台、权限、上下文管理和停止条件，让循环跑得稳、收得住。

所以 Agent 的复兴，与其说是厨子变聪明，不如说是“厨子 + 后厨”这套组合终于能办席了。厨子是能力来源，后厨决定他能不能被放心地放出去办一整桌——这正是第 06 讲整讲要展开的主题。

## Agent 不是更会报菜的厨子

这是最该记住的一点。Agent 不等于换了张更会报菜的嘴，而是给同一张嘴配上腿、采买、尝味和“没办成就再来一次”的循环。

因此 Agent 出问题，往往不在厨子本身，而在后厨：采买单写得含糊、没有停止条件导致空转、权限太大乱动库房、上下文搬运不当让它忘了这桌席是给谁办的。看懂这一点，你排查 Agent 故障时就会先看后厨，而不是一味怪厨子笨。

## 小练习

拿一个你想交给 AI 的需求，判断要不要上 Agent：

1. 它是一步能答完的问题，还是需要查资料、调工具、分多步推进？
2. 完成它需要哪些工具？这些工具有没有清楚的“何时用、何时别用”说明？
3. 它该在什么条件下停下来？谁来确认它真的办成了？

如果三问里出现“多步”“要调工具”“要有停止和确认”，这就是一个 Agent 任务，而不只是一次问答。
