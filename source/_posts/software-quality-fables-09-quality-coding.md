> 承上：上一讲老周说「家具的毛病多半是图纸没画好」，把设计质量讲透了。可图纸再好，最后还得落到手上的活——这一讲，我们走进车间，看小磊怎么把一刀一凿都做规矩。

图纸过了关，老周把小磊领到工作台前，说：「图是脑子里的活，凿子是手上的活。手上没规矩，再好的图也做废。」

第一天，小磊干得风风火火。一把凿子用完往台上一撂，刨子刨完顺手搁在料堆上，名牌嫌麻烦也不挂。老周转一圈，脸就沉了：「你这台子，三天后你自己都不认得哪把是开榫的、哪把是修边的。」他顺手拎起一把没挂回架子的凿子，「这玩意叫『野凿子』——你以为它在台上，伸手一摸是空的，或者一脚踢翻扎了人。工具用完立刻挂回原位，这是死规矩。」

更要命的是料场。小磊图省事，从料场一次抱来一大摞木料，用了三块，剩下的塞角落里也不记账、也不还。阿萍来盘库，账对不上：「领了十块，木工房只回来三块,另外七块呢?」找了半天,有的被压在床底，有的当垫脚垫没了。老周敲敲桌子：「料场就那么大,你领了不还,今天少七块,明天少七块,迟早料场空了,谁来都领不到料。领多少、用多少、还多少,得清清楚楚配上对。」

小磊还有个毛病，名牌爱自己瞎写：这把叫「大凿」，那把叫「我的凿」，别人来接手两眼一抹黑。老周给了他一张《作坊名牌规范》：什么活用什么前缀、谁家的料挂什么牌、临时借的工具怎么标——全镇一套写法。「名牌不是给你自己看的，是给三年后接手的人看的。」

那天收工，小磊把每把工具擦净挂回原位、料场账还清、名牌按规范重写了一遍。老周点点头：「图纸是脑子，手艺是手。脑子想得再漂亮，手不守规矩，照样出废品。这就是收尾这一课。」

## 概念揭晓

故事里那些「手上规矩」，对应的就是**高质量编程**的全部内容：

- **统一名牌规范** = **编码风格与命名规则**：变量、函数、常量都按一套约定起名，别人一看就懂。
- **野凿子** = **野指针**：指向「垃圾」内存的指针，用 `free`/`delete` 释放后没置 `NULL`，伸手一摸是雷。

- **工具挂回原位、名牌写清楚** = **代码风格、文件结构、程序版式**的种种约定。

## 代码风格：两个小例子

风格不是花架子，是防呆。看两个对照：

| 写法 | 评价 | 为什么 |
|---|---|---|
| `if (1 == j)` | **优秀** | 万一手滑写成 `=`，编译器会报错（常量不能被赋值） |
| `if (j == 1)` | 一般 | 写成 `if (j = 1)` 编译器不报错，悄悄出 bug |
| `if (i > MAX_NUM)` | **优秀** | 用具名常量，一看就懂，改起来一处改全改 |
| `if (i > 5000)` | 差 | `5000` 是「魔数」，别人不知道它是啥、改起来到处找 |

## Windows 程序命名规则

**匈牙利命名法**：在变量名前加表示类型的前缀（如 `n` 整型、`p` 指针、`sz` 字符串），一看名字就知道类型。

**常用命名规则**（要点）：

- 变量名用「名词」或「形容词 + 名词」；全局函数名用「动词」或「动词 + 名词」；类的成员函数只用「动词」（省略的名词就是对象本身）。
- 类名、函数名用**大写字母开头**的单词组合；变量、参数用**小写字母开头**；常量**全大写、下划线分隔单词**。
- 静态变量加前缀 `s_`；全局变量加前缀 `g_`；类的数据成员加前缀 `m_`（避免与成员函数参数同名）。
- 循环计数变量用 `i`、`j`、`k`、`l`、`m`。
- 用正确的反义词组命名互斥的变量或相反动作的函数；不要仅靠大小写区分相似标识符。

## 函数处理规则

- 参数书写**完整**，不要只写类型不写参数名；没有参数时用 **`void`** 填充。
- 参数若是**指针且仅做输入**，类型前加 **`const`**，防止函数体内意外改动。
- 输入参数若以**值传递**方式传对象，宜改用 **`const &`**，省去临时对象的构造与析构，提高效率。
- 参数个数尽量控制在 **5 个以内**；参数命名恰当、顺序合理。
- **不要省略返回值的类型**；函数名与返回值类型语义上不可冲突。
- **不要把正常值和错误标志混在一起返回**：正常值用**输出参数**获得，错误标志用 **`return`** 返回。
- 为支持链式表达，原本无返回值的函数可附加返回值；在函数「出口处」检查 `return` 的正确性与效率。

## 文件结构

**定义文件**有三部分：① 开头的**版权和版本声明**；② 对一些**头文件的引用**；③ 程序的**实现体**（数据和代码）。

**头文件**：

- 为防止被重复引用，用 **`ifndef` / `define` / `endif`** 结构产生预处理块。
- 引用**标准库**头文件用 `#include <filename.h>`（从标准库目录搜索）；引用**非标准库**头文件用 `#include "filename.h"`（从用户工作目录搜索）。
- 头文件中**只存放「声明」不存放「定义」**；不提倡在头文件中出现 `extern int value` 这类全局变量声明。

## 程序的版式

- **空行规则**：每个类声明、每个函数定义结束后加空行；函数体内逻辑密切相关的语句之间不加空行，其它地方加空行分隔。
- **一行代码只做一件事**（只定义一个变量，或只写一条语句），便于阅读和写注释。
- `if`、`for`、`while`、`do` 等语句**自占一行**，执行语句不得紧跟其后；**不论执行语句有多少都要加 `{}`**，防止书写失误。
- **就近初始化**：尽可能在定义变量的同时初始化它，减少引用未初始化变量的隐患。
- **对齐**：`{` 和 `}` 独占一行、位于同一列，与引用它们的语句左对齐。
- **长行拆分**：代码行宜控制在 **70 至 80 个字符**以内；长表达式在低优先级操作符处拆分，**操作符放在新行之首**；修饰符 `*` 和 `&` 紧靠变量名（`int *x, y;` 这样 `y` 不会被误解为指针）。
- **注释**：是对代码的「提示」而非文档，不可喧宾夺主；代码本身清楚就不必注释（`i++; // i 加 1` 是多余注释）；边写边注、改代码同时改注释；注释放在代码上方或右方，**不可放在下方**。
- **类的版式**有两种：「以数据为中心」（private 数据在前）和「以行为为中心」（public 函数在前）。**建议采用「以行为为中心」**，因为用户最关心的是接口。

## 表达式：共性规则

- 运算符较多时，**用括号确定操作顺序**，别依赖默认优先级。
- 不要写太复杂的复合表达式（如 `i = a >= b && c < d && c + f <= g + h;`），也别写多用途复合表达式（如 `d = (a = b + c) + r;`）。
- 别把程序表达式与「真正的数学表达式」混淆：`if (a < b < c)` 是数学写法，在程序里它**不**表示 `if ((a<b) && (b<c))`，而是成了令人费解的 `if ((a<b) < c)`。

## 基本语句：if 的四种变量比较

考试高频，按变量类型记牢：

| 变量类型 | 标准写法 | 禁忌 |
|---|---|---|
| **布尔变量** flag | `if (flag)` / `if (!flag)` | 不可写 `== TRUE` / `== FALSE` / `== 1` / `== 0` |
| **整型变量** value | `if (value == 0)` / `if (value != 0)` | 不可写 `if (value)`（让人误以为是布尔） |
| **浮点变量** x | `if ((x >= -EPSINON) && (x <= EPSINON))` | 不可用 `==` / `!=` 比较（有精度限制） |
| **指针变量** p | `if (p == NULL)` / `if (p != NULL)` | —— |

补充：`if (NULL == p)` 这种「古怪写法」是有意把 `p` 和 `NULL` 颠倒，防止把 `if (p == NULL)` 误写成 `if (p = NULL)`——编译器认为 `if (p = NULL)` 合法，却会指出 `if (NULL = p)` 错误。

**for 循环**：不可在循环体内修改循环变量（防止失控）；建议循环控制变量采用「半开半闭区间」写法 `for (int x = 0; x < N; x++)`。

## 内存管理（重点）

### 三种内存分配方式

- **静态存储区**：编译时就分配好，整个运行期都存在（全局变量、`static` 变量）。
- **栈**：函数内局部变量在栈上创建，函数结束自动释放；效率很高但容量有限。
- **堆（动态内存）**：运行时用 `malloc`/`new` 申请，自己负责用 `free`/`delete` 释放；最灵活，但问题也最多。

### 常见内存错误及对策

- **分配未成功就用**：用前检查指针是否为 `NULL`；参数指针用 `assert(p != NULL)`，`malloc`/`new` 申请的用 `if (p == NULL)` 防错。
- **未初始化就引用**：内存缺省初值没有统一标准，「宁可信其无」，无论怎么建数组都要赋初值。
- **越界**：数组下标「多 1」或「少 1」，尤其 `for` 循环次数易搞错。
- **忘记释放，造成内存泄漏**：含这种错误的函数每调用一次就丢一块内存，最终系统内存耗尽。**动态内存的申请与释放必须配对，`malloc` 与 `free` 的次数一定要相同。**
- **释放后继续使用，产生「野指针」**：`return` 别返回指向「栈内存」的指针/引用；`free`/`delete` 后没把指针置 `NULL`。

### 野指针

「野指针」**不是 `NULL` 指针**，而是指向「垃圾」内存的指针。`if` 语句对它**不起作用**（即便 `p != NULL`，它也不指向合法内存）。

- **成因**：① 指针变量没被初始化（缺省值随机，会乱指一气）；② 指针 `free`/`delete` 后没置 `NULL`。
- **对策**：申请内存后立即查 `NULL`；数组和动态内存赋初值；**申请与释放配对**；**用 `free`/`delete` 释放后立即把指针置 `NULL`**。
- 关键认知：`free`/`delete` 只释放指针所指的内存，**并没有干掉指针本身**；指针消亡不代表内存自动释放，内存释放也不代表指针成了 `NULL`。

## const 的魅力

`const` 能修饰函数的**参数、返回值，甚至函数定义体**，被修饰的东西受强制保护，能提高健壮性。

- **`const` 只能修饰输入参数**：作输出用的参数加了 `const` 会失去输出功能。
- 输入参数用「指针传递」时加 `const`，防止意外改动指针。
- 非内部数据类型的参数，`void Func(A a)` 这样值传递效率低（要构造/复制/析构临时对象）；改 `void Func(A &a)` 用引用传递不产生临时对象，但可能改动 `a`；最终加 `const` 成 **`void Func(const A &a)`**，又快又安全。

## Java / C++ 编程规则（课后阅读，点到）

**Java 编程规则**要点：类名首字母大写、字段/方法/对象首字母小写；包名全小写；每个类考虑置入 `main()` 放测试代码；让一切尽可能 `private`；警惕「巨大对象综合症」「分析瘫痪」「过早优化」；避免「魔术数字」，用具描述性名称的常数代替。**C++ 编程规则**列为课后阅读。

### 表达式 · 共性规则

- 运算符较多时用括号确定操作顺序，避免使用默认优先级。
- 不要编写太复杂的复合表达式（`i = a >= b && c < d && c + f <= g + h;`）；不要有多用途复合表达式（`d = (a = b + c) + r;`）。
- 不要把复合表达式与「真正的数学表达式」混淆：`if (a < b < c)` 是数学表达式，并不表示 `if ((a<b) && (b<c))`，而是成了令人费解的 `if ((a<b) < c)`。

### 基本语句 · if 语句

- **布尔变量** flag：标准写法 `if (flag)`（为真）、`if (!flag)`（为假）；**不可写** `if (flag == TRUE)`、`if (flag == 1)`、`if (flag == FALSE)`、`if (flag == 0)`。
- **整型变量** value：用 `==`/`!=` 直接与 0 比较，`if (value == 0)`、`if (value != 0)`；不可模仿布尔风格写 `if (value)`、`if (!value)`。
- **浮点变量** x：不可用 `==`/`!=` 与任何数字比较（有精度限制），应转化为 `if ((x >= -EPSINON) && (x <= EPSINON))`，`EPSINON` 是允许的误差（精度）。
- **指针变量** p：用 `==`/`!=` 与 `NULL` 比较，`if (p == NULL)`、`if (p != NULL)`；`if (NULL == p)` 是为防止把 `if (p == NULL)` 误写成 `if (p = NULL)` 而有意颠倒。
- **for 循环控制变量**：不可在 `for` 循环体内修改循环变量（防止失控）；建议循环控制变量取值采用「半开半闭区间」写法 `for (int x = 0; x < N; x++)`。

### 内存管理

> **内存分配方式有三种**：① 从静态存储区分配（编译时分配，整个运行期都存在，如全局变量、`static` 变量）；② 在栈上创建（函数内局部变量，函数结束自动释放，效率高但容量有限）；③ 从堆上分配（动态内存，运行时用 `malloc` 或 `new` 申请，自己负责用 `free` 或 `delete` 释放，最灵活但问题最多）。

**常见内存错误及对策**：

- 内存分配未成功却使用它——使用前检查指针是否为 `NULL`，参数指针用 `assert(p != NULL)`，`malloc`/`new` 申请的用 `if (p == NULL)` 防错。
- 分配成功但未初始化就引用——内存缺省初值无统一标准，无论何种方式创建数组都要赋初值。
- 操作越过内存边界——数组下标「多 1」或「少 1」，`for` 循环次数易错。
- **忘记释放内存，造成内存泄露**——每调用一次丢一块内存，终致内存耗尽；**动态内存的申请与释放必须配对，`malloc` 与 `free` 的使用次数一定要相同。**
- 释放了内存却继续使用——`return` 不要返回指向「栈内存」的指针/引用；`free`/`delete` 后没把指针置 `NULL`，导致产生「野指针」。

**野指针**：

> 「野指针」不是 `NULL` 指针，是指向「垃圾」内存的指针，`if` 语句对它不起作用。
>
> 成因主要两种：① 指针变量没被初始化（缺省值随机，会乱指一气）；② 指针被 `free` 或 `delete` 后没置为 `NULL`。

**总对策**：申请内存后立即检查指针是否为 `NULL`；为数组和动态内存赋初值；**申请与释放必须配对**；**用 `free`/`delete` 释放后立即把指针置 `NULL`**。`free`/`delete` 只释放内存，并没干掉指针本身；指针消亡不代表内存自动释放，内存释放也不代表指针成了 `NULL`。

### const 的魅力

> `const` 可修饰函数的参数、返回值，甚至函数的定义体，被修饰的东西受强制保护，能提高健壮性。

- 参数作输出用时不能加 `const`（否则失去输出功能）；**`const` 只能修饰输入参数**。
- 输入参数用「指针传递」时加 `const` 防止意外改动指针。
- `void Func(A a)` 值传递效率低（构造、复制、析构临时对象）；改 `void Func(A &a)` 引用传递不产生临时对象，但可能改动 `a`；最终加 `const` 成 **`void Func(const A &a)`**。

### Java / C++ 编程规则（课后阅读）

- **Java**：类名首字母大写，字段/方法/对象首字母小写；包名全小写；每个类考虑置入 `main()` 放测试代码；方法设计成简要功能性单元；让一切尽可能 `private`；警惕「巨大对象综合症」「分析瘫痪」「过早优化」；避免「魔术数字」，用具描述性名称的常数代替；对象的行为也应得到良好定义。
