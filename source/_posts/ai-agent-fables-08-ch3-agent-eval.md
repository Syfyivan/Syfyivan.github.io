> 承上：上一章阿评学会了考“会答话的”。这一章，考场上来了个完全不同的角色——一个会自己跑去办事的。

新选手接了道实务题：把一桩积压的事项办结。他出了考场，跑了几个地方，过了一阵回来交差。阿评一看结果对，就要打满分。

老裁判又拦住：“他答得对不对只是一面。会办事的，得看他**怎么办的**。”老裁判把这场拆开看：他**一步步去了哪些地方、做了哪些动作**？中间**该用的工具有没有用对、有没有瞎用**？最后这件事**到底办成了没、办成了几成**？还有——他来回**跑了多久、花了多少盘缠**？“同样办成一件事，有人三步搞定，有人绕二十圈、花十倍盘缠，这俩能一个分吗？”

> 所属路径：AI 与 Agent 大寓言课 / 第 08 讲：会验收的裁判 / 08.3 Agent 任务级 eval

## 概念揭晓

老裁判这套考法，是 **Agent 任务级评测**——和上一章“评一句回答”很不一样，它评的是“完成一个多步任务的整个过程和结果”。

“一步步去了哪些地方、做了哪些动作”，是**轨迹（trajectory）**：Agent 为完成任务走过的完整步骤序列。过程对不对，往往和结果一样重要。

“工具有没有用对、有没有瞎用”，是**工具调用评测**：该调的有没有调、参数对不对、有没有乱调或漏调（呼应第五讲）。

“办成了没、办成几成”，是**任务完成率（task success rate）**：以“任务是否真正达成”为准的端到端指标，这是 Agent 评测的核心。

“跑了多久、花了多少盘缠”，是**成本与延迟**：完成同一任务消耗的 token、时间、调用次数——再准的 Agent，又慢又贵也用不起（呼应第二讲 02.3）。

## 不能只看最后交没交差

评一句回答，看输出就够了。评一个 Agent，只看最终结果远远不够，因为：

- 它可能**蒙对**：过程一团糟，结果碰巧对，换个题就崩。
- 它可能**对而极贵**：办成了，但绕了几十圈、烧了大把 token。
- 它可能**对但越界**：顺手做了不该做的事（删了不该删的、调了不该调的工具）。

所以 Agent 评测要同时看**结果**和**过程（轨迹）**，才能判断它是“真会办”还是“侥幸办成”。

## 结果对 ≠ 过程对

把轨迹摊开看，能发现只看结果看不到的问题：

- 走了大量无用的弯路（效率差）。
- 调错工具又自己绕回来（说明工具契约或判断有问题，第五讲）。比如订房 Agent 本该一步调 `search_rooms(time, capacity)` 就拿到候选，却反复调 `list_all_rooms` 把全部会议室拉回来、自己在上下文里筛——结果也许对，但多烧了 token、慢了好几秒，还更容易在长列表里挑错。只看结果看不到这种“能用但很糟”的过程，**轨迹评测就是给过程也立一把尺**。
- 在关键步骤上反复试错、几乎要失败（脆弱，换个输入就翻）。

对要长期可靠的 Agent，过程质量是稳定性的先行指标。一个“结果对但过程乱”的 Agent，是在拿运气换通过。

## 任务完成率怎么定

这是 Agent 评测最核心、也最难的一环：先把“算办成了”定义清楚。

- 准备一批**有明确成功判据**的任务（最终状态可检验：文件改对了、订单建成了、问题答全了）。
- 对每个任务，用程序或人判定“成功 / 部分成功 / 失败”。
- 在足够多、覆盖真实分布的任务上，算端到端完成率。

举个具体例子：评一个“订会议室”的 Agent，跑 100 个任务。成功判据定死为“在用户要的时段、订到容量够的那间，且没占用别人的会议室”。跑完一数：78 个完全达成、12 个订上了但时段差半小时（部分成功）、10 个彻底失败。完成率怎么报取决于你怎么对待“部分成功”——严口径只认全对就是 78%，宽口径给部分成功记半分就是 (78 + 12×0.5) / 100 = 84%。两个数都对，关键是**口径要写死、对所有版本一致**，否则下次迭代的涨跌分不清是真进步还是换了算法。

难点正在于这个“成功判据”——它就是第七讲的“可验证完成”落到 Agent 上。判据含糊，完成率就不可信。

## 成本和延迟必须一起算

Agent 多步、调工具、反复推理，天然又慢又贵。所以评测必须把开销和质量放一起看：

- **token / 调用次数**：直接对应钱。
- **延迟**：用户等不等得起、能不能并发。
- **效率**：完成同一任务用了多少步——步数越少通常越稳越省。

一个有用的视角：在“完成率”和“成本/延迟”之间画一条权衡线，而不是只盯一个数。又快又省又准很难三全，工程上常要取舍——这条线会一直延伸到第十一讲（多 Agent 的成本）和第十二讲（产品化）。

## 常见误区

第一，只看最终结果对不对，不看轨迹——分不清“真会”和“蒙对”。

第二，不把“算成功”定义清楚就报完成率，数字没意义。

第三，只比准确率，不算成本和延迟——选了个又准又用不起的方案。

## 小练习

你要评测一个“帮用户订会议室”的 Agent，定四类指标：

1. 任务完成率：怎么判定“真的订上了对的会议室”？
2. 轨迹/工具：你会检查它过程中的哪些动作？
3. 成本/延迟：你会盯哪几个数？多绕几步算不算扣分？
